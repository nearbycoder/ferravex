## Concrete behavior and compatibility

- Detailed target outcomes distinguish inactive, duplicate, admitted continuing
  hit, admitted final hit with exhausted pierces, and the legacy defensive
  storage stop. Reports include the resulting remaining budgets and retained-ID
  count. `accepted()` includes the final hit but excludes the defensive storage
  stop; it is nominal projectile admission only.
- Detailed walls distinguish inactive, separating, exactly tangent/stationary,
  exhausted bounce, and admitted perfect reflection. No epsilon is introduced.
  Reports return exactly the velocity/None that legacy `wall` returns.
- Original `HitResult::{Ignored, Continue, Stop}` remains exhaustive and
  unchanged. Original `target` and `wall` signatures remain unchanged and map
  through the detailed implementation. Original inline regression test retained.
- Original target ordering remains inactive, duplicate, free slot, final-hit
  stop/one-pierce decrement. Zero pierces still admits one final target; zero
  bounces remains alive until an approaching wall. Duplicates do not spend
  budgets; inactive takes precedence over a repeat of the final target.
- Original wall order remains finite/bounded velocity and finite normal check,
  `normal.try_normalize()`, inactive check, dot product, `dot >= 0`, exhausted
  bounce, then decrement and `velocity - normal * (2. * dot)`. No restitution,
  output clamp, renormalization change or added numerical rejection. The input
  velocity component bound remains inclusive +/-1e6; legacy reflected output can
  exceed that bound and is preserved. Reusing that output as a new input may
  therefore be rejected, also unchanged.
- Invalid and zero normals reject without mutation even when inactive. Existing
  normalization handles huge finite and subnormal normals without a new local
  implementation. Sampled finite/extreme/sign/zero cases compare velocity bits
  against a frozen copy of the pre249 arithmetic, not approximate equality.
- Original private fields, fixed `[Option<u64>; N]`, Copy/Clone and constructor
  bounds (`1 <= N <= 256`, `pierces < N`) remain unchanged. No operation adds
  allocation. Reports/state inspect bounded storage; state counting is O(N).
- `StorageExhausted` describes the preserved defensive guard; it is unreachable
  from valid public construction: at most initial_pierces+1 <= N unique IDs can
  be admitted, and the last makes the budget inactive. Tests fill the maximum
  256 slots with 255 pierces and exercise every u8 pierce count at N=256. They do
  not fabricate private invalid storage to claim a publicly reachable failure.
- IDs remain opaque host u64 generation identities. Existing Entity::to_bits()
  preserves generation+slot; Entity::id() alone does not. World/session identity,
  stale-target validation, generation wrap and collision validity remain host
  responsibilities. Distinct generations can both be hit; one equal ID is
  admitted at most once over one budget lifetime. No new ID/ledger/protocol.
- No in-place reset added. Construct and explicitly replace with a fresh budget
  for a new projectile/run. Copy forks history and is not coordinated authority.
  Tests cover new-lifetime replacement, rejected construction preserving the
  current lifetime, and independent Copy behavior.
