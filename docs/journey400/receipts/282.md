## Concrete behavior

`NoticeQueue<const N: usize, T, K = u64>` owns `[Option<Entry<T, K>>; N]` inline. Construction, submission, ordering and removal contain no allocator calls. Messages/keys may borrow caller data or be bounded enums/fixed-size values, with no Clone/Copy/Default requirement. Caller payload/key allocations, equality, merge work, interior mutation and destructor behavior are outside the queue's storage/work bound; no process-wide allocator instrumentation was performed.

Presentation order is descending priority, FIFO among equal priorities. Saturation evicts the oldest entry at the lowest priority only when the incoming priority is strictly higher. Equal/lower-priority bursts reject intact inputs, so already-retained critical notices survive unrelated critical bursts. Zero capacity accepts no notice. `None` keys never match; `Some(key)` uniquely groups retained notices. Keys are not event IDs and do not deduplicate an event stream.

Duplicate handling is explicit: Keep rejects without refreshing time; Replace returns the entire old notice, permits intentional priority demotion and treats the replacement as a new arrival. Coalescing uses a shared-reference callback returning a new typed message, returns the prior message and incoming notice, retains the original authored key/duration, promotes priority to the maximum, and keeps its ordering position unless promoted. A promotion joins behind existing entries of its new priority. Missing-key coalescing follows normal insertion without calling the callback. Numeric overflow is caller policy; the runnable score recipe uses `u32::saturating_add` explicitly.

Lifetimes must be finite and strictly positive. Invalid lifetime takes precedence over duplicate/capacity rejection and never calls merge. Coalescing explicitly keeps remaining time, refreshes from incoming duration (may shorten), or extends by incoming duration with finite saturation at `f64::MAX`. `advance` takes caller-chosen seconds, rejects negative/nonfinite deltas atomically, accepts zero, ages hidden and visible entries alike, clamps subtraction at zero, removes entries at the exact expiry boundary and returns the expired count. There is no hidden clock, accumulated total time, renderer, input, game-state inference or implicit motion/flash policy. Ordinary f64 precision applies; sufficiently small deltas may not reduce huge remaining durations. This is deterministic for the tested supplied values on the tested host, not a cross-platform floating-point guarantee.

`dismiss` and `pop_front` return owned notices. Successful submissions return all displaced/redundant owned payloads instead of internally dropping them. `advance`, `clear`, queue destruction and host disposal of returned values can run caller destructors. Equality and merge panic before structural mutation; callback interior side effects are not rolled back. Expiry/reset destructors can panic after partial progress, leaving later work incomplete; removal compacts storage before disposal and preserves its occupied-prefix/length invariants. Submission/removal is O(N), clear O(N), and expiry of multiple notices can be O(N²), with O(1) extra queue storage. No unbounded counters or serial wrap behavior is introduced.
