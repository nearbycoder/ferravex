## Behavior and compatibility

- `PreparedAffine3D` retains the exact supplied `Mat4`, a cached linear inverse
  transpose and a reflection flag. Private fields and copy-returning accessors
  prevent mutation from invalidating the cache.
- Preparation validates finite coefficients first, then exact bottom row
  `(0, 0, 0, 1)` (including signed zero), then calls the existing
  `Mat4::checked_inverse()` on the translation-free linear matrix. No inverse
  implementation or alternate TRS authoring system was introduced.
- The normal matrix is `[L^-T, 0; 0, 1]`, not a full inverse model containing
  inverse translation in its bottom row. Its `transform_vector3` result agrees
  with the full inverse transpose's XYZ result, subject to rounding. It has
  zero translation and a canonical affine row.
- Forward point/normal preparation does not require representability of an
  irrelevant inverse translation. A model with finite translation `f32::MAX`
  and linear X scale `1e-20` is accepted even though its full checked inverse
  reports `ResultOutOfRange`. The linear inverse must still fit f32.
- No affine-row epsilon, repair or projective division. Tiny nonzero row
  components and W other than exactly 1 fail. Singular linear transforms and
  inverse-range failures preserve `MatrixError` diagnostics and error chaining.
  No arbitrary determinant/scale cutoff is imposed.
- Reflection policy: inverse-transpose **covector orientation**, with no
  determinant-sign multiplication. Under a negative determinant, the transformed
  authored normal points opposite the transformed source triangle's edge cross
  product. `is_reflected()` lets the consumer choose winding/culling or an
  explicit sign flip. Even numbers of reflected axes preserve orientation.
- Reflection is computed once using existing `Mat4::determinant()` and
  `is_sign_negative()`. The determinant's f64 elimination followed by f32 cast
  can yield signed zero or infinity; their signs are retained, so tiny/huge
  mirrored scale determinants are not confused with positive orientation.
- `transform_point` includes translation; `transform_vector` excludes it and
  does not normalize. Finite input is required. Both use f64 dot products and
  return `ResultOutOfRange` if a result casts to nonfinite f32. Valid cancellation
  can therefore succeed where the legacy unchecked f32 calculation overflows.
  Finite coordinate underflow to zero is allowed. Zero vectors are valid.
- `transform_normal` accepts finite nonunit normals, applies the cached inverse
  transpose with f64 dots, rescales by the largest absolute component and reuses
  `Vec3::try_normalize()`. This produces unit results for huge/subnormal inputs
  even when an unnormalized f32 matrix-vector product would overflow or vanish.
  Zero input/transformed direction returns `DegenerateNormal`; nonfinite input
  returns `NonFiniteInput`. No zero/identity fallback is inserted.
- Batch operations require `output.len() >= input.len()` before element work.
  Capacity failure wins over invalid-input errors. Otherwise the first invalid
  element's zero-based index and scalar error are returned. All inputs/results
  are checked in a read-only first pass; a second pure pass writes the exact
  input-length prefix. Errors preserve every output bit, including NaN payloads,
  signed zeros and unused tails. Success retains the unused tail. Empty input
  succeeds, including with empty output; operations never truncate.
- Batch work is O(n) and limited by caller input length, with O(1) stack storage
  and no heap scratch. There is no hidden global batch/work ceiling. Separate
  point/vector/normal batch calls are separate transactions; the API does not
  promise combined atomicity across them. Input/output disjointness is enforced
  by safe Rust references; no in-place API was added.
- `try_update` validates a replacement before assignment; any failure retains
  model, normal matrix and reflection flag together. Updating to identity resets
  all state; there is no history, tick, clock, I/O or renderer ownership.
- Allocation regression: a thread-local allocator counter observes zero heap
  calls over preparation, repeated scalar/batch queries, errors and update/reset
  recovery. A separate positive-control allocation confirms the counter works.
  Unsafe forwarding exists only in the integration-test allocator; production
  math still compiles under the crate's `#![forbid(unsafe_code)]`.

## Exact public API

All types are in `ferravex_math::affine`. `PreparedAffine3D` derives
`Clone, Copy, Debug, PartialEq`. Both error enums are `#[non_exhaustive]`, derive
`Clone, Copy, Debug, PartialEq, Eq`, and implement `Display` and
`std::error::Error`. `AffineError::Matrix` exposes the `MatrixError` as its
source; `AffineSliceError::Element` exposes its `AffineError` as source.
There is `impl From<MatrixError> for AffineError`.

API-signature excerpt, not a runnable snippet:

```rust
pub enum AffineError {
    NonFiniteInput { input: &'static str },
    NonAffine,
    Matrix(MatrixError),
    ResultOutOfRange,
    DegenerateNormal,
}
pub enum AffineSliceError {
    InsufficientCapacity { required: usize, available: usize },
    Element { index: usize, source: AffineError },
}
pub struct PreparedAffine3D { /* private validated state */ }
impl PreparedAffine3D {
    pub fn try_new(model: Mat4) -> Result<Self, AffineError>;
    pub fn try_update(&mut self, model: Mat4) -> Result<(), AffineError>;
    pub const fn model(&self) -> Mat4;
    pub const fn normal_matrix(&self) -> Mat4;
    pub const fn is_reflected(&self) -> bool;
    pub fn transform_point(&self, point: Vec3) -> Result<Vec3, AffineError>;
    pub fn transform_vector(&self, vector: Vec3) -> Result<Vec3, AffineError>;
    pub fn transform_normal(&self, normal: Vec3) -> Result<Vec3, AffineError>;
    pub fn transform_points_into(
        &self, input: &[Vec3], output: &mut [Vec3],
    ) -> Result<(), AffineSliceError>;
    pub fn transform_vectors_into(
        &self, input: &[Vec3], output: &mut [Vec3],
    ) -> Result<(), AffineSliceError>;
    pub fn transform_normals_into(
        &self, input: &[Vec3], output: &mut [Vec3],
    ) -> Result<(), AffineSliceError>;
}
```

## Unverified limits retained for parent

- Host tests/doctest/Clippy only. No dependent-renderer adoption, shared native
  or Wasm integration, browser/device/playtest, performance benchmark, audible
  or visual runtime result, or cross-platform determinism claim.
- Linear inverse and normal matrix coefficients are f32; permitted underflow,
  cancellation and ill-conditioning can lose direction or perpendicularity.
  Checked inverse success and computed determinant sign are not exact-rank,
  condition-number or real-arithmetic certificates. No arbitrary epsilon or
  exact-predicate subsystem was added.
- Rescaling avoids range loss in a final normalized normal; it cannot restore
  information already lost when the matrix/inverse was rounded. Unit output and
  perpendicularity remain subject to f32 rounding.
- Two-pass atomic slices trade repeated arithmetic for O(1) scratch. Callers
  bound work with input length. There is no joint transaction for positions and
  normals, no hidden work budget and no in-place mutation method.
