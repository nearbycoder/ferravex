## Behavior, bounds and compatibility

Default is off: creating a bridge publishes nothing, exports without an adopted
publisher report pointer/length zero, and JS never invents a snapshot from
absent exports or an absent game publisher. `publish(None)` is an explicit,
game-authored unavailable snapshot; `Some(empty)` means available but empty.
Inputs are complete current facts, not patches. The game owns all lifecycle,
objective, result and action-label meaning. There is no timer, scene traversal,
input listener, synthetic input, execution callback, request/action export or
new game authority.

The caller supplies borrowed facts plus optional immutable `UiInspection` and
an explicit widget-ID-to-status-ID whitelist. Only current registered Button
entries that are submitted enabled and have positive clipped visible bounds
contribute labels. Paint-only entries, unsupported roles, absent widgets,
disabled buttons and discarded modal scopes contribute no available action.
An inspected widget is never automatically treated as an authorized command.
Host input blocking/semantic availability remains the game’s responsibility;
omit mappings when local gameplay/menus do not authorize them. Clipped bounds
are not a promise of unoccluded ink visibility. Full-label inspection misses
are counted omissions; painter abbreviations are never presented as full copy.

Limits are constants: 128 combined source facts/mappings; 32,768 full selected
source-label bytes, including output-omitted labels and unavailable full-label
required sizes; 32 retained items; 256 UTF-8 bytes per retained label; 57,344
wire bytes. Oversized source rejects atomically. The output retains declaration
order followed by mapping order; later available items increment `omitted`.
Labels retain the longest whole UTF-8 prefix fitting 256 bytes, setting per-item
`truncated` and aggregate `shortened`. Omitted/unavailable full copy and shortened
retained copy remain distinct. Disabled/absent actions are not truncations.
Place essential lifecycle/results early in the game-owned source ordering.

All source IDs, including the omitted suffix and unavailable/absent mappings,
are validated for uniqueness before publication. Widget mappings are also unique.
There is at most one Lifecycle and one Result source item. No-op comparison is
of retained semantics, including item order and truncation counts; source changes
entirely outside the retained prefix do not increment serial. Rejected duplicate,
source-capacity, inspection and counter errors preserve the last-good bridge.
Serialization uses private bounded scratch before replacement, escapes controls,
quotes/backslashes and preserves Unicode. `bytes()` exposes only the initialized
prefix; internal tails are zeroed on replacement/reset. Caller `write()` rejects
insufficient capacity before any write and preserves unused caller-buffer tails.

Retained bridge storage is one fixed wire array and one fixed 32-item snapshot;
private update scratch is fixed too. Browser opt-in adds one thread-local boxed
fixed wire buffer, freed by successful clear. Duplicate checking is O(128²), UI
selection at most 128 scans of UiInspection's 1,025-entry ceiling, serialization
bounded by 32 × 256 input bytes with at most sixfold JSON escaping. There are no
caller iterators/callbacks with unbounded update work. Normal native publication,
caller-buffer writing and warmed browser copying measured zero allocations over
200 changed publications and 200 no-op publications. Construction, first browser
opt-in allocation, UI composition, caller strings and JS engine allocations are
outside that warmed allocation claim.

Existing structs/enums/defaults/imports/exports and save/replay/network formats
are untouched. This is a new, separately versioned diagnostic/semantic contract,
not a scene, replay, save, input or game-command protocol. No dependencies added.
The pure fact path is suitable for custom software hosts without renderer changes.

## Exact public Rust API

Qualified under `ferravex_render::status`; excerpts, not standalone code:

```text
pub const MAX_SOURCE_ITEMS: usize = 128;
pub const MAX_SOURCE_BYTES: usize = 32768;
pub const MAX_ITEMS: usize = 32;
pub const MAX_LABEL_BYTES: usize = 256;
pub const MAX_WIRE_BYTES: usize = 57344;

pub enum StatusKind { Lifecycle, Objective, Result, Action, Notice, Telemetry }
pub struct StatusItem<'a> { pub id: u64, pub kind: StatusKind, pub label: &'a str }
pub struct UiAction { pub widget_id: u64, pub status_id: u64 }
pub struct StatusFacts<'a> {
    pub items: &'a [StatusItem<'a>],
    pub ui: Option<UiInspection<'a>>,
    pub ui_actions: &'a [UiAction],
}
pub enum StatusError {
    InvalidOwner, OwnerConflict, SourceItems, SourceBytes,
    DuplicateId(u64), DuplicateWidget(u64), MultipleSingletons,
    InspectionUnavailable, OutputCapacity { required_bytes: usize },
    CounterExhausted,
}
pub struct StatusUpdate {
    pub changed: bool, pub epoch: u64, pub serial: u64,
    pub omitted: usize, pub shortened: usize,
}
pub struct StatusBridge { /* private, fixed storage */ }
impl StatusBridge {
    pub fn new(owner: u64) -> Result<Self, StatusError>;
    pub fn publish(&mut self, facts: Option<StatusFacts<'_>>)
        -> Result<StatusUpdate, StatusError>;
    pub fn bytes(&self) -> &[u8];
    pub fn write(&self, output: &mut [u8]) -> Result<usize, StatusError>;
    pub fn reset(&mut self) -> Result<(), StatusError>;
    pub fn publish_browser(&self) -> Result<(), StatusError>;
}
pub fn clear_browser(owner: u64) -> Result<bool, StatusError>;
pub extern "C" fn ferravex_status_v1_version() -> u32;
pub extern "C" fn ferravex_status_v1_revision() -> u64;
pub extern "C" fn ferravex_status_v1_ptr() -> *const u8;
pub extern "C" fn ferravex_status_v1_len() -> u32;
```

StatusKind/StatusError/StatusUpdate are Copy+Debug+PartialEq+Eq; borrowed items
and UiAction are Copy+Debug. Bridge owns no gameplay reference and is not Clone.
StatusFacts borrows the current immutable inspection and cannot outlive it.

Owner is a nonzero game-assigned u64 provenance token, not authentication. Keep
IDs attached to one authored meaning within that owner's lifetime. Use a fresh
owner when replacing the game; clear the old browser slot first. Browser-slot
storage belongs to the calling thread; the bridge's ordinary data belongs to its
Rust owner. Native threads have independent slots. This contract supports
single-threaded, unshared-memory Wasm only.

Epoch starts at 1, serial at 0. Every changed valid snapshot increments serial;
no-op/error does not. Reset checked-increments epoch, resets serial and clears
instance publication. Call `publish_browser()` after reset when adopted to clear
the old exported prefix as well. No counters wrap. Exhaustion preserves last-good
state, including an exhausted browser-slot revision; a fresh Wasm instance/thread
lifetime is required if that slot's revision is exhausted. Browser publication is
an explicit copy, not an automatic lifetime binding; dropping/resetting a bridge
alone does not clear its adopted copy. Successful `clear_browser(owner)` releases
that copy; a different owner is rejected. Reconnect reads one current snapshot
without replaying event history; a new binder announces its current lifecycle/
result once. Dispose/rebind on host replacement even if an owner token was reused.

## One versioned wire/export/browser contract

Wasm exports are defined inside the owned module with Wasm-only no_mangle;
there are no writable or executable-command exports. Wasm signatures:

```text
ferravex_status_v1_version: () -> i32         // 1, even when publisher absent
ferravex_status_v1_revision: () -> i64        // monotonic u64 bit pattern
ferravex_status_v1_ptr: () -> i32             // unsigned wasm32 address
ferravex_status_v1_len: () -> i32             // initialized byte count; no NUL
memory: WebAssembly.Memory
```

Revision changes only on changed exported-copy/clear operations, independently
of semantic epoch/serial. Rust u64 uses Wasm's **signed BigInt** return convention;
the reader validates the signed i64 range and compares the raw stamp losslessly.
It never converts it to Number. Native Rust returns u64 normally. Pointer is
normalized from the signed i32 view to unsigned wasm32. Metadata and function/
exports/memory identities are rechecked around copying; grow/replacement during
read is rejected and can recover on the next host-driven refresh. No view is
cached. Shared memory is rejected. Length zero means absent/unavailable, not `{}`.
Read only the current initialized `ptr..ptr+len` prefix, never buffer capacity.

Exact JSON shape (one parser; all keys required, extra keys rejected):

```json
{"version":1,"provenance":"ferravex-status","owner":"296","epoch":"1","serial":"2","available":true,"omitted":0,"shortened":0,"items":[{"id":"1","kind":"lifecycle","truncated":false,"label":"Won"}]}
```

owner/epoch/serial/IDs are canonical decimal u64 strings; owner/epoch/serial are
nonzero. Kinds are lowercase lifecycle/objective/result/action/notice/telemetry.
Unavailable snapshots have empty items and zero omitted/shortened counts.
The browser rejects absent/malformed/oversized/unstable data, invalid UTF-8,
UTF-8 BOM, lone JSON-escaped surrogates, invalid fields/counts/IDs, duplicate IDs,
multiple lifecycle/results, bad truncation totals, owner mismatch, regressing
counters or changed content with unchanged epoch+serial before changing status DOM.

Browser exports:

```text
STATUS_V1 = Object.freeze({version:1,maxBytes:57344,maxItems:32,maxLabelBytes:256})
readStatusV1(getExports, {owner}) -> frozen snapshot; throws Error on failure
bindStatusV1(container, getExports, {owner}) -> {
    get current(), get error(), get fresh(), refresh(), dispose()
}
```

`owner` is the expected canonical nonzero decimal string. `getExports` is a
synchronous provider of the current exports object. `refresh()` returns read
success, including a no-op frame; false on error/disposal/reentrant refresh.
There is no independent loop or scheduling hook. Only host update/lifecycle
calls drive reads. Validated DOM uses stable p elements keyed by stable IDs,
textContent, and bounded insertion/removal; epoch changes discard prior identity.
There are no actionable controls. Lifecycle/result text alone occupies one
`role=status`, aria-live=polite, atomic region. Numeric telemetry, objectives,
notices and current action hints stay outside it. Repeated snapshots and changed
numeric telemetry do not repeat lifecycle/result announcements.

Initial DOM says unavailable. Valid DOM is explicitly labeled **last validated**,
with counts/suffixes for truncation. Errors keep the last-good DOM byte-for-byte,
set fresh=false and expose error/current; the host can report freshness separately.
No fabricated replacement facts or error-driven live-region spam occurs.
Disposal is idempotent, clears owned DOM content/subtree/maps/current/error and
provider/DOM references, preserves unrelated elements/focus and blocks reentrant
or late publication. No timers/listeners need cancellation. Retained work/data
is bounded to one current snapshot/fingerprint, at most 32 item nodes and three
fixed containers; there is no history or repeated telemetry queue.
