## Concrete behavior and compatibility

The opt-in `SensorOccupancyTracker` consumes existing `ContactEvent::Started/Stopped`; it performs no collision detection, world polling, timing, rendering or platform I/O. Unknown starts must resolve explicitly to `Ignore`, `Track(Occupancy)` or `Unresolved`. The adapter never infers that a physical contact is a sensor. Both logical key types are caller-selected `Copy + Eq`, defaulting to generational `ColliderHandle` and `RigidBodyHandle`.

Each canonical physical collider pair has one cached logical sensor/actor association. Multiple physical child pairs may share that association: the first emits `Entered`, intermediate starts/stops do not emit, and the final stop emits `Exited`. Pair identity includes the complete collider generation. Reversed pair order is canonicalized. Duplicate retained starts never resolve again or increment occupancy. Unknown/duplicate stops emit nothing and return `UntrackedStop`. Stops use cached logical keys, so removed collider/body lookups are unnecessary.

Explicit actor/sensor removal preflights capacity for every distinct logical exit before mutation. It emits one exit per affected occupancy, retaining inactive pair mappings until their stops. Duplicate starts on those retained mappings cannot resurrect removed occupants. A new physical pair may subsequently enter with the same logical keys. Late stops for inactive pairs release mapping capacity without further exits.

Both pair storage (`PAIRS`) and undrained output (`EVENTS`) are inline fixed arrays; no tracker-owned heap allocation or unbounded collection. Output is a FIFO with copied iteration, single-event acknowledgement and explicit clearing. Zero capacities are supported. A transition needing a full output queue rejects atomically, without consuming the pair event; nontransition child changes and inactive-pair stops still succeed. Pair overflow also rejects atomically. No accepted output is silently dropped. Removal does not recover pair capacity because mappings must survive until their stops.

`consume_batch` reports the exact accepted prefix on ordinary failure; retry its rejected suffix before later input, or mark incomplete. An explicitly incomplete batch freezes updates before accepting any of its supplied prefix. `mark_incomplete` also freezes direct consumption and explicit removals. Neither operation emits exits, clears retained mappings, or discards earlier accepted output. Retained counts/output are historical observations while incomplete. Complete empty batches cannot unfreeze the tracker.

Recovery is explicit: `reconcile` installs a complete caller-owned resolved-pair snapshot, clears pending output, restores completeness, and emits no gameplay transitions. Incomplete, over-capacity, duplicate (including reversed) or self-pair snapshots reject without changing any existing state or output. Consumers reconcile their own state through `occupants()`. `reset` silently clears state/output at a caller-established empty baseline such as a scene restart; it never invents exits.

No changes to existing public types, defaults, world contact lifecycle, struct literals, exhaustive enums, wire/save/replay formats, exports, feature definitions, manifests or Cargo.lock. All new API lives in the already parent-registered module.

## Limits and deferred integration

- Parent must review combined concurrent source and verify native/Wasm integration. No Wasm/browser/device build, game playtest, performance claim or cross-platform determinism claim is made. Only the native host configurations above ran. Dimensionless feature configuration was not tested.
- One logical direction per physical pair per tracker. A sensor/sensor bidirectional game policy can compose two trackers. There is no implicit sensor classification or live reclassification.
- Complete/ordered input is a caller responsibility. Missing input cannot be inferred from `UntrackedStop`, since solid contacts were intentionally ignored. Same-generation delayed starts after their stops cannot be distinguished from real reentry without external sequence metadata. No automatic temporal deduplication is claimed.
- On reported loss, existing queries/output remain historical; callers must check completeness. Reset/reconciliation acknowledge queued output and emit no transitions, so gameplay consumer reconciliation is explicit.
- Pair mappings, including explicit-removal tombstones, consume capacity until stops or a complete baseline replacement/reset. Choose bounded capacities for the actual scene and handle retry/freeze policy; no opportunistic eviction invents exits.
- Linear pair lookup/counting; quadratic worst-case removal, distinct-occupant iteration and snapshot validation. Large const capacities also increase inline/stack storage; no unbounded heap fallback. Arbitrary callback/key-comparison allocation, side effects or panics are outside tracker atomicity/no-allocation guarantees; keys must have stable lawful equality.
- No manifest/dependency changes, so no dependency audit was needed. No workspace/shared build, dist/site generation, status update, staging/commit/branch/PR, deployment, schedule or delegation performed.
