## Concrete behavior and measure

Recording is **disabled by default** with zero record/motion vector capacity.
An enabled observer retains at most one record per canonical generational
collider pair per valid outer step, sorted by pair handle order. The selected
point supplies position, normal and approach speed. A strictly stronger peak
replaces it; equal peaks keep the earliest substep then earliest solver feature.
Transient solved contacts remain observable even when absent from the final
contact manifold cache. Sensors and sweep-only corrections with no accepted
velocity constraint impulse produce no record.

Measure: maximum over eligible contact points, solver iterations and substeps of
`max(0, accumulated_normal_impulse - initial_warm_start_impulse)`.
This is a **peak single-point new normal impulse**, not the sum of manifold
points, solver iterations or substeps. Reapplying cached warm-start impulse is
excluded; if cached impulse is first removed and then rebuilt below its starting
value, that rebuilding is also excluded. Solver overshoot can affect a peak.
Tangential, rolling, positional and joint impulses are excluded. This is not
total energy or acoustic loudness.

Eligibility requires approach speed **strictly above** the configured positive
threshold both before substep forces/gravity/damping/integration and at contact
creation before warm start. The saved before-force linear/angular velocities
are evaluated at the new constraint point about the old center of mass.
Ordinary support accelerated from rest by gravity/forces is excluded even with
cold solving or a disabled contact cache. There is deliberately no grounded
state, second collision detector or force decomposition: acceleration from rest
that causes an entire impact within one substep can be omitted. Persistent
solver jitter or real prior motion above the configured threshold can qualify;
thresholds must match scene units. Once eligible, the observed solve can include
force effects; it is not a measurement isolated from all external forces.

Impulse threshold is also a strict lower bound, finite/nonnegative (zero accepts
positive impulses). Approach threshold must be finite/positive. Defaults are
64 records, zero impulse threshold and 1 world-unit/second approach threshold.
These observer values do not modify existing solver settings/tolerances.

Capacity is 0..=65536 records. First qualifying pairs in substep/solver order are
retained, then canonically sorted for reads. Retained pairs can strengthen even
when full. Overflow is drop-new: `impact_dropped()` saturating-counts **qualifying
pair/substep candidates rejected at capacity**, once per pair in that substep,
regardless of point/iteration count. A rejected pair can count again on later
substeps (up to eight); this is not a count of distinct lost pairs or gameplay
hits. No unbounded set of rejected identities is allocated.

Configuration fallibly reserves logical record capacity and scratch for 4096
body motions before enabling. Allocators may round capacity up. Failed
configuration preserves settings, records and drops; a successful first reserve
followed by a failed second reserve may retain additional unused capacity.
Recording itself never reserves. Ordinary solver scratch can still grow for a
new contact set; preparation does not promise allocation-free arbitrary worlds.
Shrinking logical capacity, clearing, disabling and re-enabling reuse memory;
only dropping the world releases its reserved memory.

A valid outer step clears the old snapshot/drop count; invalid dt/gravity
panics preserve it. Explicit clear and changed settings/disable clear it;
identical settings preserve it. Removal, teleport, shape/settings edits preserve
the historical snapshot until reset/next valid step, including original handle
generations. Consumers must check live identities before subsequent gameplay
operations. Clearing observation never wakes bodies or changes physical caches.

## Exact public API

Defined in `world.rs`, now root-reexported by parent from `lib.rs`:

```text
pub const MAX_IMPACT_RECORDS: usize = 65536;
pub struct ImpactSettings { // Clone, Copy, Debug, PartialEq; Default
    pub capacity: usize,
    pub min_normal_impulse: f32,
    pub min_approach_speed: f32,
}
pub struct ImpactRecord { // Clone, Copy, Debug, PartialEq
    pub collider1: ColliderHandle,
    pub collider2: ColliderHandle,
    pub point: ferravex_math::Vec3,
    pub normal: ferravex_math::Vec3,
    pub peak_normal_impulse: f32,
    pub approach_speed: f32,
}
pub enum ImpactRecordingError { // Clone, Copy, Debug, PartialEq, Eq; Display, Error
    InvalidSettings,
    AllocationFailed,
}
impl<B: Access> World<B> {
    pub fn impact_settings(&self) -> Option<ImpactSettings>;
    pub fn set_impact_settings(&mut self, settings: Option<ImpactSettings>)
        -> Result<(), ImpactRecordingError>;
    pub fn impacts(&self) -> &[ImpactRecord];
    pub fn impact_dropped(&self) -> usize;
    pub fn clear_impacts(&mut self);
}
```

## Consumer handoff and runnable typed feedback recipe

The new `set_impact_settings` rustdoc contains a pure typed-cue recipe, with real
physics stepping, an inferred settings configuration, one read of the accepted
snapshot and explicit reset/cancel. It applies in either selected dimension.
The complete binary below additionally connects to the existing first-party
`ferravex_play::feedback` system without adding a physics dependency on play.

For Pinball/lab adoption: enable before ticks, choose thresholds for authored
mass/speed units, consume once after **each executed simulation tick** (including
catch-up), apply game-owned collider/layer rules, and assign nonzero feedback
IDs in the game/session. Do not derive repeated cues from render frames or
`ContactEvent::Started`. Treat `impact_dropped()` as observation loss and tune
capacity/policy explicitly. Keep network/replay simulation progressing through
local menus. Presentation motion/flash policy remains independent of sound.

```rust,check crate-type=bin
use ferravex_physics::{ImpactSettings, d2::*};
use ferravex_play::feedback::{FeedbackController, FeedbackEvent, FeedbackPolicy};

fn main() {
    let mut world = PhysicsWorld::default();
    world.set_impact_settings(Some(ImpactSettings {
        capacity: 8,
        min_normal_impulse: 0.01,
        min_approach_speed: 0.5,
    })).unwrap();
    let (_, bumper) = world.insert(
        RigidBodyBuilder::fixed(), ColliderBuilder::ball(0.5),
    );
    world.insert(
        RigidBodyBuilder::dynamic().translation(-Vector::X * 1.1)
            .linvel(Vector::X * 10.).ccd_enabled(true),
        ColliderBuilder::ball(0.5),
    );
    let mut feedback = FeedbackController::<8>::new(Default::default(), 7).unwrap();
    feedback.set_policy(FeedbackPolicy::new(true, true, 0.).unwrap());
    let mut next_feedback_id = 1_u64;
    let mut emitted = 0;
    world.step(1. / 60.); // One actually executed simulation tick.
    for impact in world.impacts() {
        let accepted = impact.collider1 == bumper || impact.collider2 == bumper;
        let event = FeedbackEvent::hit(
            impact.point, (impact.peak_normal_impulse / 10.).clamp(0., 4.),
        ).unwrap();
        let response = feedback.emit_if_accepted(next_feedback_id, accepted, event).unwrap();
        next_feedback_id = next_feedback_id.checked_add(1).unwrap();
        if let Some(response) = response {
            assert!(response.gain > 0.); // Semantic output, no audio sink.
            emitted += 1;
        }
    }
    assert_eq!(emitted, 1);
    assert_eq!(world.impact_dropped(), 0);
    assert!(feedback.advance(1. / 60.).unwrap().shake.translation.length() == 0.);
    world.clear_impacts(); // Acknowledge this snapshot; scene restart also clears feedback.
    feedback.clear();
    assert!(world.impacts().is_empty());
}
```
