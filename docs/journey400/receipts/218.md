## Exact public API

The module exports these signatures (all inputs are existing f32 vectors):

```rust
pub fn closest_point_segment2(point: Vec2, start: Vec2, end: Vec2)
    -> Result<ClosestPoints<2>, SegmentError>;
pub fn closest_point_segment3(point: Vec3, start: Vec3, end: Vec3)
    -> Result<ClosestPoints<3>, SegmentError>;
pub fn closest_segments2(first_start: Vec2, first_end: Vec2,
    second_start: Vec2, second_end: Vec2)
    -> Result<ClosestPoints<2>, SegmentError>;
pub fn closest_segments3(first_start: Vec3, first_end: Vec3,
    second_start: Vec3, second_end: Vec3)
    -> Result<ClosestPoints<3>, SegmentError>;

pub struct ClosestPoints<const N: usize> {
    pub first: [f64; N],
    pub second: [f64; N],
    pub first_parameter: f64,
    pub second_parameter: f64,
    pub distance: f64,
}

#[non_exhaustive]
pub enum SegmentError { NonFiniteInput }
```

`ClosestPoints` derives `Clone, Copy, Debug, PartialEq`; `SegmentError` derives `Clone, Copy, Debug, PartialEq, Eq` and implements `Display` and `std::error::Error`.

## Concrete behavior and compatibility decisions

- Rejects any NaN or infinite input coordinate, including otherwise unused endpoints of a degenerate segment. No state changes or fallback witnesses occur on error.
- Promotes coordinates before subtraction and uses f64 intermediates. Clamps parameters to `[0,1]`, with positive zero. Exactly zero-length segments are valid points with parameter zero; subnormal nonzero segments remain segments.
- Returns **f64 arrays**, not independently rounded Vec2/Vec3 witnesses. Witnesses are evaluated from their reported parameters using endpoint-preserving convex interpolation. Point queries have the supplied point in `first`, parameter zero, and its projection in `second`.
- `distance` is computed from the returned witness arrays with `hypot`, so distances exceeding `f32::MAX` stay finite, and nonzero tiny separation remains representable even if its square underflows f64. Presentation conversion is explicit, e.g. `Vec3::from_array(hit.second.map(|x| x as f32))`; that rounded point need not retain the original distance.
- Pair queries consider all four constrained endpoint projections and the interior closest-line solution. Compensated cross-product determinants avoid the near-parallel Gram determinant cancellation. Only an exactly zero computed cross product is treated as parallel; no epsilon silently drops near-parallel crossings.
- Candidates compare the difference of squared separations componentwise with compensated summation. A shared large separation cannot mask a smaller improvement on another axis. Equal computed differences use lexicographically lowest `(first_parameter, second_parameter)`. Parallel overlap therefore chooses its earliest point on the first ordered segment. Reversing/swapping a tied pair can change its chosen witness. Identical reversed segments return first start and second parameter one.
- Four/five candidates, fixed-size arrays and at most three wedge components: constant bounded work/storage, no heap-backed container. Capacity/reset semantics do not apply to stateless scalar queries. Repeated valid/error/degenerate/recovery sequences and a thread-local allocation counter verify zero allocations on tested query paths. The counter has a real-allocation positive control and follows the existing math integration-test harness; production math remains `forbid(unsafe_code)`.
- Existing public vectors, struct literals/enums, save/wire/replay formats and authored defaults are untouched.

## Limits for parent

The API provides ordinary f64 numerical geometry, not exact predicates or a conditioning certificate; widely disparate coordinate scales can still lose precision, and ties refer to computed squared-separation differences. Native tests do not establish cross-platform bitwise determinism. Wasm, other native targets, full-workspace/facade integration and game adoption remain unverified here and belong to the parent. Allocation evidence is from the executed native query paths, not a global benchmark or every platform implementation of floating-point primitives.
