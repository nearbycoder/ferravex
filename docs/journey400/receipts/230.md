## Time, work bounds and partial completion

Time is one supplied monotonic `Duration` domain per state, with exact microsecond precision and inclusive maximum `2^53` microseconds. Sub-microsecond, out-of-range and backwards values return explicit errors before protocol/game mutation; equal times are allowed. Invalid operations replace last_report with an error report. A valid supplied time advances the time watermark even if a later operation fails. Native/Wasm adapters pass `started.elapsed()` sampled at their host boundary. Reliable retry milliseconds are derived from that same domain using the existing floor-to-milliseconds behavior; Pong timestamps use its microseconds. Cookie supply occurs only for a new/churned session, must return nonzero, and remains host-owned; suppliers must provide suitable fresh session cookies.

- <=16 peers; each receive processes exactly one bounded <=1200-byte datagram and <=6 inputs. Bad datagrams reject as packet counts; no cookie/output is attempted for malformed traffic.
- <=128 pending inputs per peer, using the existing checked admission/coalescing. Only tick removes a queued sample (at most one newest/coalesced sample per peer), combines it with held controls and local input, then executes the existing Match/Mode step once. Reports distinguish queue admission/refusal, consumed/coalesced remote samples and total authority actor commands. Receive and poll never simulate movement. The existing twelve-tick held-control expiry remains.
- <=8 commands per peer per command receive; <=8 per peer per poll/tick, <=128 across the full roster. <=8 reliable offers per peer per poll/tick. OutputBudget additionally clamps callbacks/accepted bytes to <=128 datagrams / 153600 bytes per core operation; zero/exact/short budgets are valid.
- Peer storage: 32 full snapshots / 38400 bytes, 256 outgoing reliable payloads of <=900 bytes each, 256 durably admitted commands (each validated two-byte action), one completed action-result slot, and bounded existing input/Delta scratch. Whole command-window admission deliberately separates incoming receipts from the outgoing event window, so 255 successors cannot block the missing head. Logical total retained backlog can exceed the old combined admission gate, but both windows are explicitly capped. Existing combined-backlog overflow still disconnects a slow peer when queuing tick events; no event is silently discarded to keep that peer alive.
- These are logical work/storage bounds for valid Match state, not allocator/RSS or throughput bounds. Public Match raw mutations must obey its existing roster/state requirements. Snapshot player collection, packet decoding, legacy Match/RewindStep results, reliable admission/encoding and peer creation can allocate. No zero-allocation driver claim is made. The existing legacy Mode/practice step APIs are retained deliberately rather than forcing checked StepOutput validation or changing game policy.

`receive` dispatches one packet and can send welcome/snapshot/Pong/command ACK. `poll` expires peers, drains durable ordered commands when downstream space opens even without any new packet, and flushes due events; it never ticks. `tick` validates local input before maintenance/commands/simulation, performs one fixed step, queues accepted events/round updates, emits due snapshots and flushes events. Output refusal/capacity is a completed tick, with returned accepted Match events and `tick_executed=true`. Encode/retention/result errors after partial work return Err; last_report retains committed-prefix counts and whether the simulation tick executed. Do not retry an already executed tick as rollback. An action may execute before a later tick error; its result is durable and counted separately. Invalid raw Match fields can cause a later encoder failure; the core does not promise to repair/transactionally roll back that public state.

An outgoing callback receives only the checked, complete initialized prefix. True means complete local admission, false means refusal. The first refusal or nonfitting packet stops all later offers for that core operation. Accepted external effects are never rolled back; a callback that externally sends then returns false or panics can cause duplicates. WouldBlock is false, never successful admission. A short/fatal socket result is false plus a retained host io error, propagated after core work; the adapter adds that send error to the operation's report. `send_due` commits timestamps only for true; refused/deferred head and untouched tail remain due. Byte budgets count full envelopes separately from reliable payload budgets.

Report refusal counts callbacks returning false; deferred counts generated candidates that were not offered, not every undiscovered reliable tail. `reliable_remaining_due` counts the full sampled backlog after poll/tick (partial prefix if an earlier error aborts sampling). Commands_executed counts applications, including rule refusals whose actual ActionResult is retained. Packet/queue/rule rejection is distinct from a DriverError. A bool output sink's own external failure classification remains caller-owned. Reports are per core operation: a GameServer::poll may invoke many receives and a final core poll, so its last_report is the last core operation, not an aggregate socket-poll report. Cumulative existing server rejection/disconnect/shot counters remain available. pending_event_count includes the rare durable result slot as well as the sender window; pending_command_count counts admitted, unexecuted ordered commands.

## Authentication, recovery and compatibility

Preserved protocol v5, session/address gates, shot validation, life epochs, default practice/respawn behavior, tactical Mode, existing wire/save/replay/checkpoint bytes and game policies. All input/authentication/event/shot behavior remains on actual existing Match APIs. No relocation-specific protocol behavior or new Match loop was introduced.

Hello reflection/churn is still gated at 250 ms, including when outgoing Welcome is refused; this is an incoming admission gate separate from reliable-send retry timing. Lost accepted Welcome uses a later Hello with the same nonce/cookie. A new nonce rotates the session, clears pending controls/shot claims, ACK/baseline/ping state, reliable sender/receiver and completed result slot, preserves the actual player's health/ammo/position/aim, and resumes fresh sequence admission. The five-second peer timeout remains strict greater-than. Snapshot ACKs, reliable ACKs, pings, inputs and commands from old sessions are rejected before state admission.

One task229 SenderBaselines per peer retains the exact full encoded snapshot only after accepted outgoing datagram, whether wire output was full or delta. Never retains delta-wire bytes. Only an exact retained tick ACK in the exact peer/session can authorize a base. Unknown ACKs increment packet rejection; exact repeated/stale retained ACKs do not replace authorization. A None ACK resets history and authorization. The acknowledged bytes are evictable within 32 slots; after eviction, bounded full fallback is used until an exact newly retained snapshot is acknowledged. Failed local output never authorizes its tick. Storage failures after accepted external output return an error without pretending to retract the datagram. Existing tick-only ACK ambiguity after complete serial reuse remains the outer session/age constraint documented by229.

Remote commands validate session and application bytes before task312 `admit`. ACK only successful retained/duplicate receipts. Admission is independent of execution. Before an action the outgoing event window must have space and the completed-result slot must be empty. The existing Mode action runs once; its fixed-size ActionResult is durably placed in that slot before the receiver consumes the command. Encoding/queue failure preserves that completed result, stops subsequent actions and reports the error, including sequence exhaustion. There is no apply-then-false callback rollback claim. Poll retries result transfer/draining when an ACK frees space. Original slow-peer tick-event disconnection policy remains deliberate and covered.
