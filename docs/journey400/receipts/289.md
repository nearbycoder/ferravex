## Concrete behavior and compatibility

- Uses the real `scene::Skeleton` and existing `scene::Transform`. Caller-owned
  borrowed name/rest-local arrays are parallel to `Skeleton::joints()`. There is
  no replacement skeleton, name field added to `Joint`, matrix decomposition,
  animation format extension or altered legacy behavior.
- Preparation checks both skeletons against `MAX_ANIMATION_JOINTS` (1..=256),
  exact metadata lengths, nonempty names of at most 4096 UTF-8 bytes, global name
  uniqueness, actual parent-before-child topology and every rest transform.
  Name comparisons are literal: no case folding, path interpretation, trimming,
  alias inference or Unicode normalization. Duplicate diagnostics carry side,
  first index and duplicate index; missing diagnostics identify the side/index
  where the unmatched name occurs. The caller can recover the original name
  from its authoring metadata.
- `Strict` requires identical name sets, reporting the first unmatched target,
  then first unmatched source. `TargetRestFallback` explicitly allows unused
  source joints and keeps unmatched target joints at normalized target rest.
  Matched joints must have matched immediate parents, or both be roots. Sibling
  and complete sibling-subtree reorderings are accepted. Unmatched parent
  skipping, parent/root mismatches and inferred reparenting are rejected.
- Local right-delta convention: `T_target = T_target_rest *
  inverse(T_source_rest) * T_source_pose`. These are LOCAL column-vector T*R*S
  transforms. Translation deltas rotate into the target rest frame and scale
  by the target/source rest-scale ratio; rotation deltas act after the target
  rest orientation. World poses are evaluated separately by the real target
  skeleton. This is not world-space retargeting, IK, automatic bone-length
  fitting, root-motion extraction or an end-effector guarantee.
- Supports finite translation, scene-valid nonzero finite quaternions and
  exactly uniform strictly positive scale. Existing checked quaternion
  normalization/inversion, `Mat4::checked_inverse`, scene matrix composition and
  `PreparedAffine3D` are reused. Nonuniform scale, any negative/zero scale,
  nonfinite/invalid transforms, singular/unrepresentable linear inverses,
  unrepresentable full source-rest inverses and unrepresentable offsets/results
  are explicit errors. Raw/sheared matrices are not accepted as pose/rest inputs,
  so no lossy shear decomposition or reflection repair is performed. Existing
  inverse-bind matrices are preserved and need not equal these rest inverses;
  their relationship remains caller-authored and downstream skin evaluation is
  separate. No new restrictions were imposed on `Skeleton` itself.
- Preparation owns bounded normalized rest copies and indexed offsets. Names
  and rest metadata may be dropped immediately after construction. Shared
  lifetime borrows retain the exact two skeleton identities and prevent safe
  mutation/replacement while the map exists. `source()`/`target()` return those
  exact objects. Raw transform slices inherently have no identity: callers must
  supply source-order locals and consume output with the bound target; arbitrary
  same-length mislabelled poses/authoring metadata cannot be detected.
- Hot mapping performs no name lookup, heap allocation, I/O or clock work.
  Exact source length is checked first, then output capacity, then all source
  transforms (including unused joints), then all target results. Two fixed
  256-Transform stack buffers stage normalized input and output (about 20 KiB
  total for current Transform layout). Only after complete validation is the
  target-length output prefix copied. All output bits, NaN payloads, signed
  zeros and tails survive errors; success retains the unused tail.
- Refeeding the original source-rest metadata produces stored normalized target
  rest exactly. Mapping has no hidden state/reset requirement. Reconfiguration
  means constructing an owned replacement, then assigning only on success;
  failed construction cannot mutate a last-good map. Tests exercise recovery
  after failed construction/mapping and repeated animated/rest reuse.
- Construction has O(joints) bounded storage and O(joints²) name comparisons;
  each name comparison is also bounded by 4096 bytes. Mapping is O(joints).
  No dependencies were added. The dependency audit was not required.
