## Concrete behavior

`Match::relocate_player` accepts a host/authority-chosen feet destination for an existing **living** actor. Missing, invalid-ID and dead actors reject. It never respawns/heals, changes ammo/aim/weapon/respawn timers, runs rules, consumes input, advances tick, creates GameEvents, or clears/overwrites retained StepOutput. There is no score field in Player, and no external score/rules callback is invoked. Existing respawn APIs retain reset ownership. Client input still has no location field or relocation authority.

Final preflight order is invalid ID, oversized options budget, nonfinite/out-of-domain destination, 233 arena validation, complete allocation-free checkpoint state validation, actor existence/alive, checked generation increment, complete static clearance, explicit dynamic occupancy. All finish before any player/history/tick mutation. Arena options preserve the explicit legacy empty-spawn/origin allowance. Complete state validation checks all players (including unrelated/dead players), unique IDs/counts, finite/ranged controller/weapon fields, arena bounds and rewind ordering/ages. Destination components must be finite and within +/-4096, matching existing checkpoint bounds; no normalization/clamping/recovery occurs. Rejection preserves all current state/storage/output, including prior nonempty events/rejections/sidecar.

Static clearance uses existing `character::check_clearance` against the actual Arena Terrain/all layers and the exact FPS upright capsule radius0.3/height1.8. Implicit ground ID0 and source-index+1 solids are unchanged. Touching uses the helper's existing 1e-5 tolerance. Budgets are 0..=1_000_000 visited candidates, include ground, and must prove a complete query: QueryBudget is an error even after observing a blocker. Arena validation bounds traversal at ground plus256 solids. No second collision detector, shape approximation or scratch vector was introduced.

Dynamic occupancy is explicit: StaticOnly checks no players; ForbidLivingAabb rejects overlap of open axis-aligned radius/height bounding volumes against every other living player, ignoring self/dead/absent actors. Exact touching is allowed; lowest actor ID is reported independent of roster ordering. This is conservative dynamic AABB occupancy, **not exact capsule/capsule collision** or swept/future safety. Defaults select ForbidLivingAabb and Reset with257 clearance candidates.

Reset sets velocity zero, grounded false and JumpState::default (coyote, buffer, held). Clearance does not acquire ground support; the next real motor tick does. Preserve retains those fields exactly, deliberately including previous ground/coyote/buffer/held continuity at a new pose. A behavioral test demonstrates a preserved buffered/coyote jump actually executes without a new jump input while Reset clears that continuity; local detailed prediction and actual Match stepping agree.

Every accepted request, even to the same coordinates, checked-increments the existing full u64 authority life/discontinuity generation once. At u64::MAX it rejects atomically; it never aliases or clears global history. The private helper captures a missing current frame normally or replaces **only the relocated actor** in an existing current frame. Repeated same-tick accepted relocations thus expose the latest accepted position/alive/life, while retaining every other actor's old and current recorded poses/lives unchanged. Normal bounded ring eviction remains in effect when a new tick frame is needed. Pre-boundary poses of this actor remain stored but fail existing generation checks. Other actors remain hittable at their historical positions. Untimed ordinary shots use the live accepted position. Shot-time validation/window rules are unchanged.

The result returns exact accepted feet position, retained aim, actor, current tick and full generation. Relocation executes no tick: subsequent accepted StepTransition uses the new life and next wrapping executed tick. Both retained spawn paths continue through the untouched shared kernel. Existing new_life behavior for legacy spawn/respawn/round reset is unchanged; relocation uses its own checked increment instead of that legacy exhaustion fallback.
