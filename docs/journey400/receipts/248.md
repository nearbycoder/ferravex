## Behavior and compatibility

- Legacy `Stagger::new`, `hit`, `advance`, `active` and `buildup` signatures remain.
  New uses zero grace. A threshold hit immediately after recovery still starts
  another stagger. Hit arithmetic, validation bounds, idle decay and the original
  regression sequence remain unchanged with the default/explicit disabled policy.
- The opt-in policy rejects all poise hits during grace, including zero hits;
  damage admission remains independent. It never accumulates hidden poise and
  never restarts the grace timer. Active spam still cannot extend stagger.
- Positive grace starts at the actual recovery boundary. One advance consumes
  active remainder, then grace remainder, then idle decay. A large step reports
  recovery and grace-end once, at offsets from that call's start. It cannot
  synthesize another onset. Zero grace emits recovery but no grace-end event.
- `hit_report` distinguishes accumulated poise, accepted onset, active rejection
  and grace rejection. `advance_report` returns only the current call's boundary
  crossings. Legacy wrappers discard reports; nothing is queued or replayed by
  reads or subsequent zero steps. Hosts must consume each returned receipt once.
- Policy is validated at construction: finite `0..=3600` grace seconds. Existing
  bounds remain threshold `0.01..=1e6`, decay `0..=1e6`, duration `(0..=3600]`, hit
  `0..=1e6`, dt `0..=3600`, all finite. NaN/infinity/out-of-range validation occurs
  before mutation, including phase-rejected hits. Tests compare all state and
  later behavior after invalid hits and dt.
- There is no in-place configuration edit API: construct a replacement (fresh
  idle state) to change tuning. Invalid construction never mutates an existing
  instance. `reset` clears poise and both timers, keeps all tuning, emits nothing,
  and is idempotent.
- Stagger retains Clone/Copy/Debug, all fields remain private; PartialEq is
  additive. Existing LoopError variants and public literals are untouched. Two
  private f64 fields add stored policy/current grace; no stable memory-layout
  contract is asserted. No wire/save/replay/native/Wasm ABI or game defaults change.
- No dynamic storage, callbacks, clocks, I/O or allocations were added. Reports
  have fixed storage for two optional offsets, with at most one of each boundary.
  Timers and offsets use f64; public dt remains f32. Idle poise retains legacy
  per-call f32 rounding, so arbitrary time repartitioning need not bit-match.
