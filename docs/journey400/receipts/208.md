## Exact additive public APIs

In `ferravex_engine::pool`:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum PoolAccessError {
    InvalidHandle { position: usize },
    DuplicateHandle { first: usize, second: usize },
}
// Implements std::fmt::Display and std::error::Error.

impl<T> Pool<T> {
    pub fn get2_mut(
        &mut self,
        first: Handle,
        second: Handle,
    ) -> Result<(&mut T, &mut T), PoolAccessError>;

    pub fn get_many_mut<const N: usize>(
        &mut self,
        handles: [Handle; N],
    ) -> Result<[&mut T; N], PoolAccessError>;
}
```

The signature block is an API excerpt, not standalone runnable Rust.

- Results preserve caller order, including reversed slot order and arbitrary
  fixed-array selections. No `Clone`, `Copy` or `Default` bound on pooled values.
- Liveness is validated for every requested handle before returning references:
  out-of-range, vacant, retired or generation-mismatched handles are invalid.
  The first invalid selection position wins over any duplicates, even if a
  duplicate occurs earlier. Only when all handles are live are duplicates
  rejected, reporting the earliest repeated position and its first occurrence.
- Error positions are zero-based caller selection positions. Errors leave values,
  generations, pool length, free-slot ordering and storage unchanged.
- Empty selections succeed on empty, full, zero-capacity and retired pools;
  single selections work through the same API. Full pools support access.
- Validated indices go through safe standard-library slice `get_disjoint_mut`.
  Production code adds no unsafe, remove/reinsert choreography, temporary slot
  growth, heap scratch collection, or returned heap collection. Validation is
  O(N²) with O(N) stack storage, independent of pool capacity. Small selections
  are recommended; whole-pool work still uses `iter_mut`.
- Successful caller mutations are ordinary Rust mutations, without rollback on
  subsequent caller panic. Access does not invalidate handles or move values.

## Runnable consumer handoff

The executable `Pool::get2_mut` rustdoc recipe in `pool.rs` creates two live,
non-Clone actors in a full pool. It transfers four units of energy and swaps
their velocities for a one-dimensional equal-mass collision response, then
asserts final energy/velocities through the original handles. It never removes
or reinserts either actor. Run it with:

```sh
cargo test -p ferravex-engine --doc pool:: --offline --locked -j 2
```

The recipe is intended for an accepted interaction within an actual simulation
tick; callers emit feedback after success. No clock, renderer or input ownership
is added. Error-type and `get_many_mut` doctests demonstrate failure handling and
three-actor selection order. Parent may choose a game consumer later; no
concurrently owned game needs modification to use or validate this capability.
