## Concrete behavior and compatibility

The operation first validates finite request parameters, planar z constraints,
explicit zero-axis normalization and requested output capacity. It rejects a
world exceeding the requested live-collider work limit before geometry/query
work. A read-only numeric guard uses the same existing `geometry::distance`
kernel, current child pose, and query membership/sensor/ignored-body predicates.
It checks finite distance, separation, normal, both witnesses, pose and COM for
every filtered collider, including distant/static colliders. This conservative
guard prevents task220's documented nonrepresentable-result omission from
silently establishing a false complete candidate set. It does not select bodies
using COM/final-pose radius guesses or replace the overlap detector.

The actual selection calls existing `PhysicsWorld::overlap_sphere_into` with
`QueryOptions { max_distance: 0., layers, ignored_body, sensors }`, retaining its
point-probe semantics at radius zero and sphere/circle radius range 0..=1000.
Every hit must fit caller scratch, including fixed/kinematic/sensor children.
A truncated result returns `CandidateCapacity { required: total }` before effects.
An exactly-full complete buffer is accepted. Scratch is ephemeral and may change
on failure. Caller-supplied scratch values are overwritten by the real query.

Complete candidates sort allocation-free by body handle, signed separation,
then collider handle. Exactly one nearest filtered child represents each body;
no child-count weighting or repeated compound kick occurs. Accepted output is in
ascending generational body-handle order. Fixed and kinematic bodies are omitted.
Sleeping dynamics use explicit Skip, Preserve (store velocity, preserve sleep/
quiet/wake flags), or Wake (existing immediate body wake plus next-step island
propagation). A zero impulse neither wakes nor produces an accepted entry.

Direction is center-to-current-COM with f64 subtraction/normalization. Exact COM
coincidence either skips the body or uses the caller's explicit finite nonzero
axis; tiny/subnormal and very large axes normalize safely. Planar axis z must be
zero even for empty worlds or zero strength. Selection/falloff still comes from
accepted child surfaces, including a sensor child near the blast whose parent's
COM is outside the radius. Direction policy never substitutes a new detector.

Constant falloff gives weight one. LinearSurface uses
`clamp(-separation / radius, 0, 1)` from task220's signed sphere separation;
penetrating surfaces have full weight, touching at the sphere boundary has zero
weight, and zero-radius accepted point probes have weight one. PerBody applies
`magnitude * weight`. Total divides one scalar impulse budget among eligible
unique bodies in proportion to those weights. It bounds scalar magnitudes, not
vector sum, momentum by axis, velocity change or kinetic energy. Ordinary f32
rounding applies; underflow-to-zero entries are absent and unused underflow
budget is not redistributed. No eligible weights means no spent impulse.

Before mutation, the helper checks every nonzero selected effect against pending
child mass edits, finite positive inverse mass, the exact f32 multiply by inverse
mass used by the existing method, and the resulting f32 velocity addition.
Pending mass is rejected without calling `refresh_mass_properties`; the caller
can refresh explicitly before retrying. All nonzero accepted bodies must fit the
requested `max_bodies`; output must hold that requested capacity even for a miss.
No first-N effects are committed. Ordinary invalid/truncated/max-body/work/
mass/numeric failures preserve all velocities, angular state, sleep/quiet/wake,
forces/torque, kinematic targets, revisions, contacts/events and every accepted
output slot. The operation retains no state requiring reset.

After preflight, existing dimensional `RigidBody::apply_impulse(impulse, wake)`
is called once per accepted body. This is a linear COM impulse, with no torque
and no platform I/O, simulation tick, clock, damage, particles or audio. Success
writes exactly the applied body/collider/separation/impulse prefix and clears the
unused output tail. There are no existing API, public-literal/enum, wire/save/
replay or native/Wasm export changes.

## Exact public API

All names below are in `ferravex_physics::radial`. Signature excerpts are not
standalone runnable examples; the module and trait rustdocs contain executed
recipes. All value types derive Clone, Copy, Debug and PartialEq; policy enums,
error and report also derive Eq, and report derives Default and is must-use.

```rust
pub enum ImpulseModel { PerBody(f32), Total(f32) }
pub enum Falloff { Constant, LinearSurface }
pub enum ZeroDistance { Skip, Axis(ferravex_math::Vec3) }
pub enum SleepingPolicy { Skip, Preserve, Wake }
pub enum RadialSensors { Exclude, Include, Only }

pub struct RadialImpulseRequest {
    pub center: ferravex_math::Vec3,
    pub radius: f32,
    pub model: ImpulseModel,
    pub falloff: Falloff,
    pub zero_distance: ZeroDistance,
    pub sleeping: SleepingPolicy,
    pub sensors: RadialSensors,
    pub layers: u32,
    pub ignored_body: Option<ferravex_physics::RigidBodyHandle>,
    pub max_bodies: usize,
    pub max_colliders: usize,
}
pub struct RadialImpulse {
    pub body: ferravex_physics::RigidBodyHandle,
    pub collider: ferravex_physics::ColliderHandle,
    pub separation: f32,
    pub impulse: ferravex_math::Vec3,
}
pub struct RadialImpulseReport {
    pub colliders: usize,
    pub candidates: usize,
    pub applied: usize,
}
#[non_exhaustive]
pub enum RadialImpulseError {
    InvalidCenter,
    InvalidRadius,
    InvalidMagnitude,
    InvalidZeroAxis,
    OutputCapacity { required: usize },
    WorkLimit { required: usize },
    CandidateCapacity { required: usize },
    BodyLimit { required: usize },
    IncompleteGeometry { collider: ferravex_physics::ColliderHandle },
    PendingMass { body: ferravex_physics::RigidBodyHandle },
    NonFiniteEffect { body: ferravex_physics::RigidBodyHandle },
}
// Implements std::fmt::Display and std::error::Error.

pub trait RadialWorld: sealed::Adapter {}
// `sealed` is private: only the existing dimensional worlds implement this.
// The inherited Candidate associated type is the corresponding OverlapHit;
// generic callers can name W::Candidate, as checked by the public rustdoc.

pub fn apply_radial_impulse<W: RadialWorld>(
    world: &mut W,
    request: RadialImpulseRequest,
    candidates: &mut [Option<W::Candidate>],
    output: &mut [Option<RadialImpulse>],
) -> Result<RadialImpulseReport, RadialImpulseError>;
```

The module's common `Vec3` request/report representation requires z=0 for d2;
it does not shrink the existing dimensional query/report types or change them.
