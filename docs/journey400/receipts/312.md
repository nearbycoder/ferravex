## Concrete admission and ACK behavior

- `admit` retains a fresh payload in the existing bounded BTreeMap and returns
  `Ok(Receipt::Retained)`. It never delivers or advances `next_sequence`.
  `Ok(Receipt::Duplicate)` means an already retained/delivered sequence.
  ACK **only either Ok**, individually by the incoming packet's sequence.
  Do not ACK any Full/OutsideWindow/Oversized/SequenceExhausted error.
- Capacity is an absolute retained-packet cap for this admission, clamped to
  EVENT_LIMIT=256. It is not an additional allowance. Lowering it does not evict
  existing receipts. Duplicates still succeed at zero/full capacity. Full means
  a fresh in-window packet cannot be retained under the supplied cap; it changes
  nothing. With the full 256-sequence window, a missing head has a reserved
  sequence position even when all 255 successors arrived first.
- A smaller hard cap can fill with successors while the missing head is refused.
  Callers must leave head room, expand the cap when downstream storage frees,
  or use the full window. Admission errors never slide the window or silently
  drop a retained event. Do not compute capacity by subtracting buffered twice.
- Exact error precedence: oversized payload (including duplicates) first;
  sequence below next is a delivered duplicate; forward distance >=256 is
  OutsideWindow; sequence MAX inside that window is SequenceExhausted; existing
  buffered sequence is Duplicate; only then check capacity. Retries of future
  sequences leave next/count/content unchanged and can succeed after actual
  delivery moves the window.
- First retained payload wins on conflicting duplicate bytes, preserving legacy
  semantics; no replacement and no extra allocation. Delivered payload bytes
  are not kept for comparison. Same bytes at different sequences are distinct
  events. This is not authentication: validate outer session and application
  payload before admission.
- Sender's final valid sequence MAX-1 remains valid. Receiver can deliver it and
  move to MAX without wrapping; MAX cannot be admitted. At the default cursor,
  MAX is OutsideWindow; near exhaustion it is SequenceExhausted. This fixes the
  old malicious-MAX path that could remove a payload before checked_add failed.
  Reserved-MAX errors now leave queued data and cursor intact.

## Delivery, output and partial failure contracts

- `drain_into` transfers payload ownership without cloning into the consecutive
  empty output prefix, starting at slot zero. A Some slot immediately stops;
  later holes are not searched. Empty slices/full destinations accept nothing.
  Output after the accepted prefix, including occupied sentinels and empty
  slots, is unchanged. No next-sequence advance happens before the output slot
  owns its packet. Receiver keeps every unaccepted head/tail.
- Output slice length limits accepted packets (the receiver additionally caps
  work at EVENT_LIMIT). Byte budget counts payload only. Too-large head stops
  before consumption; no small/empty successor jumps it. Empty payload consumes
  a slot/packet and zero bytes. Exact byte fits succeed; zero packet budgets
  cannot consume an empty payload.
- `drain_ready` borrows `(sequence, &[u8])`; true commits consumption, false stops
  without changing that head or tail. Callback work must synchronously consume
  or explicitly copy bytes. The mutable receiver borrow prevents safe reentry.
  Packet/payload budgets count accepted work; refusal is the final callback.
- Report counts accepted packets/bytes for this call, the exact remaining
  contiguous ready prefix, and all buffered packets (including gapped tails).
  Both the drain and report scans are bounded by the 256-packet window.
- With native unwind, prior true acceptances persist; a panicking callback's
  head and tail remain retained, with cursor still at that head. No report
  returns. External side effects cannot roll back: acting then returning false
  or panicking can repeat those effects on retry. Tests explicitly demonstrate
  repeated external effects rather than claiming arbitrary transactions.
  Aborting panic recovery is not claimed.
- Legacy `receive` is now the allocating full-capacity admission/all-ready drain
  wrapper. Normal legacy-only behavior, duplicate first-wins and once-only
  sequence order are preserved. Errors drain nothing. When APIs are mixed, a
  valid duplicate (including an already-delivered one) can trigger legacy drain
  of a previously admitted ready prefix. It consumes that prefix; callers must
  handle the returned vector. It does not repeat previously delivered events.
  Output Vec capacity is reserved before removing each payload; standard
  allocation failure behavior is not a recoverable Error guarantee.
- Default replacement discards retained data and resets next to zero. Existing
  session validation must reject delayed old packets/ACKs; resetting either end
  within the same session can replay or lose work. Keep an ACKed receiver alive
  until delivery completes. Tactical round restart is not a new transport
  session and must retain reliable cursors/queues.
