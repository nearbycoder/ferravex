## Concrete behavior and guarantees

`WorldJointFrame` supplies a shared world pivot or two world anchors, plus one
world hinge axis. World pivots transform through each **current authored body
origin**, independently of child collider transforms and compound COM offsets:

```text
local_anchor_i = conjugate(body_rotation_i) * (world_anchor_i - body_origin_i)
local_axis_i   = conjugate(body_rotation_i) * normalized(world_axis)
captured_reference = normalized(conjugate(rotation_A) * rotation_B)
```

This uses the existing description/solver frame representation. A separate full
frame quaternion per endpoint is unnecessary for the existing joint kinds and
is not added. The axis is meaningful only for hinges. +Z is the planar default
and +Y the spatial default. All finite nonzero axis scales, including subnormal
and huge values, use existing checked math normalization **before** rotation.
Zero/nonfinite hinge axes fail; planar axes must satisfy the existing +Z
validation tolerance. Non-hinge joints ignore the axis, including invalid values.

The caller explicitly chooses a mode; there is no implicit mode default:

- `Preserve`: replace the description's reference rotation with the current
  relative rotation; replace distance/spring rest length with current world
  anchor separation. Fixed/hinge pivots must be exactly the same input world
  point, otherwise return `InvalidJoint`. Existing local anchors/axes are replaced
  by the world frame; superseded reference/rest-length fields need not be valid.
- `Authored`: retain the supplied rest length and explicit reference rotation;
  a missing reference captures the current relative rotation **at sampling**.
  Separated fixed/hinge pivots are accepted and may cause intentional correction.

Preserve mode removes initial geometric/rest error within f32 rounding. It does
**not** disable or retarget limits/motors, clear velocities/forces, cancel queued
kinematic targets, ignore contacts, freeze bodies or guarantee a motionless next
step under those influences. Limits excluding zero and active motors still act
normally. Spring stiffness/damping, enabled state, contacts policy, break limits,
motor and limit fields are retained exactly. Tests show a retained motor executes
on the immediate next tick even though the initial authored hinge angle is zero.

Both live generational handles are checked before pose/geometry validation.
Removed/reused handles return `InvalidHandle`; same-body or no-dynamic-endpoint
pairs return `InvalidJoint`. Fixed and kinematic endpoints work when paired with
a dynamic body, in either order. Nonfinite retained body origins or nonunit/
nonfinite rotations return `InvalidBody`. Invalid/overflowed local geometry,
invalid axes and any rejected final `JointDesc::validate(planar)` return
`InvalidJoint`. Existing anchor/range, planar, spring, motor, break and reference
validation remains authoritative. Handles must belong to this world; they do
not encode world identity.

Read-only sampling is constant-storage and does not allocate, change revisions,
wake bodies, clear caches, alter pending motion or execute/issue simulation ticks.
It reads setters/teleports and shape/COM edits immediately, without stepping or
query refresh. It works with full joint capacity and needs no revision budget.
The returned ordinary `JointDesc` is a snapshot; moving bodies before insertion
does not automatically reauthor that snapshot.

The inserting convenience samples and immediately calls the unchanged
`insert_joint` path. Its ordinary validation/capacity errors preserve the world;
success retains existing allocation, wake, collision-filter and cache behavior.
The 4096-joint limit is unchanged. Sampling intentionally does not check capacity;
insertion returns `JointCapacity` at the limit and succeeds after a removal.
Successful insertion may allocate existing arena/filter/event storage. Arbitrary
caller-defined `Into<JointDesc>` execution and panics (including inherited
insertion revision-exhaustion/allocation behavior) are outside transaction and
allocation guarantees. The existing insertion code was not changed.

## Exact public APIs and registration

The following types/methods are defined independently in **both**
`ferravex_physics::d2` and `ferravex_physics::d3` by the existing api.rs includes.
`Vector` is the module's existing Vec2/Vec3 alias; the axis always uses Vec3.
Signature reference, not a standalone executable snippet:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum JointPoseMode { Preserve, Authored }

#[derive(Clone, Copy, Debug, PartialEq)]
pub struct WorldJointFrame {
    pub anchors: [Vector; 2],
    pub axis: ferravex_math::Vec3,
}
impl WorldJointFrame {
    pub fn at_pivot(pivot: Vector) -> Self;
    pub fn at_anchors(anchors: [Vector; 2]) -> Self;
    pub fn with_axis(self, axis: ferravex_math::Vec3) -> Self;
}
impl PhysicsWorld {
    pub fn joint_desc_from_world(
        &self,
        a: RigidBodyHandle,
        b: RigidBodyHandle,
        desc: impl Into<ferravex_physics::JointDesc>,
        frame: WorldJointFrame,
        pose: JointPoseMode,
    ) -> Result<ferravex_physics::JointDesc, ferravex_physics::PhysicsError>;

    pub fn insert_joint_from_world(
        &mut self,
        a: RigidBodyHandle,
        b: RigidBodyHandle,
        desc: impl Into<ferravex_physics::JointDesc>,
        frame: WorldJointFrame,
        pose: JointPoseMode,
    ) -> Result<ferravex_physics::JointHandle, ferravex_physics::PhysicsError>;
}
```

## Runnable consumer handoff

Two executable Rustdoc recipes on `WorldJointFrame` in api.rs are the first-party
consumer handoff. They are compiled **and executed** by package doctests:

1. A 2D translated/rotated support and rotor use `insert_joint_from_world`, a
   shared world pivot, preserved initial angle and unchanged hinge limits. The
   next ordinary fixed tick verifies that the rotor does not initially snap.
2. A 3D translated/rotated pair uses a scaled world axis, samples a description,
   inserts through the existing `insert_joint`, and checks its immediate next
   tick. It removes the hinge, then authors/inserts a spring from two separated
   anchors with the captured rest length and retained stiffness/damping.

The cfg-gated recipes are included under both dimensional type paths; default
doctests contain four new entries and execute both intended recipe branches.
Single-feature doc runs execute that feature's applicable recipe branch too.
