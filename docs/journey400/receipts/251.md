## Behavior and exact mutation/error order

- Construction validates N=1..256, positive caps, ranks<=caps, K<=N and nonzero namespace. K=0 is valid. It takes existing ranks, starts points=0, next serial=1, and has no RNG access.
- `credit` is explicit checked u32 addition. Overflow admits nothing and changes no rank, point, offer or serial; zero is a no-op. Repeating successful credit adds again intentionally. Caller owns accepted award authority, event deduplication, save/replay/rollback consistency and external reward delivery. Preview/restore/report copies must never be treated as fresh awards. Check capacity before committing external progression (under host serialization) or retain an owed award on refusal; there is no callback/external transaction guarantee.
- `open` first returns a cached offer. Otherwise zero points, zero K or all capped returns Ok(None); these precede exhaustion. Next, exhausted serial returns SerialExhausted. Otherwise existing Upgrades::offers selects distinct eligible indices; publish once and consume one serial. It consumes exactly min(K, eligible count) legacy RewardRng outputs, including one for a sole eligible choice. Short offers retain trailing None. No empty offer, invented choice, surprise entropy, partial prefix algorithm, retry or weighted selection is introduced. All failure/empty/cached paths consume zero RNG and no serial. Invalid K is rejected before RNG can be supplied. Abandonment is an explicit host decision permitting the next open to draw again.
- `choose` checks matching pending namespace/serial (StaleOffer), then balance (NoPoints), membership (NotOffered), then rank/cap (Capped), in that order. No rejection changes ranks, points, offer or serial. Rank apply is the existing checked operation; only after its success are the point debit and offer consumption committed, with no fallible external work/callback. Exactly one rank and one point commit together in this owned object. Whole offer consumption makes all repeated submissions stale, including another branch, a later keyboard press or callback after a new offer opens. No implicit next offer/RNG use. Public APIs cannot mutate the owned ranks concurrently; capped/no-point final guards are additionally fault-injected in inline tests.
- `abandon` returns/removes pending, retaining points/ranks/next serial. Repeated abandonment returns None. `reset` returns discarded points/pending, resets ranks/points, and retains caps/namespace/next serial including exhaustion. Old callbacks remain stale after reopening. Caller separately resets RNG/input/other run state. Reseeding reproduces choice indices without reusing identity.
- Serials are 1..=u64::MAX, checked, never wrapping. The last serial is usable, its cached offer remains readable/acceptable, then new nonempty opens fail SerialExhausted. Reset cannot restore serial capacity. Recreate with a fresh nonzero caller namespace; namespaces are not globally enforced, signed or security-grade. Reusing a namespace while old tokens survive can collide, explicitly demonstrated by a test. No persistence/anti-replay service is claimed.

Storage is O(N+K), fixed arrays/scalars only, with N<=256/K<=N. New open uses existing O(N+K) offer selection; choose scans at most K and updates one rank; reset is O(N). No heap allocation, clocks, rendering or I/O in production. A thread-local instrumented System allocator observes a positive Box control and zero alloc/alloc_zeroed/realloc calls during maximum-256 pool opens, redraws, rejected/accepted/repeated choices, reset, credit overflow and abandon. This is native measured/source evidence, not universal allocator, stack-size or performance evidence. Test-only unsafe forwarding is confined to this integration-test binary; production remains under the crate's forbid(unsafe_code).

```rust,check crate-type=bin
use ferravex_core::session::GameSession;
use ferravex_play::{
    gameplay::{
        loot::RewardRng,
        progression::Progression,
        upgrades::{UpgradeChoices, UpgradeChoiceError, Upgrades},
        waves::{WaveSequence, WaveSpec},
    },
    input::{ActionMap, Binding, InputCode},
};

fn main() {
    let mut session = GameSession::try_new(64.0, 4, true).unwrap();
    let mut waves = WaveSequence::new([WaveSpec {
        credits: 1, interval: 0.125, rest: 0.0, reward: 10,
    }], 1).unwrap();
    let mut xp = Progression::new(10, 0, 4).unwrap();
    let mut choices = UpgradeChoices::<2, 2>::new(Upgrades::new([2; 2]).unwrap(), 251)
        .unwrap();
    let mut rng = RewardRng::new(7);
    let mut input = ActionMap::default();
    let confirm_code = InputCode::Key(32);
    let confirm = input.try_action(vec![Binding::digital(confirm_code)]).unwrap();
    let mut executed = 0;

    // An actual tick admits one actor; it remains alive through this update.
    let frame = session.advance(1.0 / 64.0);
    assert_eq!(frame.steps, 1);
    for _ in 0..frame.steps {
        executed += 1;
        assert!(!input.consume_tick(confirm).pressed);
        assert!(waves.admit(1, 0));
        assert_eq!(waves.advance(frame.dt, 0.0, 1).unwrap(), None);
    }
    assert_eq!(choices.points(), 0);

    // The headless host now confirms that admitted actor's defeat. Award only
    // this newly emitted clear, with serialized capacity preflight before XP.
    let frame = session.advance(1.0 / 64.0);
    for _ in 0..frame.steps {
        executed += 1;
        assert!(!input.consume_tick(confirm).pressed);
        let clear = waves.advance(frame.dt, 0.0, 0).unwrap().unwrap();
        let amount = u64::from(clear.reward);
        let expected = xp.preview_award(amount);
        assert!(choices.points().checked_add(u32::from(expected.promotions)).is_some());
        let report = xp.award_report(amount);
        assert_eq!(report.promotions, 1);
        choices.credit(u32::from(report.promotions)).unwrap();
    }
    let offer = choices.open(&mut rng).unwrap().unwrap();
    let chosen = offer.choices()[0].unwrap();
    assert_eq!(choices.points(), 1);

    // Quick press/release survives a zero-tick redraw. Two executed catch-up
    // ticks share one consumed edge each; the offer is never rerolled.
    input.feed(confirm_code, 1.0);
    input.feed(confirm_code, 0.0);
    assert_eq!(session.advance(0.5 / 64.0).steps, 0);
    assert_eq!(choices.open(&mut rng).unwrap(), Some(offer));
    assert_eq!(choices.points(), 1);
    let frame = session.advance(1.5 / 64.0);
    assert_eq!(frame.steps, 2);
    let mut accepted_count = 0;
    for _ in 0..frame.steps {
        executed += 1;
        let action = input.consume_tick(confirm);
        if action.pressed {
            let accepted = choices.choose(offer.id(), chosen).unwrap();
            assert_eq!((accepted.rank_after, accepted.points_after), (1, 0));
            accepted_count += 1; // Accepted receipt is the feedback boundary.
        }
        // A local choice display never gates authoritative wave progression.
        assert_eq!(waves.advance(frame.dt, 0.0, 0).unwrap(), None);
    }
    assert_eq!((session.tick(), executed, accepted_count), (4, 4, 1));
    assert_eq!(choices.choose(offer.id(), chosen), Err(UpgradeChoiceError::StaleOffer));
    assert_eq!((xp.level(), choices.points(), choices.upgrades().rank(chosen)),
        (2, 0, Some(1)));
    assert!(session.is_playing()); // No fake game win/terminal state.
}
```
