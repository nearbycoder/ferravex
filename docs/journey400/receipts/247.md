## Behavior and compatibility

The existing Shield field list and Clone/Copy/Debug remain intact. No heap storage,
queue, additional retained state, dependency, feature, balance, host, wire, save,
replay, ABI, manifest, lockfile, root or game edits. Host layout-size regression
compares the original field types; Rust repr remains unspecified, not a new ABI
promise. Existing new/absorb/advance signatures and operation ordering are
preserved; wrappers call the detailed methods. Frozen original-model tests compare
legacy/detailed values and timer bits for 3,000 hit/advance pairs, including signed
zero, disabled configurations, fractional values and capped large steps.

Independent state axes have no precedence. A zero maximum is both full and broken;
a broken shield can also be delayed or recharging. Positive maximum AND rate enable
recharge. A full shield is not recharging; enabled, below-full, delay-zero means
recharging eligibility, not guaranteed stored gain. Disabled recharge still consumes
a live delay. Zero damage never resets it; positive confirmed damage resets it even
when empty/disabled. All old input ranges remain: finite maximum/rate/damage
0..=1e6 and delay/dt 0..=3600 seconds. Errors remain LoopError::Invalid; other
LoopError variants unchanged.

Detailed receipts retain before/after stored f32 values and independent flags.
Damage routing reports legacy absorbed=min(damage,value) and unabsorbed; tiny
absorptions can round away in storage, so nominal absorption is NOT claimed equal
to stored loss. value_change subtracts promoted stored endpoints in f64; the
endpoints remain available if even that difference rounds. Recovery requires
zero-to-positive storage, depletion positive-to-zero, and filled below-full-to-full
with actual positive storage change. Exact delay expiry, zero dt, zero hits,
repeated empty hits, capped/full steps and sub-ULP increments cannot falsely repeat
these signals. A single large advance may recover and fill. Receipts are per-call
facts, not queued/deduplicated persistent events. Reconfiguration receipts describe
charge edits; only actual accepted advance receipts should drive recharge cues.

Reconfiguration validates ALL new values through the original constructor before
any mutation. PreserveValue clamps on shrink, never heals on growth. PreserveRatio
uses f64 value/old_maximum * new_maximum followed by f32 rounding/capping; old maximum
zero explicitly means zero fraction (growth stays empty). Ratio changes deliberately
alter charge, including growth. Live timer becomes min(old_remaining,new_delay):
shorten by capping the pending remainder, never extend on delay growth and never
restart an elapsed timer. This does not reconstruct elapsed time since a past hit.
Rate-only/identical edits preserve the timer. Subsequent positive hits use the new
full delay. Restart is explicit replacement with Shield::new(authored settings),
which restores full charge and zero wait; no misleading automatic reset event.

Recharge still rounds to f32 each call. Partition tests use a stated case-specific
0.002 tolerance over 1,000 fractional steps; bitwise equivalence across different
partitions is NOT promised, and sufficiently small increments may all round away.

## Executable first-party consumer recipe

This complete headless bin uses GameSession at 64 Hz, real ActionMap tick-edge
consumption, ActionTimeline activation, a geometric melee-range check and actual
HitWindow serial/target admission. It does not invent a hit boolean. Shield/health
are changed only after admission; repeated overlapping active ticks cannot repeat
the hit or reset its shield delay. Elapsed time and key input are injected test
inputs, not browser/player evidence. Issued and executed ticks are counted
separately. This local standalone session intentionally pauses; network/replay
adoption must keep authority progressing while suppressing local commands.

```rust,check crate-type=bin
use ferravex_core::session::GameSession;
use ferravex_play::{
    action::{ActionEdge, ActionPhase, ActionSpec, ActionTimeline, HitWindow},
    gameplay::shield::Shield,
    input::{ActionMap, Binding, InputCode},
};

fn main() {
    let mut session = GameSession::try_new(64., 8, true).unwrap();
    let mut input = ActionMap::default();
    let code = InputCode::Key(32);
    let attack_key = input.try_action(vec![Binding::digital(code)]).unwrap();
    let mut attack = ActionTimeline::new(ActionSpec {
        windup: 1. / 64., active: 4. / 64., recovery: 2. / 64.,
        cancel_before: 1. / 64., buffer_seconds: 0.,
    }).unwrap();
    let mut hits = HitWindow::<4>::new().unwrap();
    let mut shield = Shield::new(20., 8., 4.).unwrap();
    let mut health = 100_f32;
    let mut accepted_hits = 0;
    let mut depletion_cues = 0;
    let mut executed = 0;
    let attacker_x = 0_f32;
    let target_x = 0.5_f32;
    let melee_reach = 1_f32;
    let target_id = 7; // Host-owned generational identity in a real game.
    input.feed(code, 1.);
    input.feed(code, 0.);
    assert_eq!(session.advance(0.5 / 64.).steps, 0);
    assert_eq!(shield.value(), 20.); // Pending tap has not yet been consumed.
    let batch = session.advance(4. / 64.);
    assert_eq!(batch.steps, 4);
    for dt in batch.ticks() {
        if !session.is_playing() { break; }
        executed += 1;
        let recharge = shield.advance_detailed(dt as f32).unwrap();
        assert!(!recharge.recovered());
        let command = input.consume_tick(attack_key);
        let frame = attack.step(dt as f32, command.pressed).unwrap();
        for event in frame.events() {
            match event.edge {
                ActionEdge::Activated => { assert!(hits.begin(event.serial)); }
                ActionEdge::Recovered | ActionEdge::Finished | ActionEdge::Cancelled => hits.close(),
                ActionEdge::Started => {}
            }
        }
        let in_range = (target_x - attacker_x).abs() <= melee_reach;
        if attack.phase() == ActionPhase::Active && in_range
            && hits.accept(attack.serial(), target_id).unwrap()
        {
            let receipt = shield.absorb_detailed(25.).unwrap();
            health = (health - receipt.unabsorbed).max(0.);
            accepted_hits += 1;
            depletion_cues += u32::from(receipt.change.depleted());
        }
    }
    assert_eq!((batch.steps, executed, session.tick()), (4, 4, 4));
    assert_eq!((accepted_hits, depletion_cues, health), (1, 1, 95.));
    assert_eq!(shield.delay_remaining(), 4. - 3. / 64.);
    assert!(session.set_paused(true));
    assert_eq!(session.advance(10.).steps, 0);
    session.restart();
    shield = Shield::new(20., 8., 4.).unwrap();
    input.suppress_held();
    hits = HitWindow::<4>::new().unwrap();
    attack = ActionTimeline::new(ActionSpec {
        windup: 1. / 64., active: 4. / 64., recovery: 2. / 64.,
        cancel_before: 1. / 64., buffer_seconds: 0.,
    }).unwrap();
    assert!(shield.state().full && !shield.state().delayed);
    assert!(!hits.accept(attack.serial(), target_id).unwrap());
    assert_eq!(session.tick(), 0);
}
```
