## Behavior and owner contract

`CueBatch<'a, N>` exclusively borrows one `&'a mut GameAudio` for a presentation frame, with checked `1..=128` slots. Collect caller-accepted events over actual ticks and flush once for presentation. Its lifetime prevents replacing or directly resetting/pausing the borrowed controller before another batch operation. Batch `pause()` and `reset()` first cancel all pending slots, then invoke the actual owner's lifecycle method. Reset retains pause/acoustics through GameAudio. Release/drop the batch before resuming the controller or restarting its owner. There is intentionally no owner accessor or batch resume method: paused queued work cannot survive into a resumed owner. Drop cancels without submitting anything or stopping any voices. `cancel()` only clears queued work; pause/reset preserve other controllers' voices and already-playing nonpositional UI clicks through existing GameAudio behavior.

The batch captures the existing audio runtime's `Weak<()>` identity, including its allocation lifetime protection; it never infers controller identity from an address or raw voice handle. A valid collection or flush reconciles runtime replacement and discards stale requests. Read-only length/count queries do not reconcile. Validation failures preserve both pending work and counters even across replacement; the next valid operation reconciles. Explicit cancellation takes precedence in accounting when pause/reset cancels already-stale work. GameAudio still repairs its own tracked handles when invoked; no mixer ownership logic was duplicated or changed.

Categories use caller-authored `u32` keys, Cue, policy and critical flag. Reusing a currently pending key with different cue/policy/critical metadata returns `CategoryConflict`, including across different positions. Definitions need not persist once their category is no longer pending. Only identical category keys **and exactly equal positions** coalesce. `None`, `Some(Vec3::ZERO)`, left/right positions and other distinct origins remain separate. No position averaging, volume summing/multiplication, gameplay ID deduplication, score/damage inference or synthetic accepted events.

`First` keeps the first gain. `Strongest` replaces only on strictly greater raw gain; ties keep the first. `Latest` selects the incoming gain even if weaker/equal. Coalescing retains the original slot order. At capacity, a new critical request evicts the oldest noncritical slot, shifts the bounded tail and appends. Other arrivals drop; all-critical overflow retains earlier requests regardless of gain. Existing critical slots cannot be displaced by noncritical arrivals. Critical affects batch storage only; it does not raise voice priority or guarantee mixer admission. Coalescing at full capacity precedes overflow handling.

Raw gain must be finite in exactly `0..=4`; all supplied coordinates must be finite. Errors are atomic and do not clamp. GameAudio applies acoustics once and retains its own validation, priorities, buses, pause semantics, reservation, steals and rejection policy. Nonpositional Click can flush while paused; positional Click is gameplay audio and returns actual `None` suppression. Flush calls actual `cue_with_outcome`/`at_with_outcome` and consumes suppressed/rejected requests without retry. Empty/repeated flush does not replay sound. Existing defaults, sound bank, ring recovery, wire/save/replay formats and exports are unchanged.

Storage counters saturate: retained insertions (including eviction insertions), coalesced requests, replacement selections (a coalesced subset), evicted slots, dropped arrivals, explicit cancellations and runtime discards. Flush resets frame counters and returns ordered exact requests plus `Option<VoiceAdmission>`. Actual started, stolen, pause-suppressed, invalid-parameter, reserved-budget and priority rejection counts are distinct. `admitted()` counts starts plus steals, including voices later stolen during the same flush; it is not a live-voice or audibility count. Muted/zero-gain voices can be admitted and silent.

Every collection scan, eviction shift, cancellation and flush is bounded by `N <= 128`; queue is O(N), flush O(N) GameAudio calls, each retaining its existing bounded voice scans. Fixed arrays and weak identities require no batch heap storage. The allocation probe measured **zero allocations across 128 warmed iterations** of batch creation, distinct spatial categories, coalescing, critical eviction, overflow, flush/empty flush, cancel, pause, suppression, reset and offline PCM render. Audio bank/runtime/mixer creation and arbitrary host callbacks are outside allocation/rollback claims. Runtime replacement can require fresh bank setup through GameAudio.

## Exact public API

All names below are in `ferravex_render::audio::batch`; all shown fields are public, and Cue/Vec3/VoiceAdmission are the existing types.

```text
enum Coalesce { First, Strongest, Latest }
struct CueCategory { key: u32, cue: Cue, policy: Coalesce, critical: bool }
struct BatchedCue { category: CueCategory, position: Option<Vec3>, gain: f32 }
enum BatchError { Capacity, Gain, Position, CategoryConflict }
enum QueueOutcome {
    Retained, Coalesced { replaced: bool }, Evicted(BatchedCue), Dropped
}
struct BatchCounts {
    retained: usize, coalesced: usize, replaced: usize, evicted: usize,
    dropped: usize, cancelled: usize, runtime_discarded: usize
}
struct CueOutcome { request: BatchedCue, admission: Option<VoiceAdmission> }
struct FlushReport<const N: usize> {
    batch: BatchCounts, submitted: usize, started: usize, stolen: usize,
    suppressed: usize, rejected_invalid: usize, rejected_reserved: usize,
    rejected_priority: usize, outcomes: [Option<CueOutcome>; N]
}
impl<const N: usize> FlushReport<N> {
    pub fn admitted(&self) -> usize;
    pub fn rejected(&self) -> usize;
}
struct CueBatch<'a, const N: usize> { /* private fields */ }
impl<'a, const N: usize> CueBatch<'a, N> {
    pub fn new(owner: &'a mut GameAudio) -> Result<Self, BatchError>;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
    pub fn counts(&self) -> BatchCounts;
    pub fn queue(&mut self, category: CueCategory, position: Option<Vec3>,
                 gain: f32) -> Result<QueueOutcome, BatchError>;
    pub fn cancel(&mut self) -> usize;
    pub fn pause(&mut self) -> usize;
    pub fn reset(&mut self) -> usize;
    pub fn flush(&mut self) -> FlushReport<N>;
}
```

No new public GameAudio API. No Send implementation or unsafe production code. Rustdoc compile-fail tests verify exclusive lifecycle borrowing and inability to move the accumulator to a scoped thread.
