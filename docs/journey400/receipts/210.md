## Concrete behavior and compatibility

- `Option<&T>` and `Option<&mut T>` are now accepted wherever a single `Access`
  is accepted, including `World::get`, `World::query`, `World::try_query`, and
  `World::get_many`, and in the existing tuples of up to four accesses.
- Missing components produce `None`; present components produce `Some(Ref)` or
  `Some(RefMut)`. Components are never inserted or registered by optional reads.
- Required members continue to filter iteration. All required matches are checked
  before any member is borrowed, even when an optional member comes first.
  Optional-only queries visit every live entity in stable slot order, including
  componentless entities. Dead slots are skipped.
- Optional accesses reuse the corresponding required access's TypeId, type name,
  and mutability metadata. Mutable overlap within a tuple returns the existing
  `Error::ConflictingQuery` during signature validation, even on an empty world,
  absent component types, or an empty `get_many` input. Repeated shared access
  remains valid.
- An incompatible outstanding borrow of a present optional component returns
  `Error::BorrowConflict`; it is never converted to `None`. `try_query` validates
  the signature; dynamic conflicts arise when fetching an item. `try_iter`
  reports the conflict and continues to later entities. Ordinary iteration
  retains its panic-on-conflict behavior.
- `get_many` preserves input order and its existing error precedence: signature,
  all entity identities, then entity/tuple fetch order. Missing required members
  still return `Error::MissingComponent`. Duplicate entities with a present
  mutable component return `Error::BorrowConflict`; repeated absent optional
  mutable members are permitted. Any failure drops completed array items and
  partial tuple guards without changing component values.
- Optional access validates identity before checking presence. Invalid or stale
  handles still return `Error::NoSuchEntity`, including after slot reuse. Handles
  remain world-local; this task does not change cross-world identity semantics.
- Public `Error` variants, public method signatures, tuple limits, entity
  representation/generations, required-access defaults, and structural borrowing
  rules are unchanged. No wire/save/replay/export changes are introduced.

## Exact public API

New implementations on the existing sealed public trait (signature excerpts):

```rust
impl<T: 'static> Access for Option<&T> {
    type Item<'world> = Option<Ref<'world, T>>;
    // Existing hidden Access methods: info, matches, fetch.
}
impl<T: 'static> Access for Option<&mut T> {
    type Item<'world> = Option<RefMut<'world, T>>;
    // Existing hidden Access methods: info, matches, fetch.
}
```

Both implement `sealed::Access`. The existing blanket `Query for A: Access` and
tuple implementations expose them automatically. No new public trait, struct,
enum, inherent method, or registration is needed. Existing callable entry points:

```rust
pub fn get<A: Access>(&self, entity: Entity) -> Result<A::Item<'_>, Error>;
pub fn query<Q: Query>(&self) -> QueryBorrow<'_, Q>;
pub fn try_query<Q: Query>(&self) -> Result<QueryBorrow<'_, Q>, Error>;
pub fn get_many<Q: Query, const N: usize>(
    &self,
    entities: [Entity; N],
) -> Result<[Q::Item<'_>; N], Error>;
```

The shared and mutable implementations' hidden fetch signatures are both
`fn fetch(world: &World, entity: Entity) -> Result<Self::Item<'_>, Error>`;
`matches` is `fn matches(world: &World, entity: Entity) -> bool` and checks live
identity; `info` is `fn info() -> Option<AccessInfo>` and delegates to required
access metadata.

## Safety, bounds, and regression evidence

The crate retains `#![forbid(unsafe_code)]`; this change adds no unsafe code.
Optional fetch validates the entity, obtains the existing typed `RefCell`, uses
`try_borrow`/`try_borrow_mut`, and transposes `Option<Result<guard, Error>>` into
`Result<Option<guard>, Error>`. This keeps presence independent of borrow success.
Returned guards retain the world lifetime and can outlive their iterator. The
existing tuple `?` cleanup and fixed-array initialization handle partial errors;
they were exercised without replacing either mechanism.

The thirteen new tests cover:

1. Required Position with optional shared Velocity and mutable Health, retaining
   stationary entities and excluding an entity whose optional component is held
   but whose required component is absent.
2. Empty worlds, optional-only shared/mutable queries, absent registered slots,
   indices beyond a type's storage length, never-registered types, dead slots,
   deterministic order, iterator exhaustion, and mutation of present values.
3. Nine required/optional shared/mutable tuple alias combinations, both member
   orders, absent types, empty worlds, empty batches, and signature-before-identity
   error precedence.
4. Direct optional get conflicts for shared/exclusive guards, recovery after
   release, and absence on another entity while a present value is borrowed.
5. Fallible iterator conflict reporting, partial optional guard cleanup, continued
   iteration, retained guards outliving iterators, and overlap with another query.
6. Required-member prefiltering with optional accesses first, plus get_many's
   distinct missing-required-component error and guard cleanup.
7. Ordered heterogeneous get_many, mutations, empty arrays, and duplicate entities
   whose optional mutable component is absent.
8. Repeated shared optional/required members and repeated shared entity inputs.
9. Duplicate present mutable entity failures releasing completed and partial
   optional guards, preserving values, and permitting successful retry.
10. External mutable optional conflicts and later required-member absence,
    cleanup across multiple entities, and preservation of the caller's guard.
11. Remove/reinsert, despawn/reuse, stale/invalid handles, identity prevalidation
    before an earlier borrow conflict, clearing all entities, and repopulation.
12. A 128-entry absent optional mutable batch without type registration or growth
    of entity/free/storage-map buffers, followed by ordinary insertion.
13. Panic-path iteration cleanup and successful borrows after the conflict clears.

No new heap allocation or scratch collection is introduced by optional access.
Query iteration keeps its existing fixed cursor/state; get_many keeps its existing
stack space proportional to N and bounded tuple metadata. Buffer capacity checks
are behavioral observations, not allocator instrumentation or benchmarks. Large
caller-selected N retains the existing stack-space constraint; no new absolute
capacity or allocation-failure guarantee is claimed.
