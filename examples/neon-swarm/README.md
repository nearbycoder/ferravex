# Neon Swarm

Restored locally with first-party Ferravex APIs. Native play currently uses Linux X11/GLX; browser play uses the shared WebGL2 host. This recovery has not been published, and prior backend test results must be rechecked.

A complete compact 2D twin-stick survival shooter built with Ferravex. Clear three escalating waves of drones in an industrial containment arena. Fast chasers and armored brutes flank four pieces of bullet-blocking cover. Defeated enemies drop health after every fifth kill. Dash through danger to survive; a completed run ends with a sector-secured screen.

```sh
cargo run --release -p neon-swarm
cargo test -p neon-swarm --offline --locked -j 2
cargo run --release -p neon-swarm -- --autoplay --smoke-frames 1800 --screenshot /tmp/neon-swarm.png
```

Default controls: Enter or the **Start** button begins a run. WASD or arrows move, mouse aims, left click fires, and Space/Shift dashes. Escape pauses/resumes; R starts a fresh run. Touch: the lower-left stick moves, tapping the right side dashes, and weapons automatically aim/fire at the nearest drone while a gameplay touch is active. On a gamepad, use the left stick to move, right stick to aim, right trigger to fire, A to dash/confirm, Start to pause, and Back to restart. Controls can be remapped in the shared Controls panel (F2).

The HUD reads fire, dash, pause and movement hints from `PlayerInput::format_hint` after sampling the saved profile. Confirm/restart prompts follow the same bindings. The most recently used input family selects the hints; returning to mouse/keyboard after touch restores the pointer reticle. Unbound actions say **Unbound**; long mappings use an ellipsis or **See Controls** instead of old default keys. Numbered touch/pad hints identify the channels shown in Controls, not a claim about connected hardware. The default right touch area is labelled **Touch 7** to stay accurate after remapping. In the browser, pause before using Shift+Tab to leave the canvas; up arrow still moves backward through renderer menu choices. The host's Instructions link explains keyboard focus return.

Below 900 logical pixels wide (or 480 high), the HUD and menus use a separate responsive screen viewport. The arena keeps its original centered 1280×800 fit and pointer-to-world mapping. At 320/390 portrait widths, the upper letterbox contains 14–15px health, shield, ammunition/reload, dash, wave, XP/damage and encounter status; binding hints occupy separate rows below play. Ready, pause and result cards wrap their 16px detail text and offer a 48px-high action. Long bindings ellipsize at the same font size; Controls retains the full mapping. The web host passes CSS dimensions and logical pointer coordinates to Rust, while DPR and resolution settings affect the framebuffer only, so the compact UI does not divide its sizes by DPR.

When the lower letterbox has at least 156px and the canvas is at least 240px wide, the default touch stick and **Touch 7** control move into that space: an 88px-diameter stick hit area and a 96×56px right button. Touch the displayed right button to dash with the default mapping. They retain touch channels 0/1 and 7 and the same two saved-layout slots; customized layouts remain owned and drawn by Controls. Resizing releases existing captures through the shared touch API. Otherwise, the existing arena-relative touch regions remain. Wide desktop composition is retained. Extremely short windows clip secondary compact rows instead of shrinking all text; this finite fallback is not a claim of comfortable play at arbitrarily small sizes.

Opening Controls or losing gameplay focus pauses a manual run. Closing Controls or returning focus leaves the **Resume** screen up; explicitly resume with the button, Enter, or Escape. Movement, cooldowns, wave breaks, and run time freeze while paused. Held combat buttons must be released before they can activate again, and a buffered dash is discarded. Both **Sector secured** and **Signal lost** offer the same **Play again** button, keyboard Enter, or gamepad A retry path. Retry resets combat, progression, pending input, feedback, audio travel history, and the session clock.

`ferravex_core::session::GameSession` owns start/pause/terminal/retry state and runs simulation at 120 Hz, with at most 12 catch-up ticks per frame. The internal `Run::advance` samples combat commands only on actual ticks, preserving quick taps through zero-tick frames and consuming each dash edge once across catch-up ticks. `Game::update_with_feedback` emits accepted fire, dash, hit, hurt, and pickup events directly; health comparisons cannot hide shield damage or a hit followed by healing in the same tick. The shared bounded `FeedbackController<32>` routes those events to presentation without changing combat outcomes.

Ferravex's `World` stores enemies, bullets, and pickups in separate component queries. Projectile sweeps select the nearest hit and compare cover occlusion, so fast shots cannot tunnel through enemies or scenery. The existing `SwarmAi` uses shared sight/hearing memory, decision graphs, budgeted path planning, waypoint following, and separation to pursue around cover. Kills cancel the removed drone's pending AI route work. The deterministic autoplay uses the same movement, dash, and weapon rules; headless tests verify that it defeats all 41 drones at both regular and irregular render cadences. Autoplay bypasses automatic focus suspension for smoke runs, while explicit pause still works.

After the last drone and pending spawn credit in a wave are gone, a 1.6-second **Wave clear / Next in…** banner gives a recovery interval; the final wave displays **Securing…** before victory. Amber rings mark the actual melee contact radius and thicken during the shared `ActionTimeline` windup; an exclamation mark, phase countdown and **Evade** prompt make threats readable beyond color alone. Step or dash out before the attack activates. White impact crosses confirm nonlethal hits, larger cyan crosses confirm kills, and a distinct cue accompanies each confirmed hit. The shared impact envelope adds a small cross emphasis when motion is enabled. The HUD separates active drones from queued admissions and shows wave number, level, XP to the next level, shot damage, shield, health, dash availability/recharge, and weapon reload status. A lethal hit ends the run even if a health drop or the last kill occurs on that tick.

The game needs no downloaded textures, fonts, audio, or models. Flat geometry, cyan/coral silhouettes, sparse floor joints, and procedural sound cues keep combat readable. The browser's **Sound** button enables audio; shared sound settings control volume and mute.

Presentation reads the shared renderer feedback policy before accepted events and again before drawing on every frame, including menus and frames with zero simulation ticks. Reduced motion clears dash trails, impact emphasis and moving sparks and stops pickup pulsing. Reduced flashes independently clears muzzle flashes, enemy/player damage flashes, the arena flash and additive sparks, and stops pickup blinking. Disabling either channel clears its existing effects; re-enabling does not revive them. Static attack/entry markers, hit crosses, health information and an expiry ring on pickups remain visible. These options do not change combat timing, invulnerability, damage, scoring or autoplay. The game adds no preference storage or duplicate Wasm export.

Particles and short-lived muzzle/hurt/dash effects now belong to a private presentation owner. Its fixed 512-particle pool uses `Emitter::burst_with_budget`; suppressed bursts have zero budget and no deferred backlog. Presentation time ages cosmetics even on a paused screen. `GameAudio::pause` retires owned gameplay voices on Ready/Paused screens; explicit play/resume accepts fresh cues. Retry resets audio history and effects, while terminal screens allow the accepted victory/loss cue to finish. Audio acceptance remains independent of visual preferences.

Engine gaps exercised: swept segment/circle and segment/AABB queries were promoted to `ferravex_core::collision` and this game now uses them. Circle/rectangle character movement remains game-specific. This game now uses the shared `ferravex_render::canvas::Canvas2D` helper added during this game suite to unify aspect-preserving drawing and mouse/touch transforms. The helper maps drawing and pointer/touch coordinates through the same aspect-preserving canvas. Native Linux currently uses physical window pixels; automatic desktop DPI scaling is not implemented.

Kills build a 3.5-second score chain, increasing the multiplier every three kills up to x5. Taking a hit breaks the chain. The HUD and best-run record show points. Rules ID 14 separates the consumed-dash-edge and lethal-pickup fixes from older records; the save format is unchanged.

Each kill earns 10 XP. Levels 2–4 permanently improve the current run’s shot damage (24 → 28 → 32 → 36). The shared progression curve and capped upgrade bank own advancement; restart resets the build.

Health drops attract within 130 pixels when unobstructed; cover blocks attraction. Full-health players leave drops available for later instead of consuming them.

Spawns select the farthest eligible perimeter location at least 260 pixels from the player and clear of live enemies. Unsafe locations defer admission before spending wave credits. The read-only `EncounterDirector::preview` supplies the HUD's **Entry window** countdown and blocked-admission explanations. Static **Entry** markers show eligible perimeter zones during its last 0.6 seconds. These are possible zones, not reserved spawns: movement, occupancy and pressure can change admission. Showing zones avoids flickering between equal-distance selector ties. Preview queries copy the existing selector and never advance its tie-break cursor, spend credits or reserve a location. The existing first-wave delay, pressure recovery and final securing interval are preserved; no second wave scheduler was added.

Two concentrated hits stagger armored brutes for 0.8 seconds, canceling their attack and stopping pursuit. A cyan ring signals the opening. Hits cannot extend an active stagger indefinitely.

A 20-point shield absorbs confirmed damage before health. Four seconds without a hit starts 8 points/second of recovery, rewarding a successful escape. Shield hits still break score chains and preserve ordinary invulnerability timing.

The pulse weapon fires twelve-shot energy cells, then automatically reloads for 0.65 seconds. The HUD shows cell count and reload countdown. Energy is unlimited; timing shots and using cover during recharge create the combat rhythm.

Dash taps made up to 150 ms before readiness are buffered and execute once when the charge returns. Holding a dash input does not queue repeated activations.

The targeted Rust suite covers lifecycle timing, quick fire/dash taps, catch-up, pause buffer clearing, retry, wave breaks, accepted/rejected feedback, shield-plus-heal feedback, lethal pickup rejection, cover routing, deterministic autoplay victories, live independent presentation flags, effect clearing without simulation ticks, bounded particle saturation, audio admission during menus, remapped hints, and nonmutating spawn/dash previews. It also compares complete accepted-event streams and combat state through autoplay with live preference changes. Portrait regressions check letterbox separation, unchanged camera projection, DPR 1/2/3 coordinate math, real shared-UI touch activation and Controls blocking, touch channels/capture release, and finite small-window rendering within the existing UI storage budget. These are native headless checks; fresh Wasm, browser input/focus behavior, native graphics, physical audio playback, and visual layout require the parent's integration playtests. Existing native/Wasm entry points, record rules ID 14, save format, autoplay and screenshot flags are unchanged.
