## Concrete behavior and compatibility

`Policy` has validated private immutable configuration and no RNG, cursor, seed, clock or persistent selection state. Source-index ties always choose the lowest authored index. Repeated queries and reconstruction from identical configuration reproduce results without reset state. Seeds remain replay metadata, not spawn decisions.

Only existing authored Vec3 spawn positions are candidates, at the existing arena caps (16 spawns, 256 solids). Empty or entirely unsafe input returns `Ok(None)`. There is no ID-modulo/origin fallback on the explicit policy path. Static blockage excludes a candidate; incomplete or invalid clearance returns the actual typed `ClearanceError`, including QueryBudget even when a blocker was observed before exhaustion. Every candidate is checked before any tick/join mutation, including late candidates that would not win.

Validation reuses 233's `validate_arena` with clearance disabled and empty-vector preservation; it never selects the legacy origin. Existing `Match::state_hash` reuses checkpoint validation of the complete roster, duplicate/invalid IDs, all Player fields and rewind state without allocating or modifying checkpoint code. Dead actors are ignored for scoring but their supplied state is still validated. Raw Arena/Player mutation remains possible; validation is repeated on every policy request.

The actual `character::check_clearance` checks the FPS capsule (radius .3, height 1.8), all membership layers and the concrete Arena Terrain including implicit ground. The selector does not implement another static collision detector. Full Y is preserved for clearance and LOS. Task250 is reused via a fresh `SpawnSelector::assess_into` with source-index-preserving XZ projection and nonrotating assessment. Its supplied origin distance is not substituted for 3D clearance or the multi-player metric.

Hostility/availability is deliberate: every other present, living player is a hostile distance/exposure reference, regardless of facing/team. The spawning ID, dead players and absent slots are excluded. There is no availability/team flag in the existing Player. Horizontal nearest-player distance is XZ even across floors; strictly less than the configured minimum excludes a candidate, while the exact minimum is allowed. Optional occupancy conservatively forbids overlapping **open axis-aligned player bounding volumes** on X/Y/Z; touching boundaries are allowed. This live-occupancy check is deliberately conservative, not a claim of exact inter-capsule narrowphase. Setting both minimum zero and occupancy false explicitly allows shared volumes.

Score is nearest eligible player's horizontal distance squared (zero with no references) minus visible-player count times optional exposure penalty; highest score wins. Optional LOS is an actual full Vec3 eye-to-eye segment using `Arena::raycast` plus the Terrain's implicit Y=0 ground-plane crossing. Facing, weapon range, player bodies and future player movement do not occlude this exposure metric. `None` skips LOS; `Some(0)` deliberately still performs the complete LOS assessment and has a distinct context.

Geometry/LOS preflight is allocation-free and bounded. Per-spawn clearance budget is 0..=1,000,000 (default 257); actual Arena traversal has at most ground+256 solids. LOS preflight requires `spawn_count * (living_count + spawn_count)` eye pairs, including source candidates that are blocked, the spawning ID's live pose if present, and every possible respawn-reservation pair. This conservative complete count is checked before rays; maximum is 512, each ray scans at most 256 solids. Zero/exact/short budgets have explicit behavior. All coordinate and score arithmetic is finite under validated bounds. J250's fixed 256-record scratch is reused, with no callback allocations or persistent cache.

For policy ticks, living-player references are sampled at **tick entry**. Accepted automatic respawns reserve their full positions in ascending player-ID order and become distance/occupancy/exposure references for later respawns in that tick. Only accepted respawns reserve; frozen, auto-respawn-disabled and invalid-weapon gates retain existing semantics. The shared kernel still invokes input policy/sanitization and existing weapon, movement, rewind, damage and accepted-event handling. No full combat loop is duplicated. The opt-in processing order is documented; the actual `players` Vec is not reordered. Existing trace target tie behavior remains in the shared combat code.

A due dead player with no eligible candidate stays dead at countdown zero and retries next actual tick. That deferral advances the match normally but emits no Respawned event and does not reset life generation. Accepted respawn uses the existing Player::new reset, emits exactly the existing Respawned event, and calls the existing rewind new-life boundary once. Initial joins obey ID/roster limits and slot reuse increments the retained life generation. Respawn ticks do not execute live movement/fire/reload from that command. Checked command count/IDs/duplicates are rejected before a tick; input axes/aim still use legacy sanitization, and invalid historical shot times retain existing in-kernel shot rejection.

All legacy defaults remain unchanged: `Arena::spawn`, `Match::spawn_player`, `step`, `step_with_rewind`, `step_with_rules`, `step_player_with_settings`, PracticeRules and public Arena/Player/GameEvent literals. `None` on the additive per-call API calls the exact legacy path, including roster/event order and duplicate-input first-wins behavior. Policy calls never install a sticky Match setting. No checkpoint, network v5, tactical, input wire or GameEvent changes occurred; no client-selected location was added.

## Replay design and shared helper seams

Policy replay is a separate `spawn::{Capture, World}` adapter: schema `0x4658535041574e31`, version **1**, 64 Hz. Legacy `replay::{Capture, World}` retains schema `0x4658535452494b45`, version **1**, unchanged input/checkpoint/event encodings and output bytes. Policy schema/version fixes the scoring, all-live hostility, tick-entry sampling and stable source-index semantics above. Future semantic changes require a corresponding adapter version/context change.

Policy context hashes a fixed 42-byte little-endian buffer containing its schema marker, existing `Match::context_hash`, minimum-distance f32 bits, occupancy flag, exposure-option tag/value bits, clearance budget and LOS budget. Every validated configuration field participates. Float signed-zero bit patterns remain distinguishable. Policy is immutable in Capture/World. A different configuration or arena rejects Playback::start as Incompatible **before restore or stepping**; direct restore checks context before replacing the world. Policy state is absent, so the existing checkpoint is sufficient. Capture rejects arena/context changes before appending. Existing timeline Recorder/Recording/Playback own bounded storage, checksums, checkpoints, seeking and replay verification.

Authorized replay.rs seams, all crate-private:

```text
Capture::with_header(game: &Match, header: Header, limits: Limits) -> Result<Capture, replay::Error>
DecodedInputs { commands: [(u8, InputFrame); MAX_PLAYERS], command_count: usize,
                shots: [ShotTime; MAX_PLAYERS], shot_count: usize }
decode_inputs(input: &[u8]) -> Result<DecodedInputs, replay::Error>
decode_events(expected: EventIter<'_>, tick: u32) -> Result<[Option<GameEvent>; 64], replay::Error>
compare_events(events: &[GameEvent], wanted: &[Option<GameEvent>; 64], count: usize)
    -> Result<(), replay::Error>
```

The constructor accepts a different header and reuses original Recorder/checkpoint/scratch preparation. Decode/event helpers are extracted original validation with the same bounds, finite/duplicate checks, NetworkEvent decoder, expected tick checks and trailing-byte rejection. Both Worlds call them. Capture::push and input/event encoders remain unchanged; there is no second codec. Existing lib.rs and replay.rs test-module bytes match the captured pre-edit files.

Replay adapter combat is PracticeRules, matching the existing game context. Arbitrary mutable custom CombatRules are not captured by this adapter. Use the generic policy stepping entry point for host-owned rules, and provide a separately versioned rules replay adapter if adopting other combat semantics. Capture cannot prove which host call produced a supplied Match; callers must push one actual policy step's complete commands/shot times/accepted events, as with legacy capture. Playback verifies events and resulting state. Malformed authority input/events are rejected before tick mutation; well-formed but differing accepted events report EventsDiffer **after the simulated tick**, preserving existing replay fault behavior rather than claiming rollback.
