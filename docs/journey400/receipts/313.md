## Concrete behavior and public APIs

All new methods are in `ferravex_net::delta::Delta`:

```rust
pub fn encoded_len(base: &[u8], next: &[u8]) -> Result<usize, DeltaError>;
pub fn encode_into(
    base: &[u8], next: &[u8], destination: &mut [u8],
) -> Result<usize, DeltaError>;
pub fn between_into(
    &mut self, base_tick: u32, base: &[u8], tick: u32, next: &[u8],
) -> Result<(), DeltaError>;
pub fn applied_len(&self, base_tick: u32, base: &[u8]) -> Result<usize, DeltaError>;
pub fn apply_into(
    &self, base_tick: u32, base: &[u8], destination: &mut [u8],
) -> Result<usize, DeltaError>;
```

`encoded_len` returns the exact inner payload size after equal-length and
historical snapshot-limit checks; counting and multiplication occur only after
the 1189-byte bound has been established. `encode_into` writes that inner wire
representation to a caller slice. `between_into` replaces an existing Delta's
bytes and ticks using only its already-allocated Vec capacity. It reports
insufficient capacity instead of growing storage. `applied_len` validates every
entry without allocating. `apply_into` validates completely before any copy or
write, then reconstructs the snapshot into the caller slice.

The new `ferravex_net::delta::DeltaError` derives `Clone, Copy, Debug, PartialEq,
Eq` and implements `std::fmt::Display` and `std::error::Error`. Its exact variants
and fields are:

```rust
pub enum DeltaError {
    LengthMismatch { base: usize, next: usize },
    SnapshotTooLarge { len: usize, max: usize },
    Capacity { required: usize, available: usize },
    BaseTickMismatch { expected: u32, actual: u32 },
    TruncatedHeader { len: usize },
    EncodedTooLarge { len: usize, max: usize },
    BaseLengthMismatch { expected: usize, actual: usize },
    InvalidTag { tag: u8 },
    DenseLengthMismatch { expected: usize, actual: usize },
    TruncatedEntry { body_len: usize },
    EntryOutOfRange { entry: usize, index: usize, len: usize },
    EntryOrder { entry: usize, previous: usize, index: usize },
}
```

Indices and entry ordinals are zero based; sizes are bytes. Base-tick expected
means `self.base_tick`, actual means supplied tick. Base-length expected means
the encoded length, actual means supplied baseline length. Display includes
the variant and its fields. Encode precedence is length mismatch, snapshot
limit, destination capacity. Apply precedence is tick, header, snapshot limit,
encoded limit, baseline length, tag/body shape, each entry's range then order,
finally destination capacity. Invalid content takes precedence over short output.

## Atomicity, capacity, tails and aliasing

- Every returned error from slice encoding/application preserves the entire
  destination, including for a malformed entry after earlier valid entries.
- Successful slice operations replace only the returned prefix; the rest of the
  slice is untouched. A slice's **length** is its available capacity. For a Vec
  destination used as a slice, initialize/resize it outside the hot path first.
- `between_into` uses Vec **capacity**, resizes/replaces rather than appending,
  and preserves ticks, bytes, length, allocation pointer and capacity on error.
  Success may shorten its visible length without scrubbing unused allocation
  bytes. Empty snapshots reset visible wire bytes to `[0, 0, 0]`.
- All five checked methods allocate nothing. `between_into` does not reserve.
  Input, delta byte storage and mutable destination must have disjoint valid
  Rust borrows. Overlapping/in-place apply is not supported. Unsafe aliases are
  outside the contract. Application-level mutation after successful return is
  outside rollback; allocation/panic recovery is not a new promise.

## Compatibility decisions

`Delta { base_tick, tick, bytes }` public struct literals and derives are unchanged.
Existing `between` and `apply` signatures, results and `ProtocolError::Invalid`
error mapping remain; they share the checked implementation. Their allocating
convenience behavior remains. Quantization functions are unchanged.

Wire bytes remain little-endian u16 length, tag, then dense data or sorted
u16-index/value sparse entries. Sparse is selected only if `changes * 3 < len`;
ties and zero length stay dense. Full snapshot input is still at most
`MAX_PACKET_BYTES - 11` (1189); apply still permits at most
`MAX_PACKET_BYTES - 8` inner bytes (1192). Noncanonical but valid sparse inputs
(unchanged replacement values, sparse bodies larger than dense, no entries)
remain accepted. The delta layer still accepts arbitrary tick pairs; the outer
codec retains its own newer-tick requirement. No protocol/save/replay version or
quantization policy changed, and no dependencies/features were added.

The outer v5 SnapshotDelta envelope is 24 bytes and still caps its inner payload
at `MAX_PACKET_BYTES - 24` (1176). A successful inner plan/construction does not
guarantee outer encoding succeeds. Sender policy must retain its normal size
comparison and full-snapshot fallback.
