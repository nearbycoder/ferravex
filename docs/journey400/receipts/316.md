## Behavior and compatibility

`push_checked` and `push_timed_checked` return `Ok(())` for admission or one
`InputAdmissionError`. Exact first-failure precedence is preserved:

1. Invalid embedded `InputFrame`.
2. Queue full, even if the candidate is duplicate/older/half-range ambiguous.
3. Sequence equals the newest accepted watermark: `DuplicateNewest`.
4. All other non-newer sequences: `OutOfOrder`, including older repeated inputs
   (even if pending/consumed) and the exactly-half-range ambiguous sequence.

Rejected input changes exactly one rejection counter and never pending controls
or the accepted watermark. Admission still appends without eviction and retains
`MAX_QUEUED_INPUTS == 64`. Original bool `push` / `push_timed` signatures remain;
they delegate exactly once to checked admission. Numeric validity, wrap-safe
ordering, default lazy storage, public frame/timed-input struct literals, and
existing exhaustive enums remain unchanged. Only new types and private queue
state were added.

No `shot_tick` validation was added: the current wire protocol and queue accept
`None` and all `Some(u32)` values, including ticks without `BUTTON_FIRE`. Authority
rewind/tick policy remains outside this queue. No wire code or protocol version
was edited; an exact existing v5 timed-input byte fixture is asserted.

Metrics saturate independently at `u64::MAX`. They report queue-local activity,
not packet receipt, remote delivery, simulation ticks, or accepted game actions.
The actual removal scopes are distinct:

- `returned_inputs`: one per nonempty pop, including one coalesced result. Caller
  removal does not establish simulation consumption.
- `coalesced_inputs`: older entries folded into a newest returned sample. Action
  bits and recovered fire aim/time may survive; these are not admission rejects.
- `discarded_inputs`: entries explicitly cleared by `clear_pending` or
  `reset_session`, without being returned. There is no artificial eviction policy.

Coalescing keeps newest sequence/movement, ORs all action bits, and preserves the
existing aim/time selection: newest fire wins when present; otherwise the first
(oldest) queued fire supplies yaw, pitch, and `shot_tick`. Empty removals do not
increment counters.

Reset scopes:

- `reset_metrics`: returns the old metrics and zeroes counters only. Pending
  controls, allocated storage, and watermark remain. A later removal can therefore
  count an input admitted before that reporting window.
- `clear_pending`: adds actual removed count to discarded, retains storage,
  watermark, and other metrics. Repeated/empty clears add zero.
- `reset_session`: calls pending clear and forgets the watermark, while retaining
  allocated storage and all metrics. Host must establish the new authenticated
  session first. Caller may then separately reset metrics. This operation is not
  a round reset or a menu/focus operation.

No wall time, render coupling, or network/replay suspension was introduced.
