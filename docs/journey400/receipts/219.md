## Exact public API

All declarations are in `ferravex_math::curves`:

```rust
pub const MAX_TESSELLATION_DEPTH: u8 = 32;

pub struct CubicBezier3 { /* private control_points: [Vec3; 4] */ }
impl CubicBezier3 {
    pub fn new(control_points: [Vec3; 4]) -> Result<Self, CurveError>;
    pub fn control_points(&self) -> [Vec3; 4];
    pub fn position(&self, parameter: f64) -> Result<Vec3, CurveError>;
    pub fn tangent(&self, parameter: f64) -> Result<[f64; 3], CurveError>;
    pub fn tessellate_into(&self, output: &mut [Vec3],
        options: TessellationOptions) -> Result<Tessellation, CurveError>;
}

pub struct TessellationOptions {
    pub tolerance: f64,
    pub max_depth: u8,
    pub max_work: usize,
}

pub struct Tessellation {
    pub written: usize,
    pub work: usize,
    pub subdivisions: usize,
    pub depth_reached: u8,
    pub covered_until: f64,
    pub max_error_bound: f64,
    pub status: TessellationStatus,
}

#[non_exhaustive]
pub enum CurveError {
    NonFiniteControl, InvalidParameter, InvalidTolerance, InvalidDepth,
}

#[non_exhaustive]
pub enum TessellationStatus {
    Complete, OutputFull, WorkLimit, SubdivisionLimit,
}
```

The three structs derive `Clone, Copy, Debug, PartialEq`. Both enums additionally derive `Eq`; `CurveError` implements `Display` and `std::error::Error`. Options are explicit, without an implicit default budget/tolerance.

## Concrete behavior and numeric policy

- Constructor checks every coordinate of every control, including unused-looking controls on a degenerate curve. NaN/infinity are errors. Private controls preserve that invariant; edit the returned array and construct a new curve to change them.
- Samples reject nonfinite/out-of-range parameters rather than clamping/extrapolating. Negative zero is valid. Position uses f64 de Casteljau arithmetic and then rounds to existing Vec3; both endpoints preserve the original f32 bits, including signed zero. Sampling is ordinary floating-point evaluation, not an exact polynomial oracle.
- Tangent is the unnormalized derivative of the authored polynomial **before** f32 position rounding, expressed in f64 components. Opposite extreme f32 controls therefore cannot overflow it. Constant curves and exactly computed stationary cusps return zero; small nonzero derivatives are retained. There is no normalized tangent, epsilon cutoff, cusp branch selection or arbitrary fallback direction.
- A valid tessellation emits the start if capacity permits, then tests/splits nodes left-first in increasing parameter order. Only certified endpoints are appended. A completed constant curve emits two equal positions, retaining both endpoint parameters. Repeated vertices are legal for existing Route3.
- Validation of tolerance (finite, strictly positive) and depth (`0..=32`) occurs before any output write, even for an empty buffer. Invalid requests return `Err` with the entire buffer unchanged. Zero work/depth are valid budgets, not errors.
- Empty storage returns `Ok(OutputFull)` with zero writes/work. One slot holds only the start. No work is spent examining a node if another endpoint cannot fit. The unchanged suffix must not be consumed on a later run.
- `work <= max_work`: one unit is one examined node, including its error test and at most one split. Fixed validation and fixed stack initialization are constant overhead outside that counter. `subdivisions <= work`, `depth_reached <= max_depth`, `written <= output.len()`. DFS stack is exactly 33 nodes, with bounded per-node arrays; no recursion or heap-backed storage. Dyadic parameters remain exactly representable at this depth. Counters do not add past their permitted maxima.
- `Complete` alone certifies the entire curve and both endpoints. `OutputFull`, `WorkLimit` and `SubdivisionLimit` return the already accepted prefix, **never** a forced final chord. `covered_until` is its final original curve parameter. `max_error_bound` applies only to emitted chords, and is zero when none were emitted. It never certifies the unprocessed remainder. Capacity takes precedence over work when both prevent the next node; depth is tested after a failed error test, so a flat root can complete with depth zero.
- Calls retain no state. Reusing storage restarts at parameter zero and overwrites only the new prefix. Failed/partial/constant runs cannot contaminate a later successful run. No append/resume/reset API or hidden progress state is needed.

### Error bound and rounding

Each node's exact mathematical subcurve controls are enclosed by outward-rounded f64 intervals, starting from exactly promoted f32 inputs and propagated through dyadic de Casteljau subdivision. Each arithmetic operation is enclosed separately, including around zero/subnormals. Identical intervals can be averaged without widening; identical exact controls/chord points have exact zero difference.

For the **actual rounded f32 chord** A–B, the degree-elevated line controls are A, `(2*A+B)/3`, `(A+2*B)/3`, B. Their thirds are enclosed using division with outward rounding, not a presumed exact `1/3`. For each control index, outward subtraction/absolute bounds and outward L1 summation bound its difference from the subcurve control. The maximum of these four bounds encloses the norm of their convex Bernstein combination. Euclidean norm is no larger than L1 norm. Thus every subcurve point is within that bound of its parameter-paired chord point, and vice versa, including rounded endpoints. Accepted leaf bounds are no greater than tolerance; their maximum is returned.

This deliberately conservative test may subdivide a collinear curve whose parameter speed is nonuniform, as well as curves with actual geometric curvature. It catches collinear overshoot/backtracking and S-curves whose midpoint lies on the endpoint chord. Tighter tolerance can saturate at the depth/work/output limit or the interval/Vec3 precision floor; saturation is never silently presented as a whole-curve tolerance success. No arc-length error, progress-parameter error, automatic road generation, arc-length inversion, collision guarantee or cross-platform bitwise determinism is claimed.

```rust,check crate-type=bin
use ferravex_math::{Vec3, vec3};
use ferravex_math::curves::{CubicBezier3, TessellationOptions, TessellationStatus};
use ferravex_play::navigation::Route3;

fn main() {
    let curve = CubicBezier3::new([
        Vec3::ZERO, vec3(0., 2., 0.), vec3(4., 2., 0.), vec3(4., 0., 0.),
    ]).unwrap();
    let mut points = [Vec3::ZERO; 128];
    let result = curve.tessellate_into(&mut points, TessellationOptions {
        tolerance: 0.01, max_depth: 16, max_work: 1023,
    }).unwrap();
    assert_eq!(result.status, TessellationStatus::Complete);
    assert_eq!(result.covered_until, 1.);
    assert!(result.max_error_bound <= 0.01);

    let mut route = Route3::new(points.len()).unwrap();
    route.set(&points[..result.written]).unwrap();
    assert!(!route.is_closed());
    assert_eq!(route.points().len(), result.written);
    assert_eq!(route.sample(0.).unwrap().unwrap().position, Vec3::ZERO);
    let halfway = route.sample_progress(0.5).unwrap().unwrap();
    assert!(!halfway.complete);
    assert!((halfway.position.x - 2.).abs() <= 0.01);
    let end = route.sample(route.length()).unwrap().unwrap();
    assert!(end.complete);
    assert_eq!(end.position, curve.position(1.).unwrap());
}
```
