## Concrete behavior and compatibility

- `FixedClock::advance_batch` and `GameSession::advance_batch` snapshot the counter
  before delegating to the existing `advance`. All sanitization, one-hour elapsed
  cap, catch-up limits, discarded time and fractional remainder behavior remain
  on the original code path. `FrameStep` and its dt-only `ticks()` are unchanged.
- `TickBatch::frame()` returns the original `FrameStep` by value. `ticks()` yields
  `TickContext { tick, batch_index, dt }`, in forward scheduled order by default.
  `batch_index` is zero-based and remains the original index when iterating in
  reverse or skipping. Empty batches yield nothing.
- IDs start at 1 after construction/reset/restart. The ID formula is
  `tick_before.wrapping_add(u64::from(batch_index) + 1)`. It wraps from `u64::MAX`
  through 0; IDs are local scheduled counters, not globally unique identities or
  an ordering guarantee across wrap/reset. Discarded catch-up time takes no IDs.
- Scheduling consumes the entire budget before execution. Early stop/error,
  skipping, abandoning or copying a batch does not reclaim IDs or execute work.
  An iterator yield does not prove execution. A retained batch stays a snapshot
  after subsequent advances or resets; callers must discard pending batches on
  simulation reset because IDs are reused. Reiteration repeats the same IDs.
- `step_paused_batch` delegates to `step_paused`: exactly one scheduled ID, index
  zero, normal fixed delta, alpha 1, no elapsed time/drop, exact fraction retained.
  Every non-Paused state returns the existing `SessionStepError` without mutation.
  Manual and normal calls, including old APIs, share the same counter. This
  method schedules work and does not invoke App hooks.
- `App` now iterates the contextual batch and invokes
  `Game::fixed_update_context`. The default invokes the old required
  `fixed_update(context.dt)` exactly once. Overrides own dispatch and may call
  the old hook themselves; the runner never invokes both hooks independently.
  All original legacy-Game lifecycle tests pass unchanged.
- Existing `AppFrameReport` remains the execution accounting API: scheduled work
  includes skipped tails; executed work counts only invoked hooks, including one
  returning Stop/Err. Error classification remains `AppHook::FixedUpdate`, cleanup
  ordering and exactly-once shutdown are unchanged, and no new report type or
  cumulative execution counter was added. Manual scheduling before App ownership
  affects later IDs without inflating App execution reports.
- Storage is fixed-size, with no heap collection or platform I/O. The private
  iterator uses a range and computes contexts on demand; `nth`/`nth_back` use
  constant-time range skipping. Regression tests cover a synthetic full `u32::MAX`
  budget, extreme skip indices and wrap without enumerating billions of items.

```rust
// ferravex_core root; all fields below are public.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct TickContext {
    pub tick: u64,
    pub batch_index: u32,
    pub dt: f32,
}

// ferravex_core root; fields private, no public manual constructor.
#[derive(Debug, Clone, Copy)]
pub struct TickBatch { /* frame and prior scheduled count */ }

impl TickBatch {
    pub fn frame(self) -> FrameStep;
    pub fn ticks(self)
        -> impl ExactSizeIterator<Item = TickContext>
            + DoubleEndedIterator + std::iter::FusedIterator;
}

impl FixedClock {
    pub fn advance_batch(&mut self, frame_seconds: f64) -> TickBatch;
}

// ferravex_core::session
impl GameSession {
    pub fn advance_batch(&mut self, elapsed_seconds: f64) -> TickBatch;
    pub fn step_paused_batch(&mut self) -> Result<TickBatch, SessionStepError>;
}

// ferravex_engine::app
pub use ferravex_core::TickContext;

pub trait Game {
    // Existing associated type/hooks retained, including required fixed_update.
    fn fixed_update_context(&mut self, context: TickContext)
        -> Result<AppControl, Self::Error>
    {
        self.fixed_update(context.dt)
    }
}
```

## Registration and consumer handoff

**Required root/module/manifest registration: none.** Core root defines the types,
the already registered `core::session` module exposes the session methods, and the
already registered `engine::app` module consumes the batch in `App::run_frame`.
`engine::app::TickContext` lets an engine-only consumer override the hook without
adding a direct dependency. The new hook's runnable rustdoc recipe uses only
`ferravex_engine` imports, runs a real App and asserts simulation motion and IDs.

Parent-owned facade convenience, if desired:

- `crates/ferravex/src/lib.rs`: add `TickBatch, TickContext` to the existing
  `pub use ferravex_core::{...};` declaration.
- `crates/ferravex/src/prelude.rs`: optionally add those two names to the existing
  `pub use crate::{...};` declaration after the root reexport.

Those additions are not needed for qualified paths: source inspection shows the
existing facade already exposes `ferravex::core::{TickBatch, TickContext}` and
`ferravex::app::TickContext`. Facade compilation itself is deferred to parent.

For a custom host, replace `let frame = session.advance(elapsed)` with
`let batch = session.advance_batch(elapsed); let frame = batch.frame();`, then
execute `for context in batch.ticks()` using `context.dt` and `context.tick`.
Keep the existing authoritative-phase guard before invoking each update, consume
input edges inside actual updates and derive feedback only from accepted game
events. Maintain a separate executed counter if needed; never substitute the
scheduled ID. Render from `frame.alpha`. Inspectors use `step_paused_batch` and
execute that returned context themselves.

Runnable first-party recipes are present in rustdoc for
`FixedClock::advance_batch`, `TickBatch::{frame,ticks}`,
`GameSession::{advance_batch,step_paused_batch}` and
`Game::fixed_update_context`. `App` is an actual production consumer, not an
unregistered example. Parent owns any game/example adoption and updating the
agent guide's explanation of reading batch-end clock ticks.
