## Behavior, bytes, validation and capacity

Every existing client/server family is supported, including all extension tags:
Hello 1, Input 2, Welcome 3, Snapshot 4, ReliableEvent 5, EventAck 6, timed Inputs 7,
SnapshotAck 8, Ping 9, tactical Command 10, SnapshotDelta 11, Pong 12, CommandAck 13.

One private codec walker validates and counts with no destination, then the same
walker writes the same immutable packet to the preflighted slice. There is no
parallel length formula/encoder, temporary packet Vec, 1200-byte stack scratch,
unsafe codec, in-place aliasing, I/O, clock, retained state, or application action.
The borrowed bridge and owned enum paths share the actual event writer; no
EventPacket/payload clone is needed in a send_due callback.

- Exact initialized output is the returned prefix. Tail bytes remain untouched,
  including old payload data after buffer reuse. Always send only `[..n]`.
- All field/length validation and the 1200-byte protocol bound complete before
  capacity validation and any destination write. Every returned error preserves
  the entire destination, including late invalid players/epochs. Capacity uses
  slice length, never the backing Vec's spare capacity. Zero/short/exact/oversized
  destination slices are supported with explicit `required`/`available` bytes.
- Validation/counting APIs allocate nothing. Slice encoding makes two bounded
  passes, including validation twice, on ordinary immutable fields; there is no
  user callback/interior mutable packet state between passes. Legacy allocating
  wrappers use the same preflight and writer and allocate their output Vec only
  after validation. Returned Vec capacity was not a protocol contract and is
  now exact requested length subject to normal Vec behavior.
- All v5 bytes, little-endian fields, float bits (including negative zero and
  subnormal values), masks, numeric limits, sequence/nonce acceptance, optional
  tick representation, player order, epoch membership and session conditions
  are preserved. Empty input lists remain invalid; an empty player list with
  zero epochs remains valid. `ack_valid == false` does not force ack_sequence
  zero. shot_tick remains arbitrary, including Some(MAX) without fire.
- ReliableEvent accepts 0..=900 payload bytes; Command accepts 1..=900. Sequence
  MAX remains encodable as before; admission/exhaustion policy belongs to the
  reliable layer. Hello nonce zero remains accepted; every session cookie is
  still nonzero. No ACK is generated automatically by any encoder.
- SnapshotDelta validates only outer session, wrap-safe strictly newer tick and
  3..=1176 inner byte length. It does not call Delta::applied_len, canonicalize,
  authenticate, reconstruct or inspect inner tags. Legacy noncanonical sparse
  bodies and even malformed inner bytes remain outer-encodable/decodable.
  Actual apply/install/ACK validation remains in task 313/229/authority layers.
- Current legal field limits already bound all families to <=1200. A delta of
  1176 bytes reaches exactly 1200. Whole-packet TooLarge is a separate final
  guard; an invalid field length still wins and maps to historical Invalid.
- No codec reset is necessary. Reusing one buffer across failures, shorter
  packets and externally established new sessions is tested. Reliable/queue/
  baseline state still needs the existing driver session-epoch policy; round
  resets and local menus must not reset transport cursors or stop progression.

Exact new error precedence (first failure wins):

1. Session validity, except sessionless Hello.
2. Collection length before any element; inputs and players in slice order.
3. Input fields: move_x, move_z, yaw, pitch, buttons. Player fields: id,
   position x/y/z, velocity x/y/z, yaw, pitch, jump_coyote, jump_buffer, health,
   ammo, fire_cooldown, reload_ticks, respawn_ticks. A player's validity precedes
   that player's duplicate-id check; an earlier duplicate beats later players.
4. Snapshot orphan epochs in ascending slot order, after every player.
5. Extension-specific fields in their existing logical/wire order: Ping client
   clock bound; Command payload length; delta tick ordering then byte length;
   Pong client/receive/send timestamp bounds, then send>=receive, then <=5s span.
6. Whole packet limit; finally caller destination capacity.

Diagnostic field names are `session`, `player_id`, `inputs`, `inputs.move_x`,
`inputs.move_z`, `inputs.yaw`, `inputs.pitch`, `inputs.buttons`, `players`,
`players.id`, `players.position.{x,y,z}`, `players.velocity.{x,y,z}`,
`players.yaw`, `players.pitch`, `players.jump_coyote`, `players.jump_buffer`,
`players.health`, `players.ammo`, `players.fire_cooldown`, `players.reload_ticks`,
`players.respawn_ticks`, `players.duplicate_id`, `epochs.orphan`, `event.payload`,
`delta.tick`, `delta.bytes`, `client_us`, `receive_us`, `send_us`,
`pong.send_order`, `pong.processing_us`. Indices are zero-based input/player/
epoch indices, not offsets or player IDs; other fields use None. Length min/max
are inclusive. Legacy wrappers map InvalidField/Length to ProtocolError::Invalid;
whole-packet TooLarge to ProtocolError::TooLarge. Their allocated destination
always fits, so Capacity cannot occur there; its private fallback maps TooLarge.
No existing ProtocolError variant was added or repurposed on actual old paths.

## Runnable recipe and FPS/native/Wasm handoff

The BorrowedEvent rustdoc is an executed first-party supplied-time recipe using
real EventSender::send_due, borrowed encode_into, decoder, EventReceiver::admit,
wire EventAck encoding/decoding, individual sender ACKs and drain_ready. It
refuses a send, accepts/loses the head, receives/ACKs the successor, checks the
100ms retry threshold, then retains/ACKs the retried head and drains later when
capacity opens without another incoming packet. The additional integration test
runs the whole flow for **both ReliableEvent and Command**, including actual
CommandAck codec, simulated WouldBlock/short-send refusal, full receiver
admission without ACK, unknown ACK, retry and ordered delivery of three payloads.
These are pure supplied-input recipes; no new transport/game action is added.

   allocating `peer.events.due`/owned ReliableEvent construction with send_due
   and `BorrowedEvent::ReliableEvent { session: peer.session, event }` inside its
   callback. Encode into a reusable initialized `[u8; MAX_PACKET_BYTES]` or an
