## Concrete behavior and compatibility

- Borrowed, constant-storage line iteration returns source byte ranges, visible
  borrowed prefixes, an optional static ASCII suffix and each line's advance.
  UTF-8 is sliced only at scalar boundaries. Every scalar still occupies one
  bitmap cell; ASCII uppercase and `?` substitution remain in the existing UI
  painter. No shaping, alternate font engine or new dependency was introduced.
- Measurement reports all wrapped lines, retained lines, hidden whole lines,
  full required height, retained height and maximum retained advance. Heights
  are **line slots** (`line_count * size`), including the last spacing row, not
  tight ink bounds. `is_truncated` reports omitted lines.
- `Unlimited` preserves normal wrapping. `Clip(n)` omits excess lines without a
  marker; `Ellipsis(n)` replaces the last retained line's tail with `...` only
  when another wrapped line exists. One/two-cell widths use one/two dots; below
  one cell no marker/prefix fits. A zero limit retains nothing. An exact fit or
  terminal LF alone does not spuriously add an ellipsis.
- Rectangle/scissor clipping remains independent of the maximum-line policy,
  including legacy partial-last-line painting. Counts describe the policy
  **before** geometric clipping, as documented. Use a measured-height rectangle
  for complete copy, or `floor(available_height / size)` as the explicit line
  limit for complete line slots in a fixed card. Hidden counts do not claim to
  measure occlusion, clipped pixels or an ellipsized prefix's character count.
- Existing `Ui::text`, `Ui::text_fmt`, `TextStyle` struct literals, public enums,
  labels and buttons retain their behavior. In particular non-wrapped text still
  shrinks according to its longest supplied line; wrapped text keeps its size.
- Existing wrapping's whitespace behavior is preserved, including internal
  blank LF lines, no extra line after a terminal LF, and CR/tab cells when not
  skipped at a word-wrap boundary. Unicode whitespace can be a break boundary;
  only ASCII space/tab/CR are skipped after it. The immediate font API still has
  its different CRLF/trailing-line and blank-unsupported-glyph conventions.
  `font.rs` was not changed. Checked `BitmapFontMetrics` supplies the new public
  layout's pixel size, advance and line height using the same operation order.
- Width must be finite/nonnegative, size finite in `1..=256`; invalid geometry
  returns the existing `UiError::InvalidLayout`. Below-cell/zero widths retain
  legacy one-scalar hard wrapping; painting clips instead of shrinking.
- Pure layout has no source-length/storage cap and never retains allocations.
  Measurement scans hidden lines too: work is linear in source length, not
  bounded by `n`. Iterators are cloneable/fused and restart through `lines()`;
  changing widths/source uses a new borrowed value, with no stale retained cache.
- New queuing copies the complete source into the existing 32 KiB arena, even
  with a small/zero limit. It checks this bound **before** measuring and reserves
  vertices only for retained glyphs/suffixes, with the shadow multiplier. The
  existing 1024-command/196608-vertex bounds remain; invalid input or capacity
  exhaustion rejects atomically. `Ui::begin` clears all command/text/limit state
  while preserving allocated storage. Empty/zero-line blocks use one command.
- Simulation, wire/save/replay formats, platform exports, dependencies and
  authored game defaults are untouched.

`Ui::wrapped_text` always wraps at `style.size` (ignores `style.wrap`) and honors
the supplied color/alignment/shadow. `Ui` does not retain borrowed text; the
existing arena owns the queued source. The standalone layout borrows its source.

## Consumer handoff / runnable recipe

The module-level rustdoc executes the actual public measured-layout and UI
queuing/painting path for a multiparagraph briefing at a 320-unit viewport:
288 units of content after two 16-unit margins, size 18, measured body rectangle,
and a next-block position derived from its height. This passed as a Rust doctest.
The focused public regression checks the concrete seven-line/126-unit result.

- Crystal parent: `examples/crystal-cavern/src/lib.rs::wrapped_text` currently
  receives a guessed height and uses size 18, 16-unit margins, centered shadowed
  copy. Measure `WrappedText::new(text, (screen_width() - 32.).max(1.), 18.)`
  first, size the surrounding card/next block from `measure().height`, and retain
  the existing style. `Ui::text` with `wrap: true` already shares the algorithm;
  use `Ui::wrapped_text` when explicitly choosing a maximum-line/ellipsis policy.
  Parent should choose scrolling/expansion versus hiding essential instructions.
- Marble parent: measure course-description content at the card's padded width
  before assigning card height or the next row; keep authored title/button sizes
  and course selection behavior. No changes to active Marble ownership were made.
- J400 277: use the same `WrappedText` report for variable-height card copy;
  include caller-owned padding/gaps separately. No dependency on task 272 flow
  was introduced, and flow responsibilities were not duplicated.
