## Behavior and compatibility

- Bundles accept `()` and tuples of one through eight owned `'static` components.
  Spawn, fallible spawn and insert all use the same implementations. Five through
  eight are additive; old tuple behavior and empty bundles remain supported.
- Fetched queries accept a single Access or a tuple of one through eight Access
  types. Each Entity entry counts toward eight. Required, optional shared/mutable,
  and repeated shared/identity entries compose through the existing Query
  machinery. Empty fetched query tuples remain unsupported, as before.
- Bundle duplicate validation runs before slot/free-list/len mutation or component
  writes. Insert still validates entity identity before bundle types. Errors keep
  the existing DuplicateComponent name and first-repeat-in-tuple-order precedence.
- A private sealed-supertrait method returns exactly eight optional metadata
  entries on the stack. The tuple macro fills the active prefix with TypeId and
  type name; empty bundles return all None. `validate_bundle` scans this array
  without constructing or invoking the old Vec-based metadata path.
- The existing hidden but public `Bundle::component_types` signature is retained.
  It still appends ordered metadata to the caller's Vec, preserving its prefix;
  tuple implementations now derive that data from the same inline metadata.
  Direct use of this compatibility method can allocate in the caller's Vec.
- Query alias validation continues to use its fixed array, now up to eight
  entries, and rejects mutable overlap before iteration or get_many handle checks.
  Optionality and absent components never relax signature alias checks.
- Existing tuple fetch uses fallible left-to-right construction. Late borrow
  failures release already acquired guards. Iteration still checks all required
  matches and filters before borrowing and can continue after a failed row.
  get_many retains completed-row and partial-row cleanup and caller order.
- Task 211's separate filter group ceiling remains zero through four clauses
  with static nesting. Its compile-fail example and all filter implementation
  registrations are unchanged. Presence predicates continue to avoid borrowing
  marker values, even with a wide fetched query and a live mutable marker guard.
- Public method/trait signatures, Error variants, Entity representation and
  generations, defaults, world-local handles, borrowing lifetimes and wire/save/
  replay/export formats are unchanged. No simulation clock, I/O or renderer is added.
