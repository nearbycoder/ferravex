## Behavior and compatibility

`ScrollState` contains only three f32 values and is allocation-free, Copy and
Default. It stores finite nonnegative viewport/content heights and a clamped
offset. Positive scroll deltas move down. Resize preserves/clamps the offset;
zero viewport height suspends at zero. Finite overflowing delta sums saturate
at the boundary using f64 intermediates. Invalid values/intervals/geometry
return the existing `UiError::InvalidLayout` without changing state.

`ensure_visible(top, height)` minimally reveals an interval, top-aligns an
oversized one, and does nothing for empty intervals/viewports. The entire
interval must fit inside declared content. `translate_rect` retains the full
rectangle, so text layout is stable while the viewport clips it. `content_point`
uses half-open bounds and rejects trailing empty viewport space. All coordinates
are logical UI units before viewport scaling, positive Y down. Safe areas are
applied once through the viewport, or through absolute HUD rectangles with a
zero-inset responsive viewport. DPR is not applied here.

`ScrollRegion` reuses the existing `UiState` for focus, disabled occlusion and
same-ID press/release capture. Its bounded content registry retains offscreen
items in content coordinates. This is needed because the existing `Ui::finish`
intentionally excludes fully clipped widgets and owns private input state.
No shared UI behavior was changed. The region owns its own focus, preserving
other `Ui` instances' focus. Paint uses the existing `Ui::hud_button` and clips;
there is no replacement renderer or new paint backend.

Keep a dedicated paint-only `Ui` for the region and do not call its `finish`
methods. Call `region.update` with all items, then paint using the returned offset
and `region.activated`. Only the active menu/region should receive enabled input.
Nested/overlapping scroll routing, additional enclosing clips narrower than the
region, cross-region Tab order and automatic transfer of another Ui's focus are
not supported. Do not concurrently route the same keys/pointers to another
enabled interactive menu. Other UI instances keep their existing focus/state.

Runtime behavior:

- Ordered host mouse/touch events, a single gesture owner, six-logical-unit drag
  threshold, no inertia. Crossing the threshold cancels a child click even at
  an exhausted extent. Mouse motion continues while held and outside the region.
  End-only movement samples are handled; secondary touches cannot steal capture.
- Wheel moves 40 logical units per host notch (positive host notch scrolls up).
  The existing journal has no wheel-time absolute pointer sample, so wheel
  eligibility uses the host's final absolute pointer position for that frame.
  Button edges have journaled absolute positions; held mouse drag combines
  relative motion with the final absolute sample. No host changes are required.
- Tab/arrows and selected-pad D-pad traverse all enabled, nonempty registered
  items, wrap in submission order, and reveal the focused item before painting.
  Page Up/Down, Home/End retain focus. Enter/pad A confirm existing focus; there
  is no auto-created focus. Confirming fully clipped focus first reveals it
  without activating; another edge is needed. Partially visible items can act
  within their visible part, matching existing Ui semantics.
- `focus_next`, `page`, `scroll_by`, and `activate_focused` accept explicit caller
  actions for remapping. Set the player-selected gamepad via `set_gamepad`.
  Global menu actions may be consumed once per presentation frame; gameplay
  tick-edge consumption remains the consumer's existing responsibility.
- Resize, changed item geometry/order/availability, focus epoch changes, host
  blur, disabled input, settings editor, overflow, Escape and touch cancellation
  discard gestures. Eligible focus IDs are preserved. Resize clamps without
  activating either the previously pressed row or another row beneath it.
- One update consumes a host frame's journal once. Duplicate updates clear the
  activation result without replaying input. Invalid update packets cancel
  capture/activation and inhibit acceptance but preserve prior layout/focus/
  offset; same-frame repair does not replay that failed packet.
- Item count is capped at 1024, configurable down to zero. Two vectors are
  reserved at construction (the registry and existing UiState); no growth occurs
  during update/navigation/reset. Duplicate checks are bounded quadratic work,
  consistent with existing UiState admission; this is not an unbounded list or
  virtualization system. Ui paint retains its own existing command/text/vertex
  and clip budgets. Button queue failure always restores a successfully pushed
  clip; earlier queued paint commands remain. Focus paint uses style.focus as
  fill and the original fill as ink, without shrinking font size.
- Reset returns offset to zero and clears region focus/registry/capture while
  retaining capacity and the same-frame guard. Cancel preserves offset/focus.
  This does not alter a session, wall clock, replay, network or game simulation.

Existing public structs/enums/default behavior, save/replay/wire formats,
native/Wasm exports and feature gates are unchanged. No dependencies changed.

## Runnable first-party recipe

This complete headless binary combines registered HUD layout, measured text,
offscreen focus reveal, clipping and public synthetic touch input. It exercises
CPU paint generation, not a window/GPU, browser or physical touch device.

```rust,check crate-type=bin
use ferravex_play::ui::{HudEdge, HudRegions};
use ferravex_render::{
    input::{host_frame, touch, touch_event},
    ui::{ButtonStyle, TextStyle, Ui, UiError, UiRect, Viewport},
    ui::scroll::{ScrollItem, ScrollRegion},
    ui::text_layout::{LineLimit, WrappedText},
    vec2,
};

fn main() -> Result<(), UiError> {
    let mut hud = HudRegions::new([320., 240.], [12., 20., 12., 12.], [0.; 2]).unwrap();
    let bounds = hud.reserve("course information", HudEdge::Top, 100.).unwrap();
    let viewport = Viewport::responsive([320., 240.], [0.; 4])?;
    let copy = "Follow the marked route through the course.\n\n\
                Review checkpoint times and the recovery controls before starting.\n\n\
                This optional information surface keeps the authored text size.";
    let style = TextStyle { size: 18., ..Default::default() };
    let height = WrappedText::new(copy, bounds.size[0], style.size)?.measure().height;
    let body = UiRect { min: [0.; 2], size: [bounds.size[0], height] };
    let items = [101, 205].map(|id| ScrollItem {
        id,
        rect: UiRect {
            min: [0., height + 12. + if id == 101 { 0. } else { 52. }],
            size: [bounds.size[0], 44.],
        },
        enabled: true,
    });
    let extent = height + 108.;
    let mut region = ScrollRegion::new(2);
    let mut paint = Ui::new();
    host_frame(0., 320, 240, || -> Result<(), UiError> {
        region.update(viewport, bounds, extent, &items, true)?;
        assert_eq!(region.focus_next(true), Some(205));
        assert!(region.scroll().offset() > 0.);
        paint.begin(viewport);
        paint.push_clip(bounds)?;
        paint.wrapped_text(region.scroll().translate_rect(bounds, body)?,
            copy, style, LineLimit::Unlimited)?;
        paint.pop_clip();
        region.button(&mut paint, 101, "COURSE", ButtonStyle::default())?;
        region.button(&mut paint, 205, "CONTROLS", ButtonStyle::default())?;
        paint.paint();
        Ok(())
    })?;
    let displayed = region.rect(205).unwrap();
    let point = vec2(displayed.min[0] + 20., displayed.min[1] + 20.);
    for phase in [touch::Phase::Start, touch::Phase::End] {
        touch_event(touch::Event { id: 9, position: point, phase });
    }
    host_frame(0., 320, 240, || -> Result<(), UiError> {
        region.update(viewport, bounds, extent, &items, true)?;
        assert!(region.activated(205));
        assert!(!region.activated(101));
        region.reset();
        assert_eq!(region.focused(), None);
        assert_eq!(region.scroll().offset(), 0.);
        Ok(())
    })?;
    Ok(())
}
```
