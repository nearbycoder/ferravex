## Behavior and compatibility decisions

The plan owns the existing dimensional body type `B`, ordered `Collider` children
and existing `JointDesc`s. It adds no duplicate shape/body kernel or solver.
Limits match existing insertion: 4096 bodies, 16384 total colliders, 32 children
per body and 4096 joints. Authoring stops on the first excess child even for an
unbounded iterator; capacity errors retain the plan's accepted entries and counts.
Rejected input values are consumed/dropped. Geometry checking is deferred to the
world, so plans can contain forward references before final validation.

`LocalBodyId` and `LocalJointId` are explicit zero-based plan indices, not world
handles or generation/owner tokens. Equal indices from another plan intentionally
resolve to this plan's entries; callers must keep their plan association. There
is no implicit cross-plan-ID rejection. Cloning a template preserves local ID
meaning. Collider local IDs are `(LocalBodyId, zero_based_child_index)`, avoiding
another redundant global collider-index space. Local endpoints must name staged
bodies. Existing-world body endpoints are deliberately excluded.

`validate_assembly` checks combined body/collider/joint capacities first, then
all body dimension/finite-origin/finite-rotation checks, all collider local
settings and shape dimensions, all dynamic compound mass/inertia, then all
local references and joint descriptor/type rules. Invalid local endpoints return
`Joint { error: InvalidHandle, .. }`; self joints, pairs without a dynamic body
and invalid descriptions return `Joint { error: InvalidJoint, .. }`, including
disabled joints. Fixed/kinematic anchors may have no colliders/zero density;
dynamic bodies require representable positive mass, with sensors contributing
as before. Unlike legacy compound insertion, assembly preflight also checks
shape geometry/dimension on non-dynamic bodies. This closes the fixed-body
cross-dimension geometry gap for the new API without changing old acceptance.

Returned ordinary errors occur before any world insertion, wake, cache/filter
refresh, mass edit or arena/free-slot/generation mutation. This is preflight,
not insert/remove rollback. Validation is read-only and allocates no storage.
Validation is a snapshot, not a reservation; insertion checks again after any
intervening world edit. Error context names the failing local body/joint. The
plan is consumed by insertion even on error; callers needing a retained template
can clone it or preflight by reference. There is no separate prepared plan tied
to one world and no external callback during publication.

After successful preflight, all mapping vectors are allocated before publication.
The implementation inserts in plan order using the unchanged `insert_compound`
and `insert_joint` entry points with owned inputs. Their repeated ordinary
checks cannot fail after complete preflight and the exclusive world borrow;
internal `expect`s make an invariant failure explicit rather than returning a
misleading ordinary transactional error after publication. Mass construction,
authored origins, velocity/COM behavior, wakes, child-parent assignment and child
order retain existing compound semantics. Missing reference rotations capture
relative endpoint orientation at insertion. Joint cache initialization, wake,
collision filtering and refresh of any previously dirty existing joints retain
the exact ordinary insertion behavior. Accepted insertion does not issue or
execute a simulation tick.

Mappings contain ordinary generational same-world handles in deterministic plan
order, independent of caller assumptions about arena slots. Invalid lookup indices
return `None`; collider-free anchors resolve to an empty child slice. The mapping
does not own world objects. Removing mapped bodies uses the existing removal
path, also removing their children/joints. Reinstantiating a cloned template
preserves local IDs and yields new generations; old handles remain stale.

No existing public struct literals, exhaustive enums (including `PhysicsError`),
constructors, APIs, defaults, wire/save/replay formats or native/Wasm exports
were changed. The new `AssemblyError` is non-exhaustive. Body insertion acceptance
is intentionally the existing finite pose/dimension contract; this is not a new
validator for all retained legacy velocities, forces, damping or targets. Use the
existing checked body/geometry builders for untrusted input.

## Allocation and panic boundaries

This is not panic rollback, a no-allocation successful insertion guarantee, a
fallible allocator API or an undo system. Plan growth, template cloning, mapping
staging, arena growth, per-body children and joint refresh/filter/event storage
can allocate. Ordinary rejected insertion allocates nothing after staging in the
measured paths. Read-only valid preflight also allocates nothing.

OOM/allocator failure, caller iteration/conversion/Drop panics and inherited
body-revision-exhaustion panics are outside the returned-error guarantee. A panic
after publication may leave a partial mechanism without a returned map. Input
conversions occur during staging, not after the world transaction starts. No OOM,
allocator panic or destructor panic rollback has been injected or claimed. No
world copy, serializer, general rollback/undo, fracture, solver or collision-safe
placement system was added.
