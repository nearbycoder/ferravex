## Concrete storage, authorization and failure behavior

Construction fallibly reserves a `Vec<Entry>` for exactly the requested count
and a `Vec<u8>` arena for the requested total byte budget via
`try_reserve_exact`. Zero snapshot count rejects; zero byte budget is valid for
empty snapshots. Reserve/capacity-overflow failures return `AllocationFailed`.
After construction all store operations allocate nothing and never reserve.
The allocator may round allocations; bounds describe retained byte lengths and
snapshot count, not allocator metadata/RSS. Reset clears logical lengths and
authorization while retaining allocations; unused memory is not scrubbed.

Every accepted new insertion removes the smallest oldest-first prefix needed
to fit both limits. Empty snapshots consume count. A byte insertion may evict
multiple entries. Compaction moves the remaining arena prefix and adjusts
offsets; it is O(retained bytes + entry count), not a constant-time ring. ACKs
and identical duplicates do not refresh order. An acknowledged snapshot is
evictable and has no separate pinned copy outside the byte bound. Its ACK
watermark survives eviction, but `baseline()` returns None and selection returns
`Full(BaselineEvicted { tick })` until an exact retained snapshot is ACKed.

`record_sent` and `install` share immutable per-tick content policy. A retained
tick with equal bytes returns `Duplicate` without consuming a generation; unequal
bytes returns `ConflictingTick`. An evicted old tick cannot be reinserted as a
duplicate. New ticks must be serial-newer than both the latest and oldest
retained ticks; `u32::MAX -> 0` works, backward/equal/half-range ticks reject.
The oldest-window check deliberately runs before eviction: a half-range window
requires explicit reset even if that insertion would have evicted its oldest
entry. Error precedence is retained duplicate/conflict, byte size, latest tick,
oldest window, generation exhaustion. Every returned rejection preserves all
retained bytes/order, authorization, counts and storage capacities.

Exact retained lookup precedes every ACK decision. Unknown/evicted/rejected-send
ticks return `Unknown`, regardless of whether they are newer. Among exact
retained entries, an internal nonwrapping u64 insertion generation makes ACK
authorization monotonic; repeats return `AlreadyAcknowledged`, older generations
return `Stale`. Generations reset explicitly; u64 exhaustion rejects new
insertions without eviction or authorization change. Merely retaining or
selecting a snapshot never acknowledges it.

Selection uses `Delta::encoded_len` then `Delta::between_into`; there is no second
delta codec. It checks retained ACK authorization, newer base/result ordering,
same length, codec validity, checked envelope-size arithmetic/packet limit,
strictly smaller size, and caller Delta capacity, in that order. Only
`Selection::Delta` replaces the caller Delta. Every full outcome preserves that
Delta (including ticks and allocation), store and authorization. Full selection
is a fallback recommendation, not proof that the full packet is valid, fits
limits or has an acceptable tick. Current v5 callers supply overhead 24 and
`MAX_PACKET_BYTES` (1200); codec/envelope encoding remains caller-owned.

Receiver `apply_into` checks result advancement against latest installed tick,
exact base membership and base/result serial ordering, then delegates to checked
`Delta::apply_into`. Errors preserve the entire output; success writes only the
returned prefix and preserves the tail. No result, even a successfully applied
delta, is automatically installed, published or ACKed. Same-length wrong content
cannot be detected by this byte-delta format: the receiver must install the
exact validated bytes and prohibit conflicting reuse. No hidden content hash,
application decoder, session validator, tick-field parser or transport ACK proof
is implied.

The authorization boundary is explicitly documented: retention proves local
sent bytes only. Callers must authenticate outer session/epoch and require a
snapshot ACK to mean remote application validation/acceptance/installation.
Tick-only ACKs cannot distinguish an old session with reused ticks or an ancient
ACK after a full revolution in the same session. Callers must bound packet age
within half the serial space or rotate session before tick reuse. Local
generations order known insertions; they do not transmit an epoch or repair this
protocol ambiguity. Reset both stores on reconnect and gate all delayed packets
against the new external session before calling either store.
