## Concrete behavior

`format_visible_hint[_for]` reads the real current action bindings and the
installed effective touch layout. The caller supplies `(slot, code, label)` for
labels actually drawn now. Slots are task278/PlayerInput stable slice indexes,
not output channel numbers. Each descriptor must refer to an output of that
installed slot. Hidden suffixes, removed layouts and stale code/slot pairs are
rejected, so a missing Touch14 cannot be advertised by inventing a GAS slot.
Visibility itself is the caller's assertion; installation alone never proves a
label is drawn.

The formatters retain every nonzero binding in authored order, signed/non-unit
scales and duplicates; matching visible descriptors for one output are emitted
in descriptor order. Examples: `GAS x-0.5`, `STEER (stick X) x-1`,
`SWIPE (gesture X)`, `Touch 14 (not visible)` and
`Touch look 1 (gesture; not visible)`. Missing bindings for the selected family
are `Unbound`; there is no device fallback. Generic touch fallbacks describe a
channel rather than guessing a button or gesture region. Deadzones are not
printed, matching the existing hint contract.

Caller labels may be UTF-8. Validation permits at most 32 descriptors, each
1..=96 bytes without control characters, with no duplicate `(slot, code)`.
Unknown actions fail first. Invalid descriptors and insufficient capacity leave
the entire caller buffer unchanged. Two-pass formatting reports exact required
UTF-8 bytes and preserves the unused tail on success. No descriptors are stored,
no input is sampled, and no tick edges/motion are consumed by formatting.
The maximum-capacity test measured **zero allocations** for successful reads,
capacity failures and descriptor errors.

Customization is explicit: a consumer that draws the same labels on resolved
custom geometry can supply them; a custom overlay that hides authored labels
must omit them or supply its actual replacement labels. `touch_customized()`
is not used to infer visibility. Actual effective outputs/slot identities are
checked after settings are applied. Rebind, import, capture/reset and layout
replacement take effect on the next read.

The shared real `write_code_label` now names `0xff55` PageUp and `0xff56`
PageDown. Inspection of `web/input.js` also confirmed mapped Home (`0xff50`),
End (`0xff57`) and Insert (`0xff63`), which now have names. Unknown codes retain
`Key N`. Binding identity is unchanged.

For panels narrower than 530 logical pixels, the bindings editor now shows one
action's full label plus **all** current nonzero bindings, wrapped with the
registered `ui::text_layout` at 14px with a 16px line advance. Long content
continues on numbered pages instead of eliding text. At most two bounded action
strings coexist while deriving pages; there is no retained page list or new
PlayerInput state. The existing `page` field remains the cursor. Done, Bind key,
applicable Bind pad, paging and Reset remain on every page. Delta actions still
have no pad-capture target. Save/close, capture/cancel and status copy wrap at the
same readable size. Device labels use full row width on narrow panels, with
separate value/adjustment geometry. Tab changes return before painting the old
tab's indexes, avoiding a stale-page action lookup.

Production glyph tests visit every page of the TopDown defaults, a 96-byte
label, Unbound, and an action with 64 long signed bindings. They compare every
body glyph vertex with complete expected text, exercise 320x480, 320x324 and
304x324 logical hosts, check full save/close/capture/status/help and essential
button glyphs, and verify bounds. The minimum panel remains 280x300 logical
pixels (304x324 with normal margins). Smaller hosts can clip the panel, as
explicitly documented; no essential type is reduced. Native vertex submission
is not browser screenshot or physical-device evidence.

## Exact new public API

Accessible through `ferravex_render::input` and the existing facade input alias:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct VisibleTouchLabel<'a> {
    pub slot: usize,
    pub code: InputCode,
    pub label: &'a str,
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum VisibleHintError {
    Hint(HintError),
    Capacity,
    InvalidLabel { index: usize },
}
// VisibleHintError implements Display and std::error::Error.
impl PlayerInput {
    pub fn format_visible_hint<'a>(
        &self, name: &str, labels: &[VisibleTouchLabel<'_>], buffer: &'a mut [u8],
    ) -> Result<&'a str, VisibleHintError>;
    pub fn format_visible_hint_for<'a>(
        &self, name: &str, device: Option<HintDevice>,
        labels: &[VisibleTouchLabel<'_>], buffer: &'a mut [u8],
    ) -> Result<&'a str, VisibleHintError>;
}
```

This is a signature excerpt, not a runnable block. `InvalidLabel { index }`
identifies the descriptor failing slot/code/text/duplicate validation. The
existing exhaustive `HintError` enum and existing public struct literals are
unchanged. Legacy `format_hint`/`format_hint_for` retain their formatting,
current-device, Unbound, buffer and error contracts, apart from the requested
named navigation-key display improvement.
