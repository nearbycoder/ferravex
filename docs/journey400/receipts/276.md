## Concrete behavior and compatibility

`StatRow` borrows caller-formatted label/value/optional description strings.
Metric semantics, availability, sign, precision, rollover and units remain
caller-owned. No number parsing/rounding/unit conversion or implicit empty-value
substitution occurs. The API adds no state to `Ui`, allocates no heap layout
storage and leaves all existing public structs/enums/defaults and immediate
`ui::stat` behavior unchanged. There is no simulation, input-edge, clock,
wire/save/replay or platform-export change.

A list accepts at most **64 rows**; excess returns `UiError::Capacity` before
text scanning. Geometry uses a private fixed array; no dynamically growing row
collection or retained cross-frame cache is introduced. Rebuild a borrowed
layout when source/style/bounds change. Text source lengths and scan work are
caller-owned: construction measures every supplied row, including hidden rows,
and is not bounded by the visible prefix. Visible source is copied only at
submission into the existing reusable UI text arena. Formatting can use a
reused caller `String`; `Ui::text_fmt` is unchanged and still works in the same
composition, as the warmed regression demonstrates. No alternate string arena
or duplicate wrapping algorithm was added.

The maximum natural label width is shared across all columns. Columns are
selected only if that label width, the maximum natural value width and the
column gap fit. Otherwise every row stacks label above value, both at full
available width. Optional descriptions always follow the pair at full width.
All blocks use task273 `WrappedText` measurement and `wrapped_text` submission
with `LineLimit::Unlimited`. Every block stays at the chosen font size; no
ellipsis, result-card scaling or text shrinking is used. Default sizes are 18
logical units for all three roles; colors, alignment and shadow are honored.
`TextStyle.wrap` is intentionally overridden to true by existing wrapped text.
Empty label/value/description blocks reserve one full line slot.

Bounds, text sizes/colors and gaps are validated even if no rows will paint.
Invalid/nonfinite bounds, negative gaps, sizes outside the UI's existing
`1..=256` range, nonfinite colors or unrepresentable geometry/heights return
`InvalidLayout`. At valid zero/tiny widths below one participating font cell,
all rows are hidden and `width_overflow` is true. Zero/tiny heights likewise
return an explicit complete-prefix count. No partial last row, partial value
or scalar narrower than its cell is submitted. The first height miss stops the
visible prefix; later short rows are not reordered into the remaining space.

`required_height` includes every supplied row plus internal row gaps;
`used_height` describes only the visible prefix, without a trailing gap.
`hidden_rows` is the full source count minus the visible prefix. Geometry uses
full line slots and actual preceding f32 endpoints; row extents round outward
where subtraction would otherwise exclude a text slot. Fractional sizes,
negative/fractional origins and zero gaps remain nonoverlapping. Essential
hidden copy is never silently replaced with dots: the consumer must choose
scrolling, expansion, a visible omitted-row message, or a small explicit fallback.

`rows()` returns the same accepted row/label/value/description rectangles used
for paint and inspection, in source-prefix order. Text rows do not register hit
regions. Existing ancestor clips/viewport projection/occlusion can still hide
content; the consumer must pass bounds within its safe visible region. Reports
are layout results, not visibility/occlusion or physical-device readability claims.

Each standalone helper and `StatRowsLayout::submit` uses task281 composition.
Any actual command/text/vertex-capacity rejection rolls back the whole list,
including commands already submitted for earlier rows and inspection copy.
Nested errors can be handled locally for an explicit fallback or propagated
with `?` to reject the entire containing card, including panel/actions/modal
blocker. No fallback is implicitly inserted or capacity reserved for it. Each
nested helper consumes one of task281's existing 16 composition depth slots.
Callback effects outside UI, panic/abort and allocator failure retain task281's
limits. `Ui::begin` clears accepted commands/copy and preserves reserved storage;
new layouts never inherit stale geometry/hidden counts from an earlier frame.

Existing bitmap-font behavior is retained: ASCII paints uppercase; unsupported
Unicode scalars paint `?`; wrapping preserves task273's documented LF/blank-line
and wrap-boundary whitespace rules. UTF-8 source/inspection strings are exact;
this is not a new Unicode shaping or glyph-support claim.

## Exact additive public API

All names below are under `ferravex_render::ui::stats` except the existing
`ui::Ui`, `ui::UiComposition`, `ui::UiRect`, `ui::TextStyle`, `ui::UiError`.
Signature excerpts are not a standalone program.

```text
pub const MAX_STAT_ROWS: usize = 64;

pub struct StatRow<'a> {
    pub label: &'a str,
    pub value: &'a str,
    pub description: Option<&'a str>,
}

pub struct StatRowsStyle {
    pub label: TextStyle,
    pub value: TextStyle,
    pub description: TextStyle,
    pub column_gap: f32,
    pub row_gap: f32,
    pub stack_gap: f32,
    pub description_gap: f32,
}
// Default: sizes 18 via TextStyle::default(); gaps 16, 12, 4, 4.

pub enum StatRowsMode { Columns, Stacked }

pub struct StatRowsReport {
    pub mode: StatRowsMode,
    pub visible_rows: usize,
    pub hidden_rows: usize,
    pub required_height: f32,
    pub used_height: f32,
    pub label_width: f32,
    pub width_overflow: bool,
}

pub struct StatRowGeometry {
    pub row: UiRect,
    pub label: UiRect,
    pub value: UiRect,
    pub description: Option<UiRect>,
}

pub struct StatRowsLayout<'a> { /* private borrowed/fixed-storage fields */ }
impl<'a> StatRowsLayout<'a> {
    pub fn new(bounds: UiRect, rows: &'a [StatRow<'a>], style: StatRowsStyle)
        -> Result<Self, UiError>;
    pub fn report(&self) -> StatRowsReport;
    pub fn rows(&self) -> &[StatRowGeometry];
    pub fn submit(&self, group: &mut UiComposition<'_>)
        -> Result<StatRowsReport, UiError>;
}
impl Ui {
    pub fn stat_rows(&mut self, bounds: UiRect, rows: &[StatRow<'_>],
                     style: StatRowsStyle) -> Result<StatRowsReport, UiError>;
}
impl UiComposition<'_> {
    pub fn stat_rows(&mut self, bounds: UiRect, rows: &[StatRow<'_>],
                     style: StatRowsStyle) -> Result<StatRowsReport, UiError>;
}
```

`StatRow`, style, report and geometry are `Clone + Copy + Debug`; report/geometry
also `PartialEq`. Mode is `Clone + Copy + Debug + PartialEq + Eq`. Style has
`Default`. Layout has `Debug` and cannot be externally mutated.

## Actual consumer recipe / handoff

The module rustdoc is an executed actual-Ui result-summary recipe at **320 and
640 logical pixels**, with 16-unit margins, 18-unit fonts, caller-formatted
`1:00.001`, `-1.250 s`, `18446744073709551615` and explicit `UNAVAILABLE`. It
selects stacked mode at 320 and columns at 640, submits a panel, the measured
list and stable `CONTINUE` action901 with 44-unit height through real
composition, then paints. Inspection asserts actual supplied copy and exact
visible label/value/description rectangles against `layout.rows()`. The recipe
rejects the complete card if any stats are hidden. A second executed doctest
uses both `Ui::stat_rows` and restricted `UiComposition::stat_rows` directly.

**Card277:** use `StatRowsLayout::new(content_bounds, borrowed_rows, style)`
after reserving title/body padding and a readable primary-action region. Read
`report().required_height`/`hidden_rows` to select expansion or scrolling before
submission. Call `layout.submit(card)?` inside the card's existing atomic group;
or use `card.stat_rows(bounds, rows, style)?` when geometry is not otherwise
needed. Required sections should propagate an error; a nonzero hidden-row count
is successful explicit geometric overflow and must be handled by card policy.
The module recipe demonstrates rejecting a partial summary as `Capacity` so the
parent can select a small explicit fallback with the same action ID. Do not
shrink the entire card or depend on essential-value ellipsis. Reuse `rows()` for
inspection/host semantic descriptions rather than maintaining another geometry.
Keep lifecycle, input finish, paint and game mutation outside the composition.

**Parent Sky/Dune results and Physics Lab inspectors:** supply the game's own
metric meaning, authored labels/units and explicit unavailable copy. Reuse
existing caller formatting buffers between frames. Use logical safe-area content
bounds and remeasure at the actual position/width after changing card geometry.
No game or custom software renderer migration was attempted here. Existing
renderers can consume the pure measured rectangles/copy via composition adapters;
this module does not install another renderer or force adoption in every demo.
