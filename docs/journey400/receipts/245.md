## Behavior and compatibility

`PityCounter::attempt` is byte-for-byte identical to HEAD. Construction, limit validation, two private u16 fields, Clone/Copy/Debug, initial zero misses and reset behavior are preserved. There was no Default implementation and none was introduced. A native storage assertion checks the existing four-byte counter; no stable layout/ABI guarantee is added. Exhaustive ten-roll boolean patterns at limits 1–5 compare both APIs to the original formula and exact misses sequence.

`attempt_outcome` distinguishes Ineligible/Deferred/Miss/Natural/Guaranteed with immediate legacy commitment. Skipped attempts do nothing. Natural success takes precedence even at the guarantee boundary and at limit one.

`PityDelivery` moves the counter into a separate wrapper, deliberately neither Copy nor Clone. It stores exactly one `Option<PityOffer>`, no payload/history/list/heap allocation. Accepted misses advance immediately. Natural/guaranteed offers do not reset committed misses until `settle(id, true)`. Refusal leaves the same offer, reason and counter intact indefinitely; retry reads `pending()` and reuses the retained payload without another event admission or RNG roll. New accepted offers while pending return Pending without mutation; even a conflicting natural success cannot replace the owed reward. Ineligible/deferred observations remain harmless while pending or exhausted.

Settlement is result-based, with no callback or rollback claim. Only the matching pending token can successfully settle once. Duplicate, stale and different-stream tokens return StaleOffer without state changes. A caller must check the current pending offer before insertion, keep exclusive ownership through insertion/settlement, report actual destination acceptance truthfully and publish feedback only after Delivered. Repeating an external insertion before checking the token is not prevented by this API. External effects, panic/crash recovery and payload provenance remain caller-owned.

IDs have private fields and consist of a caller-assigned nonzero stream plus internally issued nonzero u64 sequence. The host must use distinct stream namespaces across independently routed instances/lifetimes; recreating a wrapper with the same stream can alias old tokens. Neither copied legacy counters nor caller stream IDs establish unique/authenticated events. Sequence 1 through u64::MAX is issued once per reward offer (misses do not consume IDs). After max, all accepted admissions fail closed with IdExhausted; last pending settlement remains valid. Reset retains sequence and exhaustion, abandons/returns the pending offer and resets misses. There is no per-offer cancellation; explicit run reset/drop abandons debt, and the host must discard its payload. Reset IDs stay stale within the same instance.

No changes to game formulas, RNG ownership/consumption, game source, wire/save/replay formats, exports, dependencies or manifests. No engine changes or generic transaction framework.
