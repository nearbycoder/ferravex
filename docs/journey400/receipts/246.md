## Aggregate edge and duration contract

This is an explicit deterministic attribution policy, not a reconstruction of physical transition timestamps. All eight boolean combinations are allowed; independent `ActionMap` flags are not an ordered or counted event log.

1. Validate `dt` as finite `0..=3600` seconds before any mutation, including edge processing. Invalid input returns existing `LoopError::Invalid` atomically.
2. Age only recovery present on entry. Available held duration is `max(dt - old_cooldown, 0)`.
3. If a charge exists and `released || !held`, close that old charge using its previously accumulated duration, adding none of the current `dt`. Emit at `held_seconds + 1e-7 >= minimum`; otherwise distinguish `CanceledTooShort`. Emission resets recovery to its full configured duration. A too-short cancellation starts no recovery.
4. A final held level starts/continues a charge if recovery is now zero, adding only available held duration, capped at maximum. Thus both edges/final held true closes the old charge first, then may charge anew. Fresh positive recovery blocks restarting for this snapshot even if `dt` was large. Fresh recovery is not aged a second time.
5. Final unheld plus `pressed`, with no old charge closed and recovery now zero, resolves a zero-duration tap. Both edges/final held false and pressed-only/final unheld use this rule. Minimum zero emits power zero; a minimum above the `1e-7` tolerance cancels. A closed old charge uses this snapshot's only resolution slot, even when it was too short, so extra aggregated transitions cannot cause another emission.

When not charging, release alone is ignored. Final held can start without a press, including release-only/final held; this preserves level-based resumption after cooldown. Press without release does not reset an active charge. Final unheld closes an old charge even without a release flag. Zero `dt` still processes edges; a release/repress can emit old power and leave a zero-progress new charge if recovery is zero. Existing recovery expiring within `dt` gives a hold only its partial remainder; exact expiry starts at zero progress. A tap whose preexisting recovery expires in that snapshot still has zero duration. Neither a final unheld quick tap nor an old release borrows elapsed charge from `dt`.

With both edge flags false, final state and emitted values exactly match the unchanged legacy `step(dt, held)`. With ordinary sampled rising/falling edges and no aggregate intermediate transitions, the additional flags also preserve that behavior. `cancel()` still clears only progress/charging and keeps cooldown; it emits nothing and does not suppress a future held sample. New `reset()` additionally clears cooldown but keeps minimum/maximum/recovery configuration. Reset host input/session and accepted-event state separately on restart. A caller replaying the same edge flags in another call is submitting another snapshot; the helper cannot identify duplicate ticks. Consume once per executed tick.

## Executable first-party GameSession + ActionMap + Magazine recipe

This complete headless recipe uses real `ActionMap::feed` and tick consumption, with injected elapsed time rather than wall clocks. The first tap waits across a genuine zero-tick `GameSession` advance; two catch-up ticks resolve it once. A second tap requests a shot from an empty magazine and produces no accepted feedback. A third tap occurs under a local overlay: its input is consumed/masked, its local charge is canceled, and authoritative session/magazine time still advances. There are six actual updates; issued and executed counters are tracked separately, with the authoritative-phase guard before input consumption. The example's `accepted_feedback` counts accepted game events, not audible output or a feedback-device test.

```rust,check crate-type=bin
use ferravex_core::session::GameSession;
use ferravex_play::gameplay::charge::{ChargeAction, ChargeRelease};
use ferravex_play::gameplay::magazine::Magazine;
use ferravex_play::input::{Action, ActionMap, Binding, InputCode};

fn main() {
    let mut session = GameSession::try_new(64.0, 4, true).unwrap();
    let mut input = ActionMap::default();
    let code = InputCode::Key(32);
    let fire = input.try_action(vec![Binding::digital(code)]).unwrap();
    let mut charge = ChargeAction::new(0.0, 1.0, 0.0).unwrap();
    let mut magazine = Magazine::new(1, 0, 1.0).unwrap();
    let mut issued = 0_u64;
    let mut executed = 0_u64;
    let mut requests = 0;
    let mut accepted_feedback = 0;

    for (frame_index, local_overlay) in [false, false, true].into_iter().enumerate() {
        input.feed(code, 1.0);
        input.feed(code, 0.0);
        if frame_index == 0 {
            let zero = session.advance(0.5 / 64.0);
            assert_eq!(zero.steps, 0);
            assert!(input.peek(fire).pressed && input.peek(fire).released);
            assert!(!charge.charging()); // No charge update or edge consumption.
        }
        // Keep network/replay authority Playing under this local overlay.
        let frame = session.advance(2.0 / 64.0);
        assert_eq!(frame.steps, 2);
        issued += u64::from(frame.steps);
        for _ in 0..frame.steps {
            if !session.is_playing() { break; } // Gate any unexecuted issued tail.
            executed += 1;
            magazine.advance(frame.dt).unwrap();
            let snapshot = input.consume_tick(fire); // Once per actual tick.
            let snapshot = if local_overlay {
                charge.cancel(); // No forced release; preserve existing recovery.
                Action::default() // Consume masked edges so they cannot fire later.
            } else {
                snapshot
            };
            let report = charge.step_edges(
                frame.dt, snapshot.value != 0.0, snapshot.pressed, snapshot.released,
            ).unwrap();
            if let ChargeRelease::Emitted(power) = report.release {
                requests += 1;
                assert_eq!(power, 0.0); // Zero-duration quick tap, not inferred timing.
                if magazine.fire() { // Actual game-owned admission and ammo cost.
                    accepted_feedback += 1; // Route accepted shot event to feedback here.
                }
            }
            // Advance the rest of the authoritative simulation here, overlay included.
        }
    }
    assert_eq!(requests, 2);
    assert_eq!(accepted_feedback, 1);
    assert_eq!(magazine.loaded(), 0);
    assert_eq!((issued, executed, session.tick()), (6, 6, 6));
    assert!(session.is_playing());
    assert!(!charge.charging());
}
```

For a game, share the one consumed snapshot across charge/rules/UI rather than consuming it again for sound. Apply actual cost/hit/launch acceptance before feedback. Keep authoritative network/replay progression running under local overlays, masking only local commands; do not pause their `GameSession`. On an authoritative terminal transition, stop executing the rest of an issued batch rather than updating charge/input for work that did not execute. For a restart, reset charge, pending input, session and game-owned accepted-event history together. This recipe intentionally adds no renderer or command queue.
