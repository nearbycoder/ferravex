## Bounds, time and partial completion

One monotonic supplied Duration domain per state; exact microseconds only; inclusive maximum2^53 microseconds; equal times allowed. Operations update the accepted time watermark before later work; no implicit clock read. Render/age/diagnostic queries validate supplied time without advancing that watermark. The adapters sample their own elapsed origin with the existing native/Wasm Instant abstraction. Server/client origins may differ: correlated Ping/Pong timestamps retain that intended clock-sync behavior.

- Receive decodes exactly one <=1200-byte datagram. Only tick issues a new sanitized, sequential input and executes a fresh local prediction step. Receive/poll may reconcile already executed inputs; reports distinguish prediction_steps and replayed_inputs. Poll never creates a new input or simulation tick.
- At most128 retained newest inputs; overflow explicitly evicts one oldest entry and reports inputs_evicted, preserving the legacy overload policy. Reconciliation replays at most128. Outbound input consists of the latest six retained entries. A refused/zero-budget input datagram leaves its tail dirty for later poll; a later executed tick deliberately coalesces it into the newer six-input tail. Accepted sends do not remove unACKed prediction history.
- ReceiverBaselines:32 immutable full snapshots /38400 bytes, storing exact reconstructed full datagrams. History:32 render frames, each <=16 players. Previous/current authority rosters, predicted local player, epochs and scratch are bounded by the existing decoded roster/1200-byte protocol. No extra unbounded acknowledged baseline clone exists.
- Incoming reliable window <=256 receipts; combined final gameplay queue plus incoming receipts <=512. Absolute receiver capacity is min(256,512-final_queue_len), not remaining capacity with buffered subtracted twice. When this is less than a full sequence window and the head is missing, one slot is reserved for that head. Final delivery capacity is checked before consuming a Gameplay receipt. Retained tails drain on later poll/receive/tick without another packet; `drain_events` transfers <=512 events and the host should subsequently poll. Existing full-delivery backpressure behavior remains.
- <=8 ordered receipt applications per core operation; controls (Lobby/Round/ActionResult) stay in the same sequence stream. Each Round may replay <=128 inputs; receive can additionally reconcile one snapshot, so <=1152 replayed inputs/receive, <=1024/poll or tick, plus <=1 fresh prediction/tick. There is no catch-up loop; host calls tick per actual executed64Hz tick. Public last round/lobby/action-result slots intentionally retain the latest applied value, matching legacy semantics; gameplay delivery is a FIFO.
- <=256 pending event ACK sequence IDs with duplicate coalescing. If that output backlog is full, a new ACK obligation is refused before receipt admission. Snapshot ACKs coalesce into one latest installed tick; full recovery has one pending flag. Thus <=258 logical pending ACK/recovery obligations. ACK flush attempts a bounded prefix and whole-output budget stops it. Sender retries recover rejected admission; retained receipt plus deferred ACK survives no-new-packet calls.
- <=256 queued commands, each validated existing two-byte action; at most8 command offers/poll with the shared borrowed checked codec and send_due. Only accepted complete datagrams advance retry timestamps. Exact remaining-due sampling occurs when poll reaches command flushing; receive/tick do not flush commands, and their default commands_remaining_due=0 is not a statement that no command is due. commands_pending always reports actual retained count.
- Output callback and byte budgets are clamped to128/153600 per operation. Zero/exact/short budgets are valid. First false or nonfitting packet stops all later offers for that operation; refused output/command head and untouched tails remain pending. datagrams_refused counts false callbacks; deferred counts generated but unoffered candidates, not every undiscovered tail. Bytes count complete initialized envelopes; reliable payload budgets remain separate. Callback side effects/earlier accepted output are not rolled back.

Retained end-of-operation counts: inputs_retained, events_buffered, events_delivered, acknowledgements_pending, commands_pending. events_retained/duplicate/refused/consumed and inputs_acknowledged/evicted are operation work counts; events_ready is the retained ready suffix sampled by that operation's drain. Counters before errors are preserved; last_report records errors/tick_executed. Tick output refusal is successful completed prediction, never an instruction to execute the same tick again. Protocol encode/storage failures return Err without retracting committed work. A malformed datagram does not produce an automatic repeating error loop; installation errors are not retried by poll. Half-space baseline-window/generation exhaustion requires fresh-nonce outer reconnect rather than a fabricated ACK/reset.

The native/Wasm adapter's receive loop remains capped128, and reconnect maintenance uses at most two polls. `GameClient::poll` may perform many core operations; last_report is its last core operation, not an aggregated socket-frame report. WouldBlock returns false with no fatal error. Short datagrams return false plus retained WriteZero, and fatal I/O returns false plus the original error; adapters propagate those after recording the core's partial result. No fatal-send retry loop is hidden in the adapter. Legacy queue_action reliable failure retains WouldBlock classification.

These are logical storage/work bounds, not allocator/RSS/performance measurements. Snapshot decoding/player/history collections, reliable admission/encoding, queues, drain_events and packet construction may allocate. No allocation-free, determinism, throughput or physical-device claim.

## Snapshot, reliable and lifecycle gates

Outer session is checked before SnapshotDelta/Pong/CommandAck/reliable state. Welcome must match the current handshake nonce and cannot replace a session already bound to that nonce; mismatched delayed old Welcome is rejected both before and after the new session. Existing codec validates protocol/version, full lengths, finite/player fields, IDs, duplicates and orphan epochs. Snapshot acceptance also requires a serial-newer authority tick, local membership and representable unwrapped tick. Delta reconstruction uses task229 ReceiverBaselines into initialized scratch, then the actual full decoder and exact inner session/tick equality checks. Store installation succeeds before authority publication, reconciliation or SnapshotAck(Some). Missing/invalid/uninstalled delta never acknowledges its result; full recovery retains the100ms accepted-request rate gate. Refused recovery output does not advance that gate. Refused probes do not commit clock slots/nonces/timestamps.

Reliable payload/application decode and exact session validation precede312 admit. Only retained receipt or legitimate duplicate creates an ACK obligation. Final ordered gameplay delivery is at most once in one session, including duplicates and drain-without-packet. Refusing callback output never claims admission. Control updates and tactical actions continue through the original Mode/View rules; there is no speculative action application and false-return rollback assertion. Incoming command ACKs only affect the matching session's existing sender. Reliable sequence exhaustion remains explicit; u64 sequence does not wrap.

`new` and `reconnect` require host-provided nonzero nonce. Reconnect rejects reuse of the immediate previous nonce; the host must ensure it also never reuses an older nonce (bounded state does not retain an infinite nonce ledger). Time origin stays monotonic across reset. Reconnect clears session/id, predictions, held input edges/pending inputs, input sequence, snapshots/history/epochs, clock estimates/probes/unwrapper, commands, reliable receiver/final queue/ACK tails, lobby/round/result, last snapshot/hello/probe/recovery times together. Clock reset uses315's nonce-cursor-preserving reset. The cumulative rejected counter remains cumulative. Timeout is strict >5s since accepted snapshot/Welcome; it clears authority immediately and sets needs_reconnect. The core sends no Hello until the host supplies a fresh nonce. GameClient automatically supplies one at that host boundary, preserving automatic reconnect. Rehello on the still-present authority preserves actual health/ammo/position/aim as230 already implements; the real driver recipe tests it. Client provisional spawn before its first authoritative snapshot remains the legacy behavior.

Protocol v5 fields/bytes, authored64Hz tick rate, practical defaults, six-input redundancy, render smoothing, tactical rules and low32 life epochs remain. The original shared predictor and rendering interpolation math are reused. Existing task240 UDP relocation/life discontinuity test passes. Legacy absolute f64 rendered/clock ticks retain their precision limit: exact integer ticks only through2^53. No claim of restored upstream precise components. Half-serial-space packet-age and full tick/life-low32 reuse limits require outer session rotation; no new packet field or generation wire format was introduced. Local overlays suppress host commands while receive/poll and authoritative/replay clocks keep progressing.
