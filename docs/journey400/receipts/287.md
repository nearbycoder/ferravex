## Behavior and compatibility

- `Transition3` is optional presentation state, initially empty. No existing
  `Pose3`, `Frame3`, `Rig3`, settings, update, defaults, public literals, exhaustive
  enums, native/Wasm exports, wire/save/replay formats or renderer were changed.
- Each active segment retains prepared start/end/displayed poses, a lens and f64
  elapsed/duration. It has fixed inline storage, no collections, clocks, callbacks,
  tick/input ownership, queries or authoritative simulation writes. Capacity cannot
  fill; retarget replaces one pending segment. 512 instrumented full lifecycle
  loops observed zero allocations, including construction; positive control
  observed a real allocation. No performance benchmark is claimed.
- Eye position, positive view distance and FOV blend linearly. Target derives from
  blended eye + shortest-arc view direction * distance. Interior up is perpendicular
  unit up, preserving view roll; authored up length/forward component is not
  semantically interpolated. Zero-time/start and completed/cut endpoints return
  original `Pose3` values exactly, including authored nonunit/skew up. A target is
  a look point, not an authoritative entity tracking constraint or fixed orbit
  pivot: a blend can travel through obstacles or move away from a shared pivot.
- Reuses `Mat4::try_look_to_rh`, `try_to_scale_rotation_translation`, quaternion
  `try_normalize`, `try_angle_between` and `try_rotate_towards`. No competing basis
  conversion, quaternion interpolation, transform hierarchy or swing/twist system.
  Endpoint quaternions use positive w, or at w==0 first nonzero x/y/z positive.
  The existing checked quaternion helpers flip a destination on negative dot;
  exact zero-dot half-turn ties retain these supplied canonical endpoint signs.
  Near-half-turn perturbations may select the opposite equally short arc.
- `retarget` begins at the most recently displayed pose/orientation/distance,
  resets segment time and preserves a hold. It never restarts from stale start
  or pending end. The call itself does not advance time or change the picture.
  Continuous retargeting preserves pose continuity, not velocity continuity;
  repeatedly retargeting can keep a transition perpetually unfinished.
- `hold`/`resume` are idempotent and report whether state changed. Hold discards
  valid presentation delta without changing pose/time. Resume consumes no paused
  time and cannot rewind the picture. Retargeting while held replaces pending
  work but retains the picture. Host simulation/network/replay progression is
  independent; this module cannot stop or observe it.
- `cut`, zero-duration retarget and `Frame3::cut` replace all endpoints immediately
  and release hold. Empty-state retarget initializes exactly regardless of valid
  duration. `reset` forgets pose, lens and all pending work, releases hold; the
  next target initializes exactly. Each initialization/cut/reset increments a
  wrapping u64 generation; blending/hold/resume/ordinary retarget do not. This is
  a local discontinuity marker, not an issued/executed tick ID or unique token.
- `retarget_frame` borrows only pose/cut and validates duration even for a cut.
  Obstructed/blocked-pivot/recovered/query diagnostics remain in the unchanged
  input frame. Recovered alone is not interpreted as a cut. Output is `Pose3`,
  never a `Frame3` claiming that old queries observed the blended camera path.
- `Perspective3` declares symmetric finite-far perspective lens intent. FOV comes
  from `Pose3`; all other lens fields must compare exactly equal for nonzero
  blends, including RH/LH and NDC depth. Zero duration/explicit cuts allow lens
  changes. All four existing `NdcDepth` declarations and both handednesses are
  accepted; host construction must match its declaration. Internal orientation
  uses camera -Z/+Y, while world-space output forward/up can feed the host's RH
  or LH view constructor. No handedness flip occurs within a blend. Orthographic,
  infinite-far, asymmetric/custom projection transitions need host-owned adapters
  or cuts outside this perspective-only API; no matrix interpolation is invented.
- Lens validation requires finite positive aspect and finite `0 < near < far`.
  It does not promise the host's actual projection/inverse fits f32; the host
  still uses its checked matrix/projector construction. No viewport/DPR inference.
- Every fallible operation validates before mutation. Invalid poses/lenses,
  durations, deltas, incompatible projections and numerical sample failures leave
  the complete state unchanged, including elapsed time, hold and generation.
  Duration is finite `0..=3600` seconds; advance delta finite `0..=0.25`, even
  while empty/held/complete. Signed zero is accepted. Overshoot is discarded.
  Host suspension time must be discarded/rebased or handled by an explicit cut.
- Pose limits: finite eye components abs<=1e6; finite target; eye-to-target distance
  in `0.001..=1e6`; finite FOV in `0.05..=3.1` radians; finite nonzero up with sine
  to forward >=1e-4. Parallel/nearly parallel up is rejected without arbitrary
  roll fallback; finite extreme up scales are normalized by existing helpers.
  Distance/subtraction/scalar interpolation use f64 and output rounds to f32.
  A short interior target at large coordinates may collapse/become shorter than
  the documented minimum. Samples then return `NumericalLimit` atomically; valid
  endpoints do not guarantee every interior pose is representable. Exact endpoint
  completion bypasses reconstruction. No bitwise platform determinism promise.

Task202's `InterpolationPair` remains the engine host's optional tick-history
adapter. This camera-specific timed segment is below engine in the dependency
layering and does not introduce an engine dependency or duplicate tick history.
Task217's quaternion conventions/helpers are reused; ordinary shortest-arc motion
needs no swing/twist constraints.

## Exact public APIs

All below are exported by `ferravex_play::camera::transition`; signatures are
excerpts, with actual runnable examples in module/method rustdoc.

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum ViewHandedness { Right, Left }

#[derive(Clone, Copy, Debug, PartialEq)]
pub struct Perspective3 {
    pub aspect: f32,
    pub near: f32,
    pub far: f32,
    pub handedness: ViewHandedness,
    pub depth: ferravex_math::projection::NdcDepth,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum TransitionError {
    InvalidPose,
    InvalidProjection,
    InvalidDuration,
    InvalidDelta,
    IncompatibleProjection,
    NumericalLimit,
}
// TransitionError also implements std::fmt::Display and std::error::Error.

#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Transition3 { /* private fields */ }

impl Transition3 {
    pub fn new() -> Self;
    pub fn pose(&self) -> Option<Pose3>;
    pub fn projection(&self) -> Option<Perspective3>;
    pub fn is_blending(&self) -> bool;
    pub fn is_held(&self) -> bool;
    pub fn generation(&self) -> u64;
    pub fn hold(&mut self) -> bool;
    pub fn resume(&mut self) -> bool;
    pub fn reset(&mut self);
    pub fn cut(&mut self, pose: Pose3, projection: Perspective3)
        -> Result<(), TransitionError>;
    pub fn retarget(&mut self, pose: Pose3, projection: Perspective3, duration: f32)
        -> Result<(), TransitionError>;
    pub fn retarget_frame(&mut self, frame: &Frame3, projection: Perspective3, duration: f32)
        -> Result<(), TransitionError>;
    pub fn advance(&mut self, delta: f32) -> Result<Option<Pose3>, TransitionError>;
}
```
