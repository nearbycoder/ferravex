## Concrete behavior and compatibility decisions

- `RailSegment3` owns prepared key poses/lens intent and an existing `Transition3`, borrowing immutable route geometry if selected. It prepares a single normalized 0.25-second transition **once at construction**. Queries copy and advance that prepared transition once at normalized time, then translate its target offset to the sampled path eye. No live transition is retargeted on every frame, and no second quaternion, spline, view or projection implementation was added.
- Eye paths are either a full checked `CubicBezier3`, a full existing `Route3`, or an explicit zero-duration cut. Cubic position uses f64 polynomial parameter/time; this is not arc-length sampling. Route position uses Route3's measured f64 polyline arc length, including its closed seam and repeated/zero-length route behavior. Orientation never follows a tangent implicitly.
- `tessellate_route_into` checks both Complete status and full coverage before calling `Route3::set`. All partial statuses retain the previous route and its topology. Route-capacity failure also retains it. Scratch is explicitly disposable workspace and may contain a prefix on error; it is not a last-good output destination. A directly supplied Route3 is caller-authored geometry with no recoverable tessellation provenance; callers converting a cubic should use the adapter.
- Authored orientation/roll, eye-to-target distance and FOV reuse Transition3's shortest-arc interpolation and half-turn ties. Start/end keys are returned exactly at representable timeline boundaries, including authored nonunit/skew up. Interior up follows Transition3's orthonormal convention. Perspective declarations must match exactly within moving segments; explicit cuts may change them. All four NdcDepth values and both RH/LH declarations are exercised. View matrix construction and representability remain host-owned.
- Moving segment duration is finite positive f64 seconds <=3600. Cuts have exactly zero duration. Both key poses/lenses are checked by Transition3, including cut sources. Path endpoints must equal the authored key eyes, and cubic controls/route vertices must have absolute eye components <=1e6. Empty routes fail; stationary nonempty paths are allowed. Adjacent complete keys must match exactly; insert an explicit cut to author a jump/lens change.
- A rail borrows at most 64 prepared segments; no heap storage is owned. Timeline validation rejects a positive duration whose addition cannot advance its boundary. Once mode permits all-cut rails; Loop requires positive total duration. The maximum total duration is consequently 64*3600 seconds. Loops need not join geometrically: every seam is an explicit presentation cut.
- Supplied time is finite/nonnegative f64 seconds since rail start; it is not a delta and never reads a clock. Queries may seek backward, to the same time or over many loops. Once clamps to the last key and reports finished. Boundaries are right continuous: all zero-duration cuts at a time apply before the following timed segment starts. End-of-rail cut chains select their final key. Loop uses remainder and reports absolute cycle count, not a queue of elapsed events. Loop counts >=2^53 reject before casting; overflowing time/duration quotients reject too.
- Loop phase/count follow the supplied binary f64 values without epsilon snapping. A fused residual corrects division rounding at an integer quotient so count agrees with remainder: stored 0.1-second duration places supplied 1.0 seconds just before cycle 10. The next representable time enters cycle 10. Source time precision already lost by the caller cannot be recovered.
- Raw samples flag cuts at rail start, exact cut boundaries, loop seams and reduced-motion selection. `looped` is an exact seam observation for raw samples. `RailPlayer3` additionally detects backward seeks, skipped authored cuts and any cycle change; its looped flag reports crossed loops, including multiple skipped loops. These are presentation observations, never authoritative gameplay events, collision evidence, reward/lap counts or a fabricated Frame3.
- Player starts empty; first successful sample cuts and advances its wrapping discontinuity generation. Hold preserves the last displayed observation (including its flags) and discards valid supplied time; an empty hold permits initialization. Resume does not advance/rebase time: the host must keep a frozen/rebased playhead. Reset forgets display/time, releases hold and advances generation. Repeated identical samples do not repeatedly advance generation. Seeking back from finished or reduced-motion selection cuts to prevent stale interpolation.
- Reduced motion returns the exact final authored key immediately as a finished cut, even for loops, and overrides/releases player hold. Time must still be finite/nonnegative. No motion setting changes look bindings/tuning, simulation or independent flash policy.
- Every player failure leaves display/time/hold/generation unchanged. Batch queries use two deterministic passes (validate all, then write) over immutable geometry; all errors, including late numerical failures, leave the entire destination unchanged. Success writes exactly the requested prefix and retains its unused tail. Up to 1024 times per batch; empty batches succeed. A query scans at most 64 segment descriptors and at most one Route3 binary search; batch work is bounded by twice the requested times. Tessellation caps scratch at 4096 points and work at 8191 nodes, retaining the existing curve depth ceiling.
- As with Transition3, valid endpoints cannot guarantee every intermediate reconstructed target fits f32 or the minimum view distance. Transition reconstruction and path relocation failures return `RailError::NumericalLimit` atomically. Orientation progress rounds to f32; curve/route progress is f64. Interior normalized transition deltas are capped below 0.25 to avoid prematurely returning the final authored pose after f32 rounding. Exact endpoint queries bypass reconstruction. This is conservative: the intermediate linear-eye Transition3 reconstruction may fail before path relocation even if another construction could be representable. No bitwise determinism or frame-time benchmark is claimed.

## Exact public API

All declarations below are in `ferravex_play::camera::rail`; signatures are excerpts, not an additional example to compile. Private fields are intentionally omitted.

```rust
pub const MAX_RAIL_SEGMENTS: usize = 64;
pub const MAX_RAIL_SAMPLES: usize = 1024;
pub const MAX_RAIL_TESSELLATION_WORK: usize = 8191;

pub struct RailKey3 {
    pub pose: Pose3,
    pub projection: Perspective3,
}
pub enum RailPath3<'a> {
    Cut,
    Cubic(CubicBezier3),
    Route(&'a Route3),
}
pub enum RailMode { Once, Loop }
#[non_exhaustive]
pub enum RailError {
    Capacity, InvalidTime, InvalidCut, InvalidPath, Disconnected,
    InvalidTimeline, NumericalLimit,
    Transition(TransitionError), Curve(CurveError), Route(NavigationError),
    IncompleteCurve(TessellationStatus),
}

pub fn tessellate_route_into(
    curve: CubicBezier3,
    route: &mut Route3,
    scratch: &mut [Vec3],
    options: TessellationOptions,
) -> Result<Tessellation, RailError>;

pub struct RailSegment3<'a> { /* private */ }
impl<'a> RailSegment3<'a> {
    pub fn new(path: RailPath3<'a>, start: RailKey3, end: RailKey3,
        seconds: f64) -> Result<Self, RailError>;
}

pub struct RailSample3 {
    pub pose: Pose3,
    pub projection: Perspective3,
    pub segment: usize,
    pub cycle: u64,
    pub looped: bool,
    pub cut: bool,
    pub finished: bool,
}

pub struct Rail3<'a> { /* private */ }
impl<'a> Rail3<'a> {
    pub fn new(segments: &'a [RailSegment3<'a>], mode: RailMode)
        -> Result<Self, RailError>;
    pub fn duration(&self) -> f64;
    pub fn sample_at(&self, seconds: f64, reduced_motion: bool)
        -> Result<RailSample3, RailError>;
    pub fn sample_into(&self, times: &[f64], reduced_motion: bool,
        output: &mut [RailSample3]) -> Result<usize, RailError>;
}

pub struct RailPlayer3<'a> { /* private */ }
impl<'a> RailPlayer3<'a> {
    pub fn new(rail: Rail3<'a>) -> Self;
    pub fn displayed(&self) -> Option<RailSample3>;
    pub fn generation(&self) -> u64;
    pub fn is_held(&self) -> bool;
    pub fn hold(&mut self) -> bool;
    pub fn resume(&mut self) -> bool;
    pub fn reset(&mut self);
    pub fn sample_at(&mut self, seconds: f64, reduced_motion: bool)
        -> Result<RailSample3, RailError>;
}
```

Every type is Clone+Copy. RailKey3/RailSample3 derive Debug+PartialEq. RailMode/RailError derive Debug+PartialEq+Eq. RailError implements Display, std::error::Error and `From<TransitionError>` (NumericalLimit maps to the direct rail variant). Path/segment/rail/player retain no heap-owned collections.
