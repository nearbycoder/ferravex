## Concrete behavior and compatibility

`replace_collider_shape` reads only the shape from an existing collider or
collider builder, avoiding a duplicate public shape representation. Incoming
pose, density, material, layers, sensor status and parent are deliberately ignored.
The destination retains those settings, its generational collider identity,
parent/body identity, child order and local/world authored pose.

Preflight order: collider/parent handle, candidate shape/dimension and retained
settings, entire resulting dynamic compound mass/inertia, both collider/body
revision capacities. Errors occur before any live mutation, including before
mass changes, wake requests, dirty flags, cache edits or pending density cleanup.
A stale handle cannot edit the replacement in its old slot. Handles retain the
existing same-world requirement and do not encode world identity.

- Geometry uses the existing validator and primitive/mass kernel: finite positive
  ball/box dimensions; valid capsule endpoints/radius; dimension-valid cylinders.
  A cylinder passed from d3 to d2 is rejected even on fixed bodies.
- Dynamic compounds require positive finite mass and representable inverse
  mass/inertia. Zero-density children are accepted if another child supplies
  valid mass; sensors contribute mass as before. Underflow/overflow is rejected.
  Fixed/kinematic bodies can retain zero density and skip dynamic mass calculation.
- The dynamic calculation includes every existing child and pending density
  changes. Success commits the compound mass once and clears its mass-dirty
  flags through existing `apply_mass`; a later refresh does not apply it twice.
- Matches existing attach/remove/local-pose conventions: authored body origin,
  body-origin point velocity and angular velocity are preserved. Changing COM
  shifts stored world-space COM velocity by `angular_velocity.cross(new_COM -
  old_COM)`. Linear/angular momentum is not preserved. Body orientation, damping,
  gravity scale, CCD, forces/torque and queued kinematic targets remain intact.
- Every success, including identical geometry, advances collider/body revisions
  exactly once, marks the collider/body solver state dirty and wakes the edited
  body. Contact revisions prevent stale feature/impulse reuse; attached joint
  rows clear during the existing pre-solve refresh. Other bodies' independent
  caches remain intact. Mass edits can invalidate contacts of sibling children
  on the same body, following existing mass-edit conventions.
- Old contacts/events/manifolds remain last-step snapshots until the next valid
  step. That step wakes previous solid contact islands and new solid contacts;
  sensor overlaps do not wake unrelated bodies. Removed overlap pairs emit one
  ordinary stop event; replacements do not synthesize lifecycle events.
- Raycasts, spherecasts and direct point/sphere overlap queries see the new
  geometry immediately, with current body/child poses and the same collider ID.
  No step or query refresh is required by the operation.
- No body/child/collider identity or collection entry is inserted/removed, and
  the implementation allocates no storage. It works at 4096 bodies, 32 children
  and 16384 colliders. Existing capacity failures of attach/insert are preserved.

Existing public struct layouts, exhaustive enums (including `PhysicsError`),
constructors, setters, wire/save/replay formats and default simulation behavior
are unchanged. Existing legacy constructors can still panic before the call;
use checked `ColliderBuilder::try_*` for untrusted numeric authoring. Arbitrary
caller-defined `Into<Collider>` execution is outside the operation's transaction
and allocation guarantee. No dependency was added.

## Exact public API and registration

Defined on the existing registered generic world in `world/compounds.rs`:

```rust
impl<B: body::Access> World<B> {
    pub fn replace_collider_shape(
        &mut self,
        id: ColliderHandle,
        geometry: impl Into<Collider>,
    ) -> Result<(), ColliderShapeError>;
}
```

This method is callable on both `d2::PhysicsWorld` and `d3::PhysicsWorld` through
their existing DerefMut to `RawPhysicsWorld`, just like attach/remove/pose edits.
Both dimensional `ColliderBuilder` types already implement `Into<Collider>`;
no new public shape enum or conversion API was necessary.

Defined in `body.rs`, publicly reexported from **both** `d2` and `d3` via api.rs:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum ColliderShapeError {
    InvalidHandle,
    InvalidCollider,
    InvalidMass,
    RevisionExhausted,
}
// Implements std::fmt::Display and std::error::Error.
```

Only private seam change: existing `Shape::check_dimensions(self, planar: bool)
-> Result<(), BodyValidationError>` is now `pub(crate)` so the compound edit can
reuse authoring validation for non-dynamic geometry too.

**No required parent root registration, world.rs helper or manifest edit.** The
existing world module registers compounds.rs, and both dimensional modules
include api.rs. External tests and doctests call the actual production methods.
Optional parent root convenience export: add `ColliderShapeError` to the existing
