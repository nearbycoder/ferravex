## Concrete behavior

Point and ball/circle probes need no direction, cast endpoint, physics step or
query refresh. They reuse `geometry::distance` against current body/child poses
and existing supported collider shapes. There is no new collision kernel,
arbitrary-convex probe API or broadphase.

`QueryOptions::max_distance` means maximum signed surface separation for these
new APIs. Zero includes penetration and exact touching; positive values include
nearby separated surfaces. No solver contact margin is added. Layers use collider
membership (not its response filter), sensor policy is shared with casts, and an
ignored generational body excludes every compound child. Removed ignored handles
do not exclude reused body slots. Each child returns its own collider/body IDs.

`separation > 0` is a gap, zero is touching, and negative separation is
penetration. The unit outward normal is an exit direction for the probe. The
collider witness lies on the target boundary; the probe witness lies on the ball
boundary (or is the point itself). Within floating-point rounding:

```text
probe_point - collider_point = normal * separation
penetration_depth = max(-separation, 0)
```

For penetration, moving the candidate by `normal * penetration_depth()` brings
it to touching this single convex child. Compound children do not define a
combined depenetration solution. At nonunique exits (ball centers, box face ties,
capsule medial segments, cylinder axes), the existing kernel chooses a stable
valid normal rather than claiming a unique gradient.

Results retain the smallest signed separations: deepest penetration, touching,
then nearest positive gaps. Equal separations prefer later world iteration order,
as existing nearest casts do. Buffer insertion is bounded by caller capacity;
all accepted children count toward `total`, including after capacity is exhausted.
Zero capacity counts only, exactly-full output is not truncated, success clears
unused entries, and invalid input preserves the entire buffer. Nearest wrappers
use one stack slot and return `None` for either errors or a valid miss.

Validation order is finite origin/center, finite nonnegative maximum separation,
then finite radius in `0..=1000`. Existing `QueryError` variants suffice;
direction/endpoint validation is intentionally absent. Nonrepresentable geometry
or witnesses are omitted, matching existing casts' finite-output convention.

## Exact public APIs

The following are independently reachable through both
`ferravex_physics::d2` and `ferravex_physics::d3`; `DIM` means 2 or 3 below.
This is a signature reference, not a standalone runnable snippet.

```rust
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct OverlapHit {
    pub body: Option<RigidBodyHandle>,
    pub collider: ColliderHandle,
    pub separation: f32,
    pub collider_point: [f32; DIM],
    pub probe_point: [f32; DIM],
    pub normal: [f32; DIM],
}
impl OverlapHit {
    pub fn penetration_depth(self) -> f32;
}
impl PhysicsWorld {
    pub fn overlap_point_with_options(
        &self, point: [f32; DIM], options: QueryOptions,
    ) -> Option<OverlapHit>;
    pub fn overlap_sphere_with_options(
        &self, center: [f32; DIM], radius: f32, options: QueryOptions,
    ) -> Option<OverlapHit>;
    pub fn overlap_point_into(
        &self, point: [f32; DIM], options: QueryOptions,
        output: &mut [Option<OverlapHit>],
    ) -> Result<QueryReport, QueryError>;
    pub fn overlap_sphere_into(
        &self, center: [f32; DIM], radius: f32, options: QueryOptions,
        output: &mut [Option<OverlapHit>],
    ) -> Result<QueryReport, QueryError>;
}
```

## Compatibility and geometry corrections

Existing cast signatures, `RayHit`, `QueryOptions` fields/defaults, exhaustive
`QueryError`/`SensorPolicy` variants, wire/save/replay formats and simulation
mutation APIs are preserved. Casts still require nonzero directions even for
zero travel. Shared filtering was extracted without changing its predicates.

Two narrow kernel corrections are required for truthful surface witnesses:

- Box exterior detection tests a nonzero displacement rather than a squared
  epsilon. Tiny exterior corner gaps now have positive distance and the correct
  diagonal normal instead of being misclassified as touching.
- Capsule projection uses wider scalar intermediates and no minimum-length
  cutoff, preserving very short segments. On the exact medial segment the
  normal is perpendicular to the segment; the prior universal Y fallback could
  point axially and fail to reach a boundary. Coincident endpoints retain the
  point/ball fallback. These fixes also improve the shared contact/cast kernel
  at those degeneracies; no claim of bitwise unchanged degenerate normals.

Two compiling and executed first-party rustdoc recipes live in owned `api.rs`:

- `PhysicsWorld::overlap_point_into`: 2D proximity to a box, positive separation,
  exact target/probe witnesses and bounded report.
- `PhysicsWorld::overlap_sphere_into`: 3D placement preview, inspect penetration,
  move only the candidate along the accepted normal, then requery touching and
  confirm that no body was created/moved. This calls the nearest sphere wrapper
  and `OverlapHit::penetration_depth` too. Point nearest use is externally tested.

Run them with `cargo test -p ferravex-physics --offline --locked -j 2 --doc`.
They are Rustdoc executable examples, not unexecuted guide excerpts. Consumers
can use `QueryOptions::new(0.)` for placement rejection or positive distance for
nearby-surface previews, inspecting `report.is_truncated()` before making a
whole-set decision. Do not interpret one child's displacement as a safe world
placement or feed preview queries into body mutation without application policy.
