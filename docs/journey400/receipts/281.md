## Concrete behavior, bounds and compatibility

`Ui::compose` grants only `&mut UiComposition`, not `&mut Ui`. Its submission
methods forward to existing production commands, preserving each command's
validation, styles, clipping, storage charges and atomic rejection. Existing
`Ui` methods/signatures/defaults/public literals/exhaustive enums are unchanged.
No fields or persistent allocations were added to `Ui`; its reserved storage
accounting is unchanged by transaction support.

Success commits all commands and returns the callback value. Any direct
submission error poisons that group: the first error is retained even if
ignored, later submissions do not execute, and a later callback error cannot
replace it. A callback `Err` also rolls back. Ordinary rejection restores:

- Command/text lengths and estimated vertices.
- The entire fixed 16-entry clip stack and entry depth, including overwritten
  inactive slots.
- Inspection full-label arena **and** sidecar lengths, including metadata-only
  `UiLabel::Unavailable` misses. Prior source ranges remain valid; later command
  indexes can be reused. Inspection enable/active state is preserved because
  configuration/lifecycle operations are absent from the facade.
- `modal_start`, `modal_blocker` and the exact prior widget registry/order.
  Previously discarded scopes keep their paint/inspection commands without
  regaining interaction registration; reused IDs remain disambiguated by scope.

Focus/capture, activation/hover, interaction ownership/summary and input
bookkeeping are unchanged by composition; input is never delivered there.
Rollback never calls `end_frame`, so prior focus/capture survive even while
rebuilding registrations. Prior widgets remain navigable/activatable after
rejection. Rejected paint and hit regions disappear together.

Clips must balance within each group. `UiComposition::pop_clip` returns an error
when attempting to remove an inherited clip (unlike the existing unrestricted
`Ui::pop_clip`, whose signature/behavior are untouched). Unbalanced successful
callbacks reject with `InvalidLayout`. An already-returned callback error is
preserved instead of being replaced by the unbalanced-clip error.

Nested groups restore their own checkpoint before returning. Their errors may
be handled by submitting a local fallback in the parent; a propagated `?`
rejects every enclosing group. Successful children also disappear if a later
parent operation fails. Maximum active depth is **16 including the outermost**;
depth 17 returns `Capacity` without invoking its callback. This nesting error
can likewise be handled locally. Direct submission errors in a parent suppress
later nested callbacks.

Each checkpoint stores scalar offsets plus one fixed clip array on the stack.
No arena clone, allocation, persistent transaction object or widget undo journal
is used. Repeated destructive modal calls retain only the current registry;
rollback reconstructs at most 1024 widgets in their existing reserved buffer.
Because existing `UiState::add` checks duplicate IDs by scanning, restoration
is worst-case quadratic within that fixed 1024-widget bound. No timing or frame
rate guarantee is claimed. There is no hidden bound on caller callback work;
callers still own iteration/formatting cost and captured data.

A drop guard also restores this UI during Rust panic unwinding and propagates
the panic. It does not catch panics or promise recovery from abort/allocation
failure. Callback/formatter side effects outside this UI remain; formatting
arguments are still evaluated by the caller. Lifecycle, settings, focus changes,
input delivery, painting and a mutable `Ui` escape are not available through
the facade. Indirect global input/paint/game/scroll mutations performed by a
callback are outside rollback and should be kept outside composition.

## Exact additive public API

These are signature excerpts, not a standalone program. Existing types retain
their public import paths under `ferravex_render::ui`; `LineLimit` and
`TextBlockMetrics` remain under `ui::text_layout`, and `Color` is the existing
renderer type.

```text
pub struct UiComposition<'a> { /* private fields */ }

impl Ui {
    pub fn compose<R>(
        &mut self,
        build: impl FnOnce(&mut UiComposition<'_>) -> Result<R, UiError>,
    ) -> Result<R, UiError>;
}

impl UiComposition<'_> {
    pub fn compose<R>(
        &mut self,
        build: impl FnOnce(&mut UiComposition<'_>) -> Result<R, UiError>,
    ) -> Result<R, UiError>;
    pub fn push_clip(&mut self, rect: UiRect) -> Result<(), UiError>;
    pub fn pop_clip(&mut self) -> Result<(), UiError>;
    pub fn modal(&mut self, blocker: WidgetId) -> Result<(), UiError>;
    pub fn panel(&mut self, rect: UiRect, color: Color) -> Result<(), UiError>;
    pub fn gradient(&mut self, rect: UiRect, left: Color, right: Color) -> Result<(), UiError>;
    pub fn text_fmt(&mut self, rect: UiRect, style: TextStyle,
                    args: std::fmt::Arguments<'_>) -> Result<(), UiError>;
    pub fn text(&mut self, rect: UiRect, text: &str, style: TextStyle) -> Result<(), UiError>;
    pub fn wrapped_text(&mut self, rect: UiRect, text: &str, style: TextStyle,
                        limit: LineLimit) -> Result<TextBlockMetrics, UiError>;
    pub fn label(&mut self, rect: UiRect, text: &str, style: TextStyle) -> Result<(), UiError>;
    pub fn button(&mut self, id: WidgetId, rect: UiRect, text: &str,
                  enabled: bool, style: ButtonStyle) -> Result<(), UiError>;
    pub fn hud_button(&mut self, id: WidgetId, rect: UiRect, text: &str,
                      enabled: bool, style: ButtonStyle) -> Result<(), UiError>;
    pub fn button_with_options(&mut self, id: WidgetId, rect: UiRect, text: &str,
                               options: ButtonOptions, style: ButtonStyle) -> Result<(), UiError>;
    pub fn hud_button_with_options(&mut self, id: WidgetId, rect: UiRect, text: &str,
                                   options: ButtonOptions, style: ButtonStyle) -> Result<(), UiError>;
}
```
