Legacy `award(base) -> u64` still returns nominal points, even if total saturates.
It delegates to `award_with_receipt`, which explicitly saturates each integer
counter and reports lost increments separately. `try_award` instead rejects
atomically if either chain increment or total addition overflows: **all fields**,
including remaining time and best, remain unchanged. It does not undo an action
already accepted in another system. Use the saturating receipt path when such an
action must retain legacy scoring. Multiplication cannot overflow `u64`: base is
`u32` and the authored multiplier cap remains `1..=100`.

Receipts distinguish nominal points from `total_after - total_before`. A counter
merely reaching its maximum does not set a saturation flag. At maximum total a
nonzero saturating award still advances/caps chain, updates best, refreshes its
window, and reports zero actual score increase. A zero base returns no receipt,
changes nothing and cannot refresh a chain, even at both integer bounds.

Tier is one-based, calculated from the resulting (possibly saturated) chain
**before** the multiplier cap. Multiplier is `min(tier, maximum)`. No defaults or
authored game formulas changed. `ScoreChain`'s existing fields/layout and all
`LoopError` variants are unchanged; no existing exhaustive enum is extended.

`advance` delegates to `advance_with_outcome`. Expiry still uses the exact
inclusive internal `f64` comparison `remaining <= 1e-9`, including on zero delta.
`Expired { chain }` occurs once per expired chain, retains total/best, and clears
chain/time. Idle advancement returns `Idle`; surviving chains return `Active`.
Non-finite, negative or greater-than-3600-second deltas leave every field unchanged.
Inspection/preview never advances or refreshes timing, even at/below epsilon.

Reset policies all retain `window`, `per_tier` and `maximum`:

| Mode | chain | remaining | total | best |
| --- | --- | --- | --- | --- |
| `ChainOnly` | clear | clear | retain | retain |
| `Run` | clear | clear | clear | retain |
| `All` | clear | clear | clear | clear |

`break_chain()` is exactly `reset(ChainReset::ChainOnly)`. Resets are idempotent.

## Runnable first-party accepted-action composition

This headless training recipe deliberately rewards an **accepted shot**, using
the existing `Magazine::fire` rule, rather than claiming a hit or a win. It uses
actual `GameSession`, input-edge consumption and fixed updates. The four slots
match the authored catch-up bound; feedback is retained only for actual accepted
awards. Preview is never used as feedback. Local pause below represents a local
single-player session; network/replay authority must keep its own ticks running
while an overlay suppresses local commands.

```rust,check crate-type=bin
use ferravex_core::session::GameSession;
use ferravex_play::gameplay::{
    combo::{ChainReset, ScoreAward, ScoreChain}, magazine::Magazine,
};
use ferravex_play::input::{ActionMap, Binding, InputCode};

fn main() {
    let mut session = GameSession::try_new(64.0, 4, true).unwrap();
    let mut input = ActionMap::default();
    let code = InputCode::Key(32);
    let shoot = input.try_action(vec![Binding::digital(code)]).unwrap();
    let mut magazine = Magazine::new(2, 0, 1.0).unwrap();
    let mut score = ScoreChain::new(0.125, 1, 3).unwrap();

    let frame = |elapsed: f64, session: &mut GameSession, input: &mut ActionMap,
                 magazine: &mut Magazine, score: &mut ScoreChain| {
        let issued = session.advance(elapsed);
        let mut executed = 0_usize;
        let mut feedback: [Option<ScoreAward>; 4] = [None; 4];
        for dt in issued.ticks() {
            if !session.is_playing() { break; }
            score.advance_with_outcome(dt).unwrap();
            magazine.advance(dt).unwrap();
            let edge = input.consume_tick(shoot);
            if edge.pressed && magazine.fire() {
                // Authored reward is 10 per accepted shot; this is not a hit claim.
                feedback[executed] = score.award_with_receipt(10);
            }
            executed += 1;
        }
        (issued.steps, executed, feedback)
    };

    input.feed(code, 1.0);
    input.feed(code, 0.0); // Quick tap survives the zero-tick frame.
    let (issued, executed, feedback) = frame(0.5 / 64.0, &mut session,
        &mut input, &mut magazine, &mut score);
    assert_eq!((issued, executed), (0, 0));
    assert!(feedback.iter().all(Option::is_none));
    assert_eq!(score.remaining_life(), None);

    let (issued, executed, feedback) = frame(2.0 / 64.0, &mut session,
        &mut input, &mut magazine, &mut score);
    assert_eq!((issued, executed), (2, 2));
    let first = feedback[0].unwrap();
    assert_eq!((first.nominal_points, first.total_change), (10, 10));
    assert!(feedback[1..].iter().all(Option::is_none)); // No repeated tap.
    assert_eq!(score.remaining_life(), Some(0.125 - 1.0 / 64.0));

    input.feed(code, 1.0);
    let (_, _, feedback) = frame(1.0 / 64.0, &mut session,
        &mut input, &mut magazine, &mut score);
    let second = feedback[0].unwrap();
    assert_eq!((second.tier, second.multiplier, second.total_change), (2, 2, 20));
    assert_eq!((magazine.loaded(), score.total()), (0, 30));

    input.feed(code, 0.0);
    input.feed(code, 1.0); // A fresh request rejected by the now-empty magazine.
    let (_, _, feedback) = frame(1.0 / 64.0, &mut session,
        &mut input, &mut magazine, &mut score);
    assert!(feedback.iter().all(Option::is_none));
    assert_eq!((score.chain(), score.total()), (2, 30));
    assert_eq!(score.remaining_life(), Some(0.125 - 1.0 / 64.0));

    assert!(session.set_paused(true));
    let remaining = score.remaining_life();
    let (issued, executed, feedback) = frame(30.0, &mut session,
        &mut input, &mut magazine, &mut score);
    assert_eq!((issued, executed), (0, 0));
    assert!(feedback.iter().all(Option::is_none));
    assert_eq!(score.remaining_life(), remaining);

    session.restart();
    input.suppress_held(); // Discard edges and require held buttons to release.
    magazine = Magazine::new(2, 0, 1.0).unwrap();
    score.reset(ChainReset::Run); // A new run retains the session's best chain.
    assert_eq!((score.chain(), score.total(), score.best()), (0, 0, 2));
    assert_eq!(score.remaining_life(), None);
    let (_, executed, feedback) = frame(2.0 / 64.0, &mut session,
        &mut input, &mut magazine, &mut score);
    assert_eq!(executed, 2);
    assert!(feedback.iter().all(Option::is_none));
    assert_eq!(magazine.loaded(), 2); // Reset did not replay the old edge.
}
```

## Consumer inspection and handoff

- Orbit: `examples/owned-orbit/src/game.rs::hit_block` already calls
  `chain.award(if destroyed { 100 } else { 25 })` after accepted block damage,
  then saturates a **separate u32** `score` and sends `AcceptedEvent::Panel`.
  Authoring is `(4.0, 3, 4)` and chain advancement already occurs in `tick`.
  Parent can replace that single award call with `award_with_receipt` while
  preserving the nominal game addition and formula. Critically, helper
  `total_change` is a u64 counter's change, not necessarily the separate u32 game
  counter's change. Capture game score before/after its existing saturating add
  for truthful panel feedback at u32 saturation. Do not cast/recompute a UI
  award independently or claim that this patch changes `AcceptedEvent::Panel`.
- Pinball: `examples/salvage-pinball/src/lib.rs::Table::step` awards flat 100
  only on newly accepted bumper contact after its existing contact/cooldown gate.
  It does **not** use `ScoreChain`; `game.rs::Pinball::advance` already reports
  accepted aggregate points from actual table score deltas. Preserve those
  defaults and gates. A parent-authored optional chain mode could feed accepted
  contact awards into this helper and retain receipts, but must explicitly
  define the game's total authority/narrower counter policy first. This patch
  does not implement that mode or change Pinball scoring/overflow behavior.
- Emberline and Neon Swarm also already use `ScoreChain` for accepted kills;
  their callers/formulas are unchanged. No event IDs, deduplication, callback
  execution, game-rule speculation, renderer or wall-clock ownership is added.
