pub fn draw_residents_checked(
    instances: &[(&ResidentMesh, Mat4)],

#[must_use]

pub struct InstanceGroupReport {

    pub rejected: usize,

`InstanceGroupError` implements `Display` and `std::error::Error`; `source()`
returns the contained existing `DrawError`. Its index is zero-based in the input.
`InstanceGroupReport::default()` is an empty successful report. No new public
methods, enum variants, ABI exports, configuration fields or feature gates.
The private `Frame::prepare_draw_at` shares the existing draw-validation path
while permitting the group to preflight its aggregate demand separately.

## Concrete behavior and compatibility

- The borrowed caller slice can refer to different resident meshes, duplicates
  of one handle, or cloned handles. Handles keep already-validated immutable
  geometry alive; the API takes no forgeable raw mesh identities and does not
  register/revalidate/copy source geometry. Duplicate pairs mean separate
  instances, never deduplication.
- Preflight uses the existing model/camera/palette validation with no frame
  writes. All entries, including invisible ones, must validate. The first
  validation error in input order wins over aggregate capacity, even if an
  earlier entry would have exhausted capacity. A skinned resident requiring
  joints is rejected with the existing `SkinPaletteMismatch`; this static group
  API supplies no skin palette.
- A read-only classification determines exact storage demand under current
  padded mesh bounds, visibility/frustum/distance and shadow-caster rules.
  Visible and shadow-only instances each cost one slot; complete culls cost
  zero. If demand exceeds remaining capacity, the error identifies the first
  input entry that would require an unavailable slot. A full frame may therefore
  still accept a fully culled group. Empty input returns success immediately,
  including with an invalid current camera, without touching renderer state.
- Validation/capacity failure accepts zero, rejects the **entire caller slice**,
  reports zero visible/culled, and changes no frame buffer contents, lengths,
  capacities, allocation addresses, retained mesh/material references or
  visibility counters. The one intentional side effect is incrementing one
  existing rejection activity counter for the selected error category.
- Rejection telemetry is **one failed operation**, saturating at `u64::MAX`,
  rather than one increment per rejected entry. The report's `usize` counts are
  exact, nonsaturating slice/record counts. `accepted + culled + rejected` equals
  the input length, and `visible <= accepted`. `accepted` includes shadow-only
  records; `culled` means omitted from both passes. Counters survive frame
  clears; `reset_telemetry` leaves buffers alone, as before.
- Once preflight succeeds, commit calls the existing `State::submit` for every
  entry. Normal visible/shadow flags, material/light/parameter capture, adjacent
  merging, immediate ordering barriers, geometry/material retention and later
  opaque finalization remain owned by the existing recorder. Culling activity
  is counted only during commit, once per entry, never during preflight.
- O(n) preflight, O(1) stack storage, no heap scratch. Commit repeats validation
  and classification, trading extra work for allocation-free warmed submission.
  Caller slice length bounds work; no new hidden work limit is imposed. Ordinary
  successful buffer growth remains possible. Existing buffer clearing and
  double-buffer finalization preserve warmed storage.
- Atomicity is for reported validation/capacity failures. Allocation failure,
  unwinding or destructor panics have **no rollback guarantee**. No callback,
  wall clock, platform I/O or simulation ownership was added.
- Single-instance signatures, validation precedence/arithmetic and behavior are
  preserved. `RetainedBatch` remains 224 bytes; instance records remain 28 floats
  (112 bytes), with the existing model and inverse-transpose layout. No shader,
  wire/save/replay, native/Wasm export or existing exhaustive public-type change.
- Task 216 is composed in the runnable recipe, not substituted into legacy
  inverse validation. The existing full-inverse requirement deliberately still
  rejects a finite model with an overflowing inverse translation even when
  `PreparedAffine3D` accepts its linear inverse. A regression covers this exact
  compatibility boundary, plus reflected/nonuniform/sheared normal records.

## Consumer handoff

The complete `fn main() -> Result<(), Box<dyn std::error::Error>>` rustdoc recipe
on `draw_residents_checked` (`retained.rs:548`) compiled **and executed** through
Cargo doctests. It prepares an authored mirrored/nonuniform model with the
registered `PreparedAffine3D`, creates one resident cuboid snapshot and a cloned
handle, passes a stack array of mesh/model pairs, inspects exact report counts,
rejects a group with a late invalid model without adding records, clears the
frame and successfully reuses storage. It requires no window or graphics device.

First-party consumers can retain their mesh handles and authored defaults,
build a per-frame caller array/slice, select their existing camera/material,
and call `retained::draw_residents_checked(&pairs)` in the current rendering
frame. Handle `report.error` before deriving feedback from `report.accepted` or
`report.visible`. Complete culls are `report.culled`, not failures. Skinning
continues through existing palette-aware APIs. No game or custom software host
was migrated or replaced as part of this task.
