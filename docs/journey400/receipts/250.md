## Concrete behavior and compatibility

Legacy `SpawnSelector::new` and `choose` retain their signatures, minimum range `0..=1e6`, 1–256 candidate limit, whole-request geometry errors, f32 squared distances, conditional eligibility-query pruning and rotating stable index ties. There is no seeded bag/seed API: the Journey400 proposal's seeded wording does not describe the existing implementation. No existing public enum, struct fields, formats, defaults or platform exports changed.

Checked assessment distinguishes:

- Whole-request invalidity: empty input, over 256 entries, invalid reference or insufficient caller output. In that priority order, before external queries.
- Individual first exclusion: invalid Vec2 geometry (nonfinite or any absolute component >1e6), distance strictly below minimum, unavailable slot, authored score rejection, or obstruction/LOS rejection. All-invalid/excluded candidates return `Ok(None)` and complete diagnostics, never a fabricated location.
- Numeric failure: a nonfinite score returns `InvalidScore { index }`, aborting the whole call. All finite scores, including negative values and finite extremes, are supported. Bounded coordinate/minimum ranges make the existing squared-distance arithmetic finite (at most 8e12); no new distance arithmetic/units were introduced.
- External failure: `Callback { index, query, error }` preserves the caller's original error and identifies availability, score or obstruction.

Assessment uses the current cursor, visiting `(cursor + offset) % input_len` once per candidate. Geometry and minimum-distance checks precede availability, then score, then obstruction. Each later query is skipped after an exclusion; a callback or numeric failure stops the whole traversal. Each callback has at most 256 calls (768 total maximum). Checked assessment deliberately queries all surviving candidates, including lower-ranked ones, unlike legacy best-so-far callback pruning. Query effects/allocations/panics belong to callers and cannot be rolled back.

The score callback receives source index and squared distance. `Ok(None)` excludes under authored policy, `Ok(Some(finite_score))` ranks highest first. Equal scores, including signed zero, keep the first source identity in rotating traversal order. Dynamic scores carry no client authority. Output is in source index order; indices identify this input slice only, so reorderings change identity.

`assess_into(&self, ...)` never rotates. `choose_checked_into(&mut self, ...)` rotates to `(selected + 1) % input_len` only after successful `Ok(Some(selected))`. `Ok(None)` and reported errors preserve cursor state. `reset` explicitly restores cursor zero and retains the authored minimum; changing input length otherwise wraps the existing cursor modulo the new length, as before.

Caller output must fit every input candidate. A fixed 256-entry stack scratch array stages assessment; success copies only `output[..input_len]`, preserving the tail. Every reported failure preserves the entire output and selector. The APIs allocate no heap storage and require no preparation. Caller callbacks may allocate or have effects, which this contract does not make transactional. Stack cost is bounded by 256 assessment records; small-stack platform integration was not exercised.

## Exact public API

All new names are in `ferravex_play::gameplay::spawn`. Signatures below are excerpts, not runnable examples.

```rust
pub enum SpawnExclusion {
    InvalidGeometry, TooClose, Unavailable, Authored, Obstructed,
}
pub enum SpawnOutcome {
    Excluded(SpawnExclusion),
    Eligible { score: f32 },
}
pub struct SpawnAssessment {
    pub index: usize,
    pub distance_squared: Option<f32>,
    pub outcome: SpawnOutcome,
}
impl SpawnAssessment { pub const EMPTY: Self; }
pub enum SpawnQuery { Availability, Score, Obstruction }
pub enum SpawnCheckError<E> {
    EmptyCandidates,
    CandidateCapacity { count: usize },
    InvalidReference,
    OutputTooSmall { required: usize, provided: usize },
    InvalidScore { index: usize },
    Callback { index: usize, query: SpawnQuery, error: E },
}
impl SpawnSelector {
    pub const MAX_CANDIDATES: usize = 256;
    pub fn assess_into<E>(
        &self, positions: &[Vec2], reference: Vec2,
        output: &mut [SpawnAssessment],
        available: impl FnMut(usize) -> Result<bool, E>,
        score: impl FnMut(usize, f32) -> Result<Option<f32>, E>,
        unobstructed: impl FnMut(usize) -> Result<bool, E>,
    ) -> Result<Option<usize>, SpawnCheckError<E>>;
    pub fn choose_checked_into<E>(
        &mut self, positions: &[Vec2], reference: Vec2,
        output: &mut [SpawnAssessment],
        available: impl FnMut(usize) -> Result<bool, E>,
        score: impl FnMut(usize, f32) -> Result<Option<f32>, E>,
        unobstructed: impl FnMut(usize) -> Result<bool, E>,
    ) -> Result<Option<usize>, SpawnCheckError<E>>;
    pub fn reset(&mut self);
}
```

The unchanged methods remain:

```rust
pub fn new(minimum: f32) -> Result<Self, LoopError>;
pub fn choose(&mut self, positions: &[Vec2], player: Vec2,
    eligible: impl FnMut(usize) -> bool) -> Result<Option<usize>, LoopError>;
```
