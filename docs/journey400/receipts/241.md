## Behavior and compatibility

The original `CommandBuffer<T: Copy>` fields/storage shape and constructor policy remain intact. Capacity stays exactly one command, with no heap allocation in buffer operations. A fresh edge always replaces an occupied slot and resets its full authored life, including equal-valued edges; holding input is not a fresh edge. `push`, `advance` and `take_if` now call their checked counterparts and discard only the extra outcome detail. `clear`, `pending`, clone/copy behavior and all `LoopError` variants are preserved. There are no wire/save/replay or native/Wasm export changes.

`push_checked` returns `Queued` or the displaced value in `Replaced(T)`. `advance_checked` returns `Empty`, `Pending` or the removed value in `Expired(T)`; removal is not cached for a later operation to report again. `take_if_checked` returns `Empty`, `Gated` or `Executed(T)`. Empty takes report `Empty` regardless of the gate. A gated take preserves both command and exact remaining life. `Executed` means handoff to caller execution, not proof that arbitrary external game rules accepted it; feed feedback only after those rules accept. No API takes a speculative callback.

`remaining_life` is a nonconsuming `Option<f64>` in seconds, using internal precision; `None` means empty. Inspection does not advance, expire, refresh or execute. The exact existing inclusive comparison **`remaining <= 1e-9`** is unchanged. Expiry happens only during advancement; a just-pushed positive sub-epsilon lifetime can still be taken before any advance, and zero-delta advancement expires it. Construction still rejects zero and values outside finite `(0, 3600]`; advancement accepts finite `[0, 3600]`, including negative zero. Invalid deltas preserve command, remaining life and configured lifetime even on an empty buffer.

## Exact public API

All additions are reachable through existing `ferravex_play::gameplay::buffer` (both `gameplay` and `buffer` are already public). New enums derive `Clone, Copy, Debug, PartialEq, Eq`, with equality implementations conditional on the payload's equality bounds. No new bound beyond `T: Copy` is required to use the buffer/outcomes.

API signatures (excerpt, not a runnable program):

```rust
pub enum PushOutcome<T: Copy> { Queued, Replaced(T) }
pub enum AdvanceOutcome<T: Copy> { Empty, Pending, Expired(T) }
pub enum ConsumeOutcome<T: Copy> { Empty, Gated, Executed(T) }

impl<T: Copy> CommandBuffer<T> {
    pub fn push_checked(&mut self, command: T) -> PushOutcome<T>;
    pub fn advance_checked(&mut self, dt: f32) -> Result<AdvanceOutcome<T>, LoopError>;

}
```

This runnable first-party recipe is the consumer handoff, requiring only the existing `ferravex-core` and `ferravex-play` library externs. It uses actual `GameSession::advance_batch` tick contexts and `ActionMap::consume_tick`, not an invented clock or buffer. It proves a quick tap survives a zero-tick frame, a terminal transition stops two already-issued updates without aging the command, restart clears pending life, and a held press in three catch-up updates queues and executes only once. The recipe ages old commands before pushing fresh tick edges; this ordering is a host policy, not an automatic behavior change to the buffer. Real `PlayerInput` consumers use the same placement with `let [jump] = input.take_tick(["jump"])` inside the actual update. Local authoritative network/replay hosts must continue their tick loop while gating local commands; the terminal stop here is for a single-player session.

```rust,check crate-type=bin
use ferravex_core::session::GameSession;
use ferravex_play::{
    gameplay::buffer::{AdvanceOutcome, CommandBuffer, ConsumeOutcome, PushOutcome},
    input::{ActionMap, Binding, InputCode},
};

fn main() {
    let dt = 1.0 / 64.0;
    let mut session = GameSession::try_new(64.0, 4, true).unwrap();
    let mut input = ActionMap::default();
    let code = InputCode::Key(32);
    let jump = input.try_action(vec![Binding::digital(code)]).unwrap();
    let mut commands = CommandBuffer::new(4.0 / 64.0).unwrap();

    // Host supplies a quick tap across a frame with zero actual updates.
    input.feed(code, 1.0);
    input.feed(code, 0.0);
    assert_eq!(session.advance_batch(0.5 * dt).ticks().len(), 0);
    assert!(input.peek(jump).pressed);
    assert_eq!(commands.remaining_life(), None);

    let batch = session.advance_batch(3.0 * dt);
    assert_eq!(batch.frame().steps, 3);
    let mut executed = 0;
    for tick in batch.ticks() {
        if !session.is_playing() { break; }
        executed += 1;
        assert_eq!(tick.tick, 1);
        assert_eq!(commands.advance_checked(tick.dt).unwrap(), AdvanceOutcome::Empty);
        let action = input.consume_tick(jump);
        assert!(action.pressed);
        assert_eq!(commands.push_checked(1), PushOutcome::Queued);
        assert_eq!(commands.take_if_checked(false), ConsumeOutcome::Gated);
        // A terminal game rule ends this run during its first actual update.
        assert!(session.finish(true));
    }
    assert_eq!((session.tick(), executed), (3, 1));
    assert_eq!(commands.remaining_life(), Some(4.0 / 64.0));
    assert_eq!(session.advance_batch(30.0).ticks().len(), 0);
    assert_eq!(commands.pending(), Some(1));

    session.restart();
    commands.clear(); // The session does not own gameplay-buffer reset.
    assert_eq!(commands.remaining_life(), None);
    assert_eq!(session.tick(), 0);
    assert!(!input.peek(jump).pressed); // Earlier tap was actually consumed.

    // A held press queues once; an authored landing gate opens on tick three.
    input.feed(code, 1.0);
    assert_eq!(session.advance_batch(0.5 * dt).ticks().len(), 0);
    let batch = session.advance_batch(2.5 * dt);
    assert_eq!(batch.frame().steps, 3);
    let mut queued = 0;
    let mut accepted_jumps = 0;
    for tick in batch.ticks() {
        assert!(session.is_playing());
        executed += 1;
        let aging = commands.advance_checked(tick.dt).unwrap();
        assert_eq!(aging, if tick.batch_index == 0 {
            AdvanceOutcome::Empty
        } else {
            AdvanceOutcome::Pending
        });
        let action = input.consume_tick(jump); // One snapshot per actual tick.
        if action.pressed {
            assert_eq!(commands.push_checked(2), PushOutcome::Queued);
            queued += 1;
        }
        let grounded = tick.batch_index == 2; // Supplied game-rule observation.
        match commands.take_if_checked(grounded) {
            ConsumeOutcome::Gated => assert!(!grounded),
            ConsumeOutcome::Executed(command) => {
                assert_eq!(command, 2);
                assert!(grounded);
                accepted_jumps += 1; // Apply accepted jump; feedback follows here.
            }
            ConsumeOutcome::Empty => panic!("command must survive until landing"),
        }
    }
    assert_eq!((queued, accepted_jumps, executed), (1, 1, 4));
    assert_eq!(commands.remaining_life(), None);
    assert_eq!(commands.take_if_checked(true), ConsumeOutcome::Empty);
    println!("issued 6 ticks across two runs; executed 4; accepted 1 jump");
}
```
