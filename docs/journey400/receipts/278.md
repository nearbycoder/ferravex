## Concrete behavior and compatibility decisions

The adapter returns existing `touch::Control` values, preserving slice index,
explicit authored slot identity, output channels, output kind, floating-stick
policy and first-slot hit priority. Rectangles project their origin and extents;
circles project their center/radius; stick travel radii scale by the same factor.
There is no alternate touch router or renderer dependency in the pure play layer.

`from_viewport` adapts renderer `UiRect`/UI-local geometry through the current
Viewport safe origin and scale. `from_canvas` extracts Emberline's exact rectangle
conversion and Neon's circle/stick conversion from existing Canvas2D fields.
The result is absolute host logical screen pixels. Draw its `Control::region`
under the screen camera, or a zero-inset responsive UI viewport. Never project
it again, add safe offsets twice, or multiply input/layout by framebuffer DPR.

There is **no implicit clipping or enlargement**. This preserves Neon's authored
broad circle/background region extending past the canvas and Emberline's exact
rectangles. Existing touch bounds/output validation is reused through default
`TouchLayoutSettings::apply`, rather than duplicated. MinimumTouchSize defaults
to Preserve; Require(n) explicitly rejects a rectangle's shorter side/circle's
diameter below positive finite n screen logical units (including look regions).
It never silently enlarges a hit region beyond drawing or shrinks text. Consumers
must choose a readable reflow/fallback on error. Saved custom settings retain the
legacy minimum/margins and may move controls outside the original safe area;
this adapter does not silently replace those stored choices with a new policy.

Layouts use a fixed 16-control array and construct atomically. Capacity, slot
order, hidden gaps, invalid controls/settings/transforms and failed minimum
checks are explicit errors. Constructors check source controls even when
suspended. A viewport displayed extent below one logical pixel, or a canvas
screen/displayed-world extent below one, returns an empty layout; install that
empty slice to release previous targets. Canvas invalid fields/overflow are
errors rather than suspension. Recompute from original slots after resize;
identical layouts preserve captures and changed layouts cancel them via existing
PlayerInput/TouchSurface behavior. A raw host resize alone is not claimed to
cancel captures: the consumer must rebuild/install the layout.

Hidden slots are deliberately restricted to a trailing suffix, including hiding
all controls. Every supplied slot ID must equal its original slice index,
including hidden suffix IDs. This matches Emberline's existing four-gameplay /
five-menu prefix behavior. Hidden middle slots return HiddenGap rather than
compacting saved indexes or parking targets offscreen where saved edits could
reactivate them. Hidden suffix edits remain stored and are reapplied at the same
index when those slots become visible again.

`resolve` applies the exact legacy `PlayerInput::set_touch_layout` settings for
drawing: same stable index, same full-screen logical dimensions floored at 64,
same `TouchLayoutSettings::apply`. Install **authored** `controls()` first to load
settings, then resolve/draw with `input.touch_settings()`. Never install the
resolved result (that would apply customization twice). `resolve` rechecks the
requested minimum and existing control validity without mutating the authored
layout or settings. `apply_in_safe_area` remains available but is not inserted
here: its normalized center remapping would apply the already-projected safe
origin again and would differ from PlayerInput's current production contract.

Public struct literals/enums in existing modules, saved touch document format,
wire/save/replay formats, exports, dependencies and feature defaults are unchanged.

## Exact public signatures

All additions are under `ferravex_render::input::touch_layout` (and the existing
facade alias `ferravex::render::input::touch_layout`). Excerpt, not runnable:

```rust
pub struct TouchSlot {
    pub slot: usize,
    pub control: Option<touch::Control>,
}
impl TouchSlot {
    pub fn rect(slot: usize, rect: UiRect, output: touch::Output) -> Self;
    pub fn hidden(slot: usize) -> Self;
}
pub enum MinimumTouchSize { Preserve, Require(f32) } // Default = Preserve.
pub enum TouchGeometryError {
    Capacity, SlotOrder, HiddenGap, InvalidGeometry, BelowMinimum,
}
// TouchGeometryError implements Display and std::error::Error.
// TouchLayout fields are private. All four types implement Clone/Copy/Debug/PartialEq.
impl TouchLayout {
    pub fn from_viewport(viewport: Viewport, slots: &[TouchSlot], minimum: MinimumTouchSize)
        -> Result<Self, TouchGeometryError>;
    pub fn from_canvas(canvas: Canvas2D, slots: &[TouchSlot], minimum: MinimumTouchSize)
        -> Result<Self, TouchGeometryError>;
    pub fn controls(&self) -> &[touch::Control];
    pub fn resolve(&self, settings: touch::TouchLayoutSettings, screen: [f32; 2])
        -> Result<Self, TouchGeometryError>;
}
```

saved edits with original indexes before installing only visible controls,
without reapplying customization at compacted indexes. Renderer-only sentinel
geometry cannot safely satisfy that behavior. Current game adoption above needs
only visible prefixes and requires no such extension.

## Runnable first-party composition recipe

This is a headless recipe, not a browser/visual playtest. It composes task 271
HUD reservations, task 286's canvas adapter, shared draw/hit geometry, saved
customization, and actual PlayerInput journal/tick consumption. Draw calls use
the normal first-party renderer buffers; no window or GPU presentation occurs.

```rust,check crate-type=bin
use ferravex_play::ui::{HudEdge, HudRegions};
use ferravex_render::{
    canvas::Canvas2D, draw_rectangle, set_camera, set_default_camera, vec2, Color,
    input::{ActionKind, Binding, InputCode, PlayerInput, host_frame, touch_event,
        touch::{Event, Output, Phase, Region, TouchLayoutSettings},
        touch_layout::{MinimumTouchSize, TouchLayout, TouchSlot}},
    ui::{UiRect, Viewport},
};

fn main() {
    let screen = [390., 844.];
    let mut hud = HudRegions::new(screen, [10., 24., 12., 16.], [160., 100.]).unwrap();
    let footer = hud.reserve("actions", HudEdge::Bottom, 80.).unwrap();
    let canvas = Canvas2D::from_fit(hud.fit_canvas([1280., 720.]).unwrap().unwrap());
    // Footer coordinates are already absolute. Use zero insets here.
    let slots = [
        TouchSlot::rect(0, UiRect { min: [footer.min[0] + 8., footer.min[1] + 12.],
            size: [56.; 2] }, Output::Button(12)),
        TouchSlot::rect(1, UiRect { min: [footer.min[0] + footer.size[0] - 64.,
            footer.min[1] + 12.], size: [56.; 2] }, Output::Button(3)),
        TouchSlot::hidden(2),
    ];
    let authored = TouchLayout::from_viewport(Viewport::responsive(screen, [0.; 4]).unwrap(),
        &slots, MinimumTouchSize::Require(44.)).unwrap();
    let mut input = PlayerInput::transient("journey400-278-recipe");
    for (name, channel) in [("left", 12), ("jump", 3)] {
        input.action(name, name, ActionKind::Button,
            vec![Binding::digital(InputCode::Touch(channel))]).unwrap();
    }
    let mut settings = TouchLayoutSettings { mirrored: true, ..Default::default() };
    settings.edits[0].offset = vec2(0.02, 0.);
    host_frame(0., 390, 844, || {
        input.set_touch_layout(authored.controls()).unwrap();
        input.set_touch_settings(settings).unwrap();
        input.sample(true);
        set_camera(&canvas.camera());
        draw_rectangle(0., 0., 1280., 720., Color::new(0.1, 0.1, 0.1, 1.));
        set_default_camera();
        let drawing = authored.resolve(input.touch_settings(), screen).unwrap();
        for control in drawing.controls() {
            if let Region::Rect(r) = control.region {
                draw_rectangle(r.x, r.y, r.w, r.h, Color::new(0.2, 0.7, 0.8, 1.));
            }
        }
    });
    let drawing = authored.resolve(input.touch_settings(), screen).unwrap();
    let Region::Rect(button) = drawing.controls()[0].region else { unreachable!() };
    for phase in [Phase::Start, Phase::End] {
        touch_event(Event { id: 278, phase, position: button.center() });
    }
    host_frame(0., 390, 844, || { input.sample(true); }); // Zero simulation ticks.
    host_frame(0., 390, 844, || {
        input.sample(true);
        let [left, jump] = input.take_tick(["left", "jump"]);
        assert!(left.pressed && left.released);
        assert!(!jump.pressed);
        assert!(!input.take_tick(["left"])[0].pressed);
        assert_eq!(input.touch_settings(), settings);
    });
}
```

## Unverified limits

No Wasm compilation, native window/GPU presentation, browser build, screenshot,
physical mobile/DPI, listening, performance benchmark or cross-platform
simulation determinism is claimed. DPR checks are synthetic numeric conversions;
journal events are synthetic host input, not physical or DOM touch. Parent owns
native/Wasm combined integration and fresh game/browser adoption. The adapter
preserves inclusive touch boundary priority, which differs from half-open UI
Rect membership; consumers should use returned touch regions and avoid relying
on both adjacent controls owning a shared edge. Custom layouts can overlap under
existing saved settings; no automatic separation or safe-area rewrite occurs.
