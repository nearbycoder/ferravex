## Exact versioned contract and public APIs

Browser getter: `player.uiPreferencesV1` is a frozen, cached snapshot with exactly:

```js
{version: 1, textScale: 1, contrast: 0}
```

`textScale` is a finite number in inclusive `[1,2]`; current stored/select `text`
values `'0'/'1'` map to `1/1.5`. `contrast` is numeric `0` Normal or `1`
HighContrast; current stored/select contrast strings `'0'/'1'` map to those
indices. No contrast system mode/inference/coercion/fallback palette is used.
Changing only motion/flash leaves this cached UI snapshot unchanged.

The single new Wasm export, identical across all three hosts:

```rust,ignore
pub extern "C" fn ferravex_ui_preferences_v1(
    version: u32,
    text_scale: f32,
    contrast: u32,
) -> u32;
```

Version **must equal 1**. Complete validation, including theme palette/metrics,
precedes publication. Exactly numeric `1` accepts both changed and unchanged
settings; `0` rejects. Hosts require `!==1` to reject all other values (including
true, strings, promises, undefined and other nonzero numbers). Browser validation
runs before Wasm integer/float marshalling. This ABI deliberately excludes
motion/flash; the existing `ferravex_feedback_preferences(motion:u32,flash:u32)
->u32` export, intensity preservation and two-flag numeric success contract are
unchanged. There is no second/combined presentation ABI.

New Rust public surface (`ferravex_render::preferences`):

```rust,ignore
pub const UI_PREFERENCES_VERSION: u32 = 1;
pub struct UiPreferences { /* private fixed-size fields */ }
impl Default for UiPreferences { /* 1x, Normal */ }
impl UiPreferences {
    pub fn from_snapshot(version: u32, text_scale: f32, contrast: u32)
        -> Result<Self, UiPreferenceError>;
    pub fn version(self) -> u32;
    pub fn text_scale(self) -> f32;
    pub fn contrast(self) -> u32;
    pub fn theme(self) -> Result<UiTheme, UiPreferenceError>;
}
pub enum UiPreferenceError { Version, TextScale, Contrast, Theme(ThemeError) }
pub struct UiApplyOutcome { pub changed: bool, pub reflow_required: bool }
pub fn ui_preferences() -> UiPreferences;
pub fn apply_ui_preferences(next: UiPreferences) -> UiApplyOutcome;
pub fn apply_ui_snapshot_v1(version: u32, text_scale: f32, contrast: u32) -> u32;
```

`UiPreferences` derives Clone/Copy/Debug/PartialEq, the error likewise;
`UiApplyOutcome` additionally derives Eq. The error implements Display/Error.
`UiTheme`/`ThemeError` are the existing task290 types. `theme()` explicitly selects
and validates its authored preset, enlarges type sizes, insets, gaps, compact
gaps, control height and stroke together, and calls real `UiTheme::try_new`.
1x Normal exactly equals `UiTheme::preset(ThemeMode::Normal)`; Large derives
label/body/heading 24/27/36 and control height 66 in logical units. Maximum 2x
produces 32/36/48 and control height 88. Never shrink to fit. Native choices are
thread/session-local; `apply_ui_preferences(UiPreferences::default())` resets
only the UI channel. Legacy saved `Preferences` and public `ApplyOutcome` literals
and their save encoding are untouched.

New JS API in `web/visuals.js`:

```js
validateUiPreferencesV1(value) // throws Error, otherwise frozen unaliased snapshot
bindVisualPreferences(canvas, readLegacy, applyLegacy, {
  window, // optional, unchanged
  ui: {read: () => player.uiPreferencesV1, exports: () => currentWasmExports}
})
```

Binding adds read-only `uiCurrent` (last accepted frozen UI snapshot or null) and
`uiError` (latest read/setter error or null). Old `current/error` retain legacy
meaning. `refresh(force=false)` synchronously attempts **both independent**
channels and returns false if either enabled channel fails or after disposal.
Hosts continue gameplay regardless of that result and expose UI failures via
`canvas.dataset.uiPreferencesError`, separately from the existing visual error.
A failed setter leaves `uiCurrent` intact and retries on the next existing refresh;
a valid deferred read cannot clear a setter failure during context loss. Invalid
reads retain the latest fully validated UI snapshot; resize/restoration may
reapply that snapshot while retaining the read error, matching the existing
last-good recovery model. There is no partially validated UI commit.

UI changes are sampled by the existing host refresh points, including before
presentation and after queued preset/detail updates. Shared resize, canvas-size,
context restoration and explicit force invalidation also update UI. Enabled UI
adds `pageshow` and document `visibilitychange` invalidation; events never build
a renderer or start a scheduler. BFCache keeps listeners; existing real teardown
calls dispose, which removes all added listeners. No async callbacks or per-frame
storage writes were added.
