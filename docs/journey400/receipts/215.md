## Concrete behavior and compatibility

- A `PreparedProjector3D` caches the supplied world-to-clip matrix and its
  `Mat4::checked_inverse()`. Projection and inverse projection reuse
  `Mat4::try_project_point3()`; no duplicated inverse implementation or
  math-to-graphics dependency was introduced.
- Viewport origin and extent, Y direction, physical near/far NDC values and
  finite/infinite far intent are explicit. Nothing infers an eye position,
  handedness, NDC convention, viewport or original far intent from coefficients.
  RH/LH perspective and orthographic finite-far cameras are supported; reversed
  NDC conventions are available for matrices actually authored that way.
- Inputs use one caller-selected screen unit system, normally host logical
  pixels. X increases right. Origin is the numerical minimum X/Y corner;
  `ScreenYAxis::Down` maps NDC +Y to minimum screen Y. DPR conversion belongs at
  the host boundary. No safe-area inset is applied internally.
- Viewport extent must be finite and **at least 1 screen unit per axis**. Zero,
  negative, subunit/tiny, nonfinite, overflowing and collapsed edges fail with
  `InvalidViewport`. The maximum edge is the f32 sum `origin + size`; both
  mapping and membership use the same rounded minimum/maximum edges. Fractional
  offsets are supported, with their usual f32 rounding.
- Coordinates refer to continuous edges, with **no implicit half-pixel shift**.
  A pixel index samples its center at `origin + index + 0.5`. Both viewport edges
  are inclusive. Hosts sharing adjacent regions must resolve edge ownership.
- NDC Z is neither linear world distance nor normalized window depth. Endpoint
  conventions are (-1,1), (0,1), (1,-1), or (1,0) in physical near/far order.
  Membership is inclusive, exact on computed values, without epsilon/clamping.
- Preparation validates viewport first, then explicit far intent, then checked
  inverse, then all eight closed NDC-box corners. Corner inverse W must be
  positive; each corner must divide to representable finite world coordinates.
  Positive corner W excludes an infinity crossing throughout the cached box
  because inverse W is affine. Nonpositive W returns `InvalidClipVolume`;
  nonrepresentable coordinates retain `Matrix(ResultOutOfRange)`.
- `FarPlane::Infinite` always returns `UnsupportedInfiniteFar`, even when rounded
  coefficients might produce a finite apparent endpoint. Declaring an exact
  infinite matrix as finite is also rejected by the corner checks. An authored
  finite camera whose coefficients round to an infinite endpoint is rejected;
  no synthetic finite far point is substituted. Correct original intent remains
  the caller's responsibility after matrix composition/rounding.
- `project` rejects finite negative-W points as `BehindCamera` before division.
  Nonfinite point inputs and exactly zero W retain their checked matrix errors.
  Tiny positive W is allowed when divided coordinates fit, with no epsilon.
  Positive-W points outside XY/depth are returned unclamped with separate
  `inside_viewport` and `inside_depth` flags. These flags do not test occlusion.
  Orthographic W cannot establish an absent eye position: points behind the
  authored near interval are represented by `inside_depth == false`.
- `unproject` rejects nonfinite screen, then nonfinite depth, then outside
  viewport, then outside depth. It never extrapolates or clamps. The cached
  inverse maps accepted screen/NDC coordinates to world points.
- `pick_ray` uses the physical **near-plane world point** as origin and points
  toward the physical finite far endpoint. It does not infer the eye. Direction
  has unit length subject to f32 rounding; `origin + direction * t` uses world
  distance. Orthographic origins differ while their directions are parallel;
  perspective near-plane origins produce divergent directions. The returned
  `far_point` is an explicit endpoint, not an implicit physics-query cap.
- Endpoint subtraction and normalization use f64, allowing a valid normalized
  direction when an extreme finite endpoint difference overflows f32. If f32
  endpoint rounding collapses both points, picking returns `DegenerateRay`.
- `try_update` validates a replacement before assignment. Every error retains
  the earlier matrix, inverse, viewport and conventions. There is no hidden
  history or reset state; successful replacement installs all new state together.
- Fixed-size values and stack arrays only: preparation and queries allocate no
  heap storage. There is no variable capacity, collection, output buffer or
  saturation contract. A thread-local allocator regression observes zero
  allocation calls across preparation, repeated queries/errors and update
  recovery, with a separate positive allocation-counter control.
- Additive module only: existing matrix/shapes/quaternion APIs, struct literals,
  exhaustive enums, camera defaults, wire/save/replay formats and exports remain
  unchanged. No engine/game state, timing, input or renderer is owned here.

## Exact public API

All declarations below are in `ferravex_math::projection`. All types derive
`Clone, Copy, Debug, PartialEq`; the four configuration/error enums also derive
`Eq`. `ProjectionError` is `#[non_exhaustive]`, implements `Display` and
`std::error::Error` (matrix variant exposes its source), and has
`impl From<MatrixError> for ProjectionError`.

    NegativeOneToOne,
    ZeroToOne,

    ReverseZeroToOne,

impl NdcDepth {
    pub const fn near(self) -> f32;
    pub const fn far(self) -> f32;
}
pub enum FarPlane { Finite, Infinite }

    Matrix(MatrixError),
    InvalidViewport,
    UnsupportedInfiniteFar,
    InvalidClipVolume,
    BehindCamera,

    NonFiniteDepth,
    OutsideViewport,
    OutsideDepth,
    ResultOutOfRange,
    DegenerateRay,
}
pub struct ProjectedPoint {
    pub screen: Vec2,
    pub ndc_depth: f32,
    pub inside_viewport: bool,
    pub inside_depth: bool,
}
pub struct PickingRay3D {
    pub origin: Vec3,
    pub direction: Vec3,
    pub far_point: Vec3,
}
pub struct PreparedProjector3D { /* private validated state */ }

    pub fn try_new(
        view_projection: Mat4,

    pub fn unproject(&self, screen: Vec2, ndc_depth: f32) -> Result<Vec3, ProjectionError>;
    pub fn pick_ray(&self, screen: Vec2) -> Result<PickingRay3D, ProjectionError>;

## Limits retained for parent

- Infinite-far cameras are intentionally unsupported. Matrix coefficients alone
  cannot certify the original authored far intent or detect all wrong convention
  declarations; callers must supply the actual camera metadata.
- Positive homogeneous W is required. Multiplying the whole matrix by a
  negative scalar preserves raw projective coordinates but changes this explicit
  half-space policy and is rejected during preparation.
- Cached inverse coefficients, NDC points, world endpoints and screen outputs
  are f32; ordinary underflow, boundary rounding and conditioning limits remain.
  No exact-rank/condition-number certificate or arbitrary epsilon was added.
  Ill-conditioned round trips and rounded endpoint collapse are not silently
  repaired. Successful preparation is not a general numerical-accuracy promise.
- Host native tests/doctests only. No Wasm/dependent-crate integration, browser,
  physical mobile/device, graphics/game adoption, playtest, performance benchmark,
  cross-platform determinism or audible/visual runtime claim. Parent retains
  downstream native/Wasm/graphics/game gates and task acceptance/status.
