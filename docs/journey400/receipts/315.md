## Concrete behavior and compatibility

- `observe_detailed` returns `Result<(), ClockSampleIgnored>`. Legacy `observe(...) -> bool` forwards to `.is_ok()` and retains its signature and acceptance behavior. The reason is the first failing check, not a claim that every other field was valid.
- Reasons distinguish bounds, reversed server/local timestamps, unretained nonce, mismatched echoed timestamp, retained-but-expired probe, old server anchor, old/half-space tick, estimator RTT rejection and extended-tick overflow.
- `ProbeNotRetained` deliberately combines unknown, overwritten, already consumed and reset probes. Four slots cannot reconstruct those histories. `ProbeExpired` is only reported for an actually matching retained probe and timestamp.
- Every rejected observation preserves the complete clock, including pending probes, nonce cursor, ClockSync sample counter/weight, RTT, offset, jitter, anchor and freshness. No rejection counters were introduced. Even expired probes remain until overwritten/reset; an ignored timestamp does not consume the legitimate probe. Inspection never expires or consumes anything.
- Existing four-slot modulo replacement, wrapping u32 nonce domain (including zero), inclusive 2^53-microsecond bound, five-second inclusive probe lifetime, timestamp-to-f64 conversion, ClockSync smoothing, jitter arithmetic, six-to-twelve-tick delay, estimation clamps and tick unwrapping are unchanged. Equal ticks with newer server sends are still accepted. No new local timestamp watermark or probe issue-order constraint was introduced.
- Diagnostics contain fixed slot-order probe identities/send times/ages, latest accepted local receive time, common age of the latest RTT/offset update, optional smoothed RTT/offset, jitter and delay selected for the supplied Hz. Unknown estimates are `None`; zero remains a known value. Both smoothed estimates retain older weighted contributions; sample age measures time since their latest update.
- Age is explicit: unknown, inspection timestamp outside the 2^53 bound, inspection before the retained timestamp, or elapsed microseconds. Unknown takes precedence when there has never been an accepted sample. No automatic freshness policy or wall clock is added. Pending `AgeMicros(age)` establishes expiry only when `age > 5_000_000`. Cross-domain timestamps that happen to be ordered cannot be identified by this API.
- Diagnostics preserve the legacy render-delay rate domain (all u16); estimation/render sampling still independently require 1..=1000 Hz. Snapshot delay is inspectable even when a tick estimate is unavailable.
- `ClientClock::reset` clears probes/estimator/sample age/jitter/anchor, retaining only the nonce cursor to avoid immediate reuse. The next correlated accepted sample rebases local/server time origins and raw tick, including lower values. `TickUnwrapper::reset` clears its separate tick epoch. Neither reset creates a session identity or authenticates traffic. Wrapping/recreating clocks can reuse nonce/timestamp values; the outer session must still reject old traffic before any clock observation.
- Existing public types retain their signatures and construction compatibility (private fields already prevent external struct literals). New enums/diagnostic structs are non-exhaustive for additive evolution. No protocol, save, replay, export or drift-algorithm changes.

## Exact public additions

All are available through the already registered `ferravex_net::clock` module:

```text
impl ClientClock {
    pub fn observe_detailed(
        &mut self,
        nonce: u32,
        client_us: u64,
        receive_us: u64,
        send_us: u64,
        tick: u32,
        now_us: u64,
    ) -> Result<(), ClockSampleIgnored>;
    pub fn diagnostics(&self, local_us: u64, hz: u16) -> ClockDiagnostics;
    pub fn reset(&mut self);
}
impl TickUnwrapper {
    pub fn reset(&mut self);
}

#[non_exhaustive]
pub enum ClockSampleIgnored {
    TimestampOutOfRange,
    ServerTimeReversed,
    LocalTimeReversed,
    ProbeNotRetained,
    ProbeTimestampMismatch,
    ProbeExpired,
    ServerTimeNotNewer,
    TickNotCurrentOrNewer,
    RttOutOfRange,
    TickOverflow,
}

#[non_exhaustive]
pub enum ClockAge {
    Unknown,
    TimestampOutOfRange,
    BeforeTimestamp,
    AgeMicros(u64),
}

#[non_exhaustive]
pub struct PendingClockProbe {
    pub nonce: u32,
    pub client_us: u64,
    pub age: ClockAge,
}

#[non_exhaustive]
pub struct ClockDiagnostics {
    pub local_us: u64,
    pub tick_rate_hz: u16,
    pub pending_probes: [Option<PendingClockProbe>; 4],
    pub last_observed_us: Option<u64>,
    pub sample_age: ClockAge,
    pub rtt_seconds: Option<f64>,
    pub offset_seconds: Option<f64>,
    pub jitter_seconds: f64,
    pub render_delay_ticks: u32,
}
```

`ClockSampleIgnored`, `ClockAge`, `PendingClockProbe`: Clone, Copy, Debug, PartialEq, Eq. `ClockDiagnostics`: Clone, Copy, Debug, PartialEq. Existing ClientClock remains Clone, Debug, Default; TickUnwrapper remains Clone, Copy, Debug, Default.
