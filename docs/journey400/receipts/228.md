## Concrete behavior

- `check_clearance` performs one complete current-pose Terrain query at the supplied feet position, using the existing candidate visitor and shape/obstacle separation kernel. It performs no recovery, snap, carry, support lookup, mutation or time/input advancement.
- Touching is clear, with the existing motor penetration tolerance of `1e-5`; no extra skin margin is added. Penetration deeper than this returns `Blocked`. Capsule/Box2 restrictions and supported obstacle geometry follow existing separation behavior, including planar obstacle validation.
- Candidate limits are explicitly `0..=1_000_000`. Zero succeeds only when no candidates are visited; the first candidate returns `QueryBudget`. An exact full limit succeeds when the query is complete. Limits above one million are invalid before terrain visitation. Sensors and excluded membership layers consume the budget before being filtered, as in existing movement queries. Existing CharacterSettings validation/defaults are unchanged; callers pass its mask/limit values explicitly.
- Blocking requires a complete query; a later budget or included-obstacle failure prevents any partial clearance authorization. When multiple obstacles block, the smallest stable ID is reported independent of visitation order. Existing first traversal-error behavior is retained.
- `Character::try_set_height` changes only the caller-owned shape after successful clearance of the target. Its height argument is full sole-to-top height for both variants. Capsule radius and Box2 half-width remain exact; Box2 stores half the requested height in half.y. Existing shape limits still apply (capsule height at least twice radius and at most 1000; Box2 half-height between 0.001 and 1000).
- The character is immutably borrowed. Feet, velocity, jump coyote/buffer/held state, grounded state, ground normal and support identity/local/previous anchors remain unchanged on success and failure. Invalid motor history is rejected consistently with step's checks. Every rejected request also preserves the caller's shape.
- Shrinking and unchanged-height requests are checked too: shrinking out of a ceiling overlap succeeds if the target clears, but a still-penetrating target is refused. The transition never hides an overlap by shifting the feet.
- Current terrain is checked without applying pending support motion. A platform that has moved into the old feet position can block the request; normal recovery/carry remains the next step's responsibility. Pending translating/rotating support displacement and buffered jumps survive successful height changes. Subsequent movement still carries once and binds its usual fresh anchors.

```rust
pub struct Clearance {
    pub candidates: usize,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum ClearanceError {
    InvalidInput,
    InvalidObstacle,
    QueryBudget,
    Blocked { obstacle: u64 },
}
// ClearanceError also implements std::fmt::Display and std::error::Error.

pub fn check_clearance<T: Terrain + ?Sized>(
    world: &T,
    shape: CharacterShape,
    feet: Vec3,
    membership_mask: u32,
    max_candidates: usize,

impl Character {
    pub fn try_set_height<T: Terrain + ?Sized>(
        &self,
        world: &T,
        shape: &mut CharacterShape,
        height: f32,
        membership_mask: u32,
        max_candidates: usize,
    ) -> Result<Clearance, ClearanceError>;
}
```

The only new function reexport is `pub use geometry::check_clearance;` inside the assigned character/mod.rs. Clearance/Error are declared there and the method extends the already-reexported Character. No api.rs, lib.rs, world.rs, manifest or facade edit is needed for these qualified APIs. The integration test is automatically discovered by Cargo.

The `Character::try_set_height` rustdoc in motion.rs contains an executed first-party recipe: create an existing character over slice Terrain, acquire floor support with teleport, shrink, reject standing under a ceiling, assert the unchanged motor and accepted short shape, stand in clear space, move the platform, then step with the accepted shape and assert carried displacement. The query also has an executed zero-budget/ceiling doctest in geometry.rs. Both are ordinary runnable Rustdoc examples and were compiled and executed by cargo test --doc, not metadata-only guide snippets.

Consumer integration retains a mutable CharacterShape alongside the existing Character, passes the movement settings' membership_mask/max_candidates to the new method, and passes that accepted shape to subsequent step calls. Map QueryBudget/invalid results separately from Blocked; do not treat an incomplete query as standing clearance. A height-only change needs no feet interpolation snap. Input policy, camera presentation, optional game crouching and any networking/replay shape policy remain parent-owned; this task does not adopt crouching into a game or protocol.
