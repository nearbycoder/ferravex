## Selection, storage and numeric contract

- Radius query returns the closest `min(out.len(), total)` circle matches.
  Nearest-k returns `min(k, out.len(), total)`. Both sort ascending by returned
  squared distance, then ascending ID, including co-located points and IDs 0 and
  `u64::MAX`. Returned points are current stored positions.
- `total` always counts every match inside the inclusive circle, before either
  output or k truncation. `is_truncated()` means `written < total`, including
  intentional k omissions. An exact fit is complete. Zero output or zero k is a
  validated count-only query. Only the written prefix changes; unused entries
  remain caller-owned and may contain previous results.
- Traversal uses the existing cells covering `center +/- radius`, then exact
  circular filtering in floating-point arithmetic without an epsilon. It never
  scans the entire points map for candidates. All relevant candidates are
  examined even when the heap is full, so early IDs/cells cannot hide a closer
  point. The buffer is a max-heap during traversal and is sorted in place after
  selection. No query scratch allocation or cached result state is introduced.
- The existing 4096-cell bounding-rectangle ceiling applies before callbacks or
  output writes, including on empty grids, empty output and zero k. A 64 by 64
  cell square is accepted; a larger square returns `QueryTooLarge`. The circle
  is never clipped to fit the cell range or work ceiling. The output length
  limits storage, not candidate work; occupants are bounded by grid capacity.
- `Invalid` rejects nonfinite centers, negative or nonfinite radius, overflowing
  `radius * radius`, and bounding coordinates that are nonfinite, outside i32
  cells, or overflow coordinate-to-cell division. All returned errors leave
  the whole output buffer unchanged.
- For normal radius squares, the circle test is
  `dx * dx + dy * dy <= radius * radius`. Overflowing candidate squared
  distances are outside an accepted finite squared radius and are omitted,
  rather than producing infinite returned distances or a late partial error.
- When the radius square is subnormal or underflows, radius-normalized deltas
  perform the circular test; the bounding square's corners do not become
  matches merely because squared distances round to zero. Radius zero,
  including negative zero, matches only equal stored coordinates. Returned
  squared distances still use ordinary f64 multiplication/addition, may
  underflow to zero, and resolve rounding/underflow ties by ID. No exact-real or
  cross-platform floating-point determinism claim is made.

Queries borrow the grid immutably and have no reset state. Move/remove/reinsert,
rejected updates, emptying the grid and reuse of caller output are covered. Grid
setup/mutation may allocate B-tree storage and is excluded from query allocation
claims.
