## Concrete behavior and compatibility

Content borrows a nonblank title, body/stat sections and single-line actions.
Every action has a stable caller ID, complete label and caller-owned enabled
state. The required primary ID must exist; it can deliberately be disabled.
Missing primary/blank labels/impossible layout return `InvalidLayout`; duplicate
action/blocker IDs return `DuplicateId`. Unknown action/section queries return
`None`. IDs need not encode list positions. Start/resume/retry/next-run meaning,
remapping, feedback, authoritative progression and action application remain
caller-owned. No gameplay input, lifecycle or simulation clock is installed.

Fonts are fixed at title **24**, body/stat/action **18** logical units; card
padding is **16**, section gaps **12**, action gaps **8**, action height **44**.
Title/body use task273 wrapping. Stats reuse task276's `StatRowsLayout`, its
shared columns/stacked fallback, complete label/value/description geometry and
default styles. No alternate number formatting, unit conversion or stat layout
is introduced. Action widths are measured from complete labels plus 32 units of
padding, at least 44 wide, then placed with task272 flow. All action rows are
reserved before content; none is clipped/ellipsized/shrunk to make the card fit.
The same canonical endpoint rectangles go to actual buttons, hit testing and
inspection, including fractional flow widths. Task271 absolute safe rectangles
work with a zero-inset responsive viewport. With inset responsive viewports,
coordinates start at zero inside the safe area; host pointer coordinates must
be projected/unprojected through that viewport exactly once.

Bounds/title/actions/source limits are measured before submission. Whole title
and every action must fit; otherwise no card is inserted. If content overflows,
a full readable notice slot is also reserved. A 320×170 short-screen regression
retains the full primary and an 18-unit omission notice; 320×140 with the same
copy rejects explicitly. Invalid/tiny/unrepresentable bounds never scale the
entire card. A narrow fitting card without content does not require room for an
unused omission notice. Fixed visual styling is this additive card API's policy;
existing UI and game styles/defaults remain unchanged.

Without scrolling, only a complete prefix of sections is submitted. The first
nonfitting section stops the prefix; later short sections do not reorder around
it. A stats section is either complete or wholly omitted. `CONTENT OMITTED` is
painted and the returned report counts omitted sections and stat rows; no
essential value disappears behind an unreported ellipsis/partial final row.
Callers must choose scrolling or an explicit fallback if omission is unsuitable.

Optional scrolling reuses **task274's existing pure `ScrollState`**, not a new
pan/scrollbar/modal framework. Set its viewport/content extents from the layout,
feed accepted remapped scroll commands outside composition, and pass an immutable
reference. Both extents must match exactly; a zero-height scrolling viewport or
stale/mismatched state rejects before insertion. Scroll update/reset has no
hidden game meaning. A scrolling card reports zero omitted source sections/rows
and paints `SCROLL FOR MORE` when content exceeds its viewport.

Full local section/stat geometry is translated by `ScrollState::translate_rect`.
Each intersecting wrapped line keeps its **full logical rectangle** under the
content clip and all inherited clips. It is never cropped first and rewrapped.
Offscreen lines consume no command/text/vertex budget. This bounded culling uses
the existing line cursor and painter; inspection describes the actual queued
UTF-8 line commands, not a second retained full-document accessibility tree.
Bitmap ASCII uppercase/unsupported-glyph `?` behavior is unchanged. Scrolling
can partially expose a line/value while moving; all source remains reachable.
There are no interactive body widgets needing a separate scrolled hit registry.
Fixed action hits preserve ancestor clipping and existing half-open boundaries.

Submission uses `Ui::compose`/`UiComposition::compose` and the existing modal
primitive. Any command/text/vertex/clip/depth error, including a later enclosing
callback error, rolls back the entire card's paint, modal/widget registration,
clips and inspection. Prior modal/HUD registration, focus and capture survive
rejection. The scroll reference is immutable and no external state is mutated.
Input finish and paint remain outside composition. Controls-open/blur/disabled
input cancellation and real release semantics come from existing Ui behavior.
No fallback is inserted implicitly or capacity reserved for one; after rejection
the caller can submit a small readable fallback from its restored entry budget.

## Bounds and allocation policy

- At most **8 sections**, **8 actions**, **64 stat rows total across sections**.
- At most **8192 combined UTF-8 source bytes**, counting title, all section/stat
  fields and action labels, including offscreen/omitted source. Bounds reject
  before text measurement; exact 8192 success and 8193 rejection are exercised.
- Geometry is fixed stack storage; no retained card state, heap layout cache,
  dynamically growing source collection or new UI storage is added.
- Measurement scans bounded source and uses existing flow/stat layout scratch.
  Submission scans bounded line cursors and existing UI command/text/vertex and
  16-level clip/composition limits still apply. A very large visible viewport or
  earlier accepted groups can exhaust those UI budgets; rejection is atomic.
- Rebuild the borrowed layout when copy/bounds change. `Ui::begin` removes old
  commands; caller `ScrollState::set_extents` clamps reflow and `reset` returns to
  the top. No stale action/section tail is submitted.

## Exact additive public API

All card names below are under `ferravex_render::ui::cards`. `ScrollState` is the
registered `ferravex_play::ui::scroll::ScrollState`; `Ui`, `UiComposition`,
`UiRect`, `UiError` and `WidgetId` retain their existing `ui` paths.
These are signature excerpts, not a separate runnable program.

```text
pub const MAX_CARD_SECTIONS: usize = 8;
pub const MAX_CARD_ACTIONS: usize = 8;
pub const MAX_CARD_BYTES: usize = 8192;

pub enum CardSection<'a> {
    Body(&'a str),
    Stats(&'a [StatRow<'a>]),
}
pub struct CardAction<'a> {
    pub id: WidgetId,
    pub label: &'a str,
    pub enabled: bool,
}
pub struct CardContent<'a> {
    pub title: &'a str,
    pub sections: &'a [CardSection<'a>],
    pub actions: &'a [CardAction<'a>],
    pub primary: WidgetId,
    pub blocker: WidgetId,
}
pub struct CardReport {
    pub omitted_sections: usize,
    pub omitted_stat_rows: usize,
    pub scrollable: bool,
}
pub struct CardLayout<'a> { /* private borrowed/fixed-storage fields */ }
impl<'a> CardLayout<'a> {
    pub fn new(bounds: UiRect, source: CardContent<'a>) -> Result<Self, UiError>;
    pub fn bounds(&self) -> UiRect;
    pub fn title_rect(&self) -> UiRect;
    pub fn content_bounds(&self) -> UiRect;
    pub fn content_extent(&self) -> f32;
    pub fn section_rect(&self, index: usize) -> Option<UiRect>;
    pub fn action_rect(&self, id: WidgetId) -> Option<UiRect>;
    pub fn submit(&self, group: &mut UiComposition<'_>, scroll: Option<&ScrollState>)
        -> Result<CardReport, UiError>;
}
impl Ui {
    pub fn card(&mut self, layout: &CardLayout<'_>, scroll: Option<&ScrollState>)
        -> Result<CardReport, UiError>;
}
```

Section/action/content are `Clone + Copy + Debug`; report additionally has
`Default + PartialEq + Eq`; layout is `Debug`. There is no new error enum or
change to exhaustive existing enums. `CardLayout::submit` is the nested helper;
no extra `UiComposition` method or registration is needed.
